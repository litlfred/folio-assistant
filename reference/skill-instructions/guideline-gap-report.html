guideline-gap-report

Skill id: guideline-gap-report · Package: authoring-who-smart-guidelines · Run after every stage of smart-guideline-end-to-end (§The gap report), and after each L2 track of dth-authoring.

A gap is a missing link in the chain, never a judgement. The report says what is not there yet and who closes it. It does not say whether an asset is right; that is the reviewer’s verdict, recorded in its QaReview.

Input and output

The contract is input.schema.json and output.schema.json.

  • In: the guideline’s l1Kg, its l2Assets and ig (whatever stages have run so far), the reviews recorded (qa-review/v1), and the stage just finished.
  • Out: the gaps, one row each, with the counts per kind in summary, and the staged page it is published on in stagingLinks.

What counts as a gap

Each kind is read off links the stages already write: wasDerivedFrom and implementedBy edges, their adjudication property, and the QaReview records. The report adds no data of its own.

review-pending is not the agent’s to close, and the report never asks the agent to. It lists the waiting role so the programme manager can follow it up.

Who reads it

The report is written for the people who review, not for developers:

  • Per role. The staged page groups the gaps by reviewing role, so a clinical SME opens the page and sees only the items waiting on clinical judgement, each linked to its review item in the form that role reads (§Review by expertise). No gap row shows FSH, JSON or CQL.
  • Per stage. The summary counts each kind per stage, so the programme manager sees how far the guideline has come and what is holding it.
  • Linked from every review request. Each request carries the link to the report, anchored at the asset’s own row.

Steps

  1. Read the inputs. A stage that has not run yet is reported as not run, never as having no gaps.
  2. Walk the chain L1 → L2 → L3 and the review records, and write one row per gap with kind, asset, stage, role, and the reason in a sentence.
  3. Write the summary, per kind and per stage.
  4. Stage the report beside the stage’s output (feature-staging) and put its link in every review request the stage opens.
