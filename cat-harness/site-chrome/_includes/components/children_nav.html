Include as: {%- include components/children_nav.html -%} Depends on: page, site, nav_breadcrumbs, and the cached `nav_cache/parenthood_map.html`. Results in: HTML for the children-navigation component, the same as the theme's. WHAT CHANGED, AND WHY ("cache the nav"). To list a page's children the theme regroups EVERY page of the site by parent, on every page that has children: `site.html_pages | where_exp | group_by`. Each page touched costs a `to_liquid`, which under Jekyll 3 re-evaluates every front-matter `defaults` scope (~5 ms a page here), so this was O(pages) per parent page and O(pages^2) for the site -- the largest single cost of the build. Here the grouping comes from a map computed once per build (`nav_cache/parenthood_map.html`), and only the page's own children are fetched, by index, then grouped exactly as the theme groups them and handed to the theme's own `components/nav/children.html`. A page in a collection, or one with no title, takes the theme's path unchanged. Everything outside the marked block is the theme's file VERBATIM. Keep in step with the theme when the just-the-docs pin moves (upstream/upstream-pins.json). {%- endcomment -%} {%- comment -%} Whether a page has any children is checked efficiently by inspecting the cached site_nav. If the page has no children, nav_children is set to an empty array; otherwise nav_children is left unset.
