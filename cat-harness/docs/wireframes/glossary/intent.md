# Glossary visualiser — as-is intent

**Covers:** `cat-harness/docs/cat-harness/docs-auto/glossary/glossary/index.html` (declared as `coverage.visualiser` of the `swimlane-glossary` directory in `cat-harness/cat-harness.json`, renamed from `glossary` on 2026-09-23). Generated by `cat-harness/scripts/gen-docs-auto.ts` (`bun run docs:auto`) using `autoDocPage()`, the same template as the docs and skills indexes. The page is static HTML with no script beyond the `SCOPE` marker.

**Who it is for:** anyone reading or writing a process who needs to know what a swimlane role *means*: an author, a reviewer, or an agent binding a lane to a role. The declaration explains that this index replaced a circular visualiser, and that it is "a real rendering: … each [term] with the definition joined from the role registry".

**What they need to do:** find a term, read its definition, and see its notation (`role/<id>`), when it was first seen, and whether it is current or retired. The note on the page says this is "an index, not the documentation": the authored explanation lives beside it.

**What it must show** (read off the page and the generator):
- the title and scope tag
- the derivation lede ("every term this instance's swimlanes define …", sub-graph `cat-harness/glossary`)
- the "index, not the documentation" note
- the sibling list, here a single entry: `glossary`, 46
- a two-column table (Artefact | What it declares about itself). Each row holds the term (linked to its anchor in `glossary-ledger.json` on GitHub), its path, its description, and the facts `notation`, `first seen` and `status`.

## Observed on main (edf3a89+)

Rendered at 1280×800 and 390×844.

1. **Heading** "Glossary" with the scope tag `glossary`.
2. **Lede** (derived; sub-graph `cat-harness/glossary`).
3. **Note** "This is an index, not the documentation."
4. **Sibling list:** one row, **glossary** `cat-harness/glossary` 46.
5. **Table of 46 rows**, from Adjudicator, Administrator, Attestation service, Author, Authoring agent … to User, Validation pipeline and Work plan (beans). Every row has `status current`, and first seen is 2026-09-21 or 2026-09-22.

The page has no mobile layout of its own. At 390 px the same two columns squeeze to about 130 px and 200 px, and the ledger path breaks anywhere. The page does not scroll sideways at 390 px (`scrollWidth` 390), but it is 16,252 px tall, against 8,261 px at 1280.

## Findings

1. **There is no way to find a term** except scrolling or the browser's find. The page has no search, no filter and no A–Z jump, and its 46 rows run to about 8,000 px at desktop width and 16,000 px at phone width.
2. **The order is not alphabetical by the displayed name.** Rows follow the role id, so **Activity log** (`role/log`) comes after **Librarian**, and **Human translator** (`role/translator`) comes after **Translation coordinator**. A reader scanning by title will miss them.
3. **Markdown shows through.** The descriptions are escaped plain text, so inline code appears with literal backticks, for example "Inherits \`reviewer\`" and "\`adjudication\` permission".
4. **The term column is wide and dominated by the path.** Each term is followed by the full `cat-harness/glossary/glossary-ledger.json#role/…` path, which breaks mid-token (`…#role/adjudi / cator`). At 390 px this leaves about 200 px for the definition, the part the reader came for.
5. **The heading is repetitive.** "Glossary `glossary`", the sub-graph path in the lede and the single sibling row all state the same scope three times before the first term.
6. **The count differs from the declaration.** The `glossary` declaration's comment says "44 terms", but the page shows 46.
