{%- assign h = site.data.harness -%} {%- comment -%} TWO links, so the browser picks by size rather than us picking for it. The unsized link is the full mark, whiskers and all, used wherever there is room — a pinned tab, a bookmark tile, a home-screen icon. The `16x16` link is the mark drawn for small sizes, which is what a tab strip actually shows. The split exists because the whiskers are `stroke-width="2.4"` against a 120-unit viewBox: 0.32 px at 16 px and 0.48 px at 24 px. Sub-pixel at 1x, and still under a whole device pixel at 2x, so at tab size they render as haze on the face rather than as whiskers. One link would have meant choosing between losing them everywhere and showing them where they cannot be drawn. {%- endcomment -%} {%- comment -%} THE TAB ICON FOLLOWS THE OPERATING SYSTEM, not the page's own toggle, and that difference is deliberate rather than an oversight. A `` cannot read `data-fa-scheme` — it is resolved by the browser before and outside the page's own styling, so the only switch available to it is `media`, which asks the OS. The sidebar mark (`title.html`) DOES follow the page toggle, so a reader who sets the page against their system will see the two disagree. That is the right way round. The tab strip is painted by the browser chrome, which follows the OS — so an icon matching the OS is matching what it actually sits on, while one matching the page would be the odd one out in the tab bar. The sidebar mark sits on the page and follows the page. Each matches its own background, which is the only rule that can be satisfied everywhere at once. Narrowest-first is not needed here: the two queries are mutually exclusive, and a browser with no `prefers-color-scheme` support takes the unmedia'd light one. {%- endcomment -%} {%- if h.icon.src -%} {%- if h.iconDark.src -%} {%- else -%} {%- endif -%} {%- endif -%} {%- if h.smallIcon.src -%} {%- endif -%}
