## Development setup

```sh
git clone https://github.com/litlfred/folio-assistant.git
cd folio-assistant
bun install
bun test          # unit tests
bun run cat lint      # eslint
bun run cat test:e2e      # e2e (test:e2e)
```

## Work-plan with `beans`

This project uses [`beans`](https://github.com/hmans/beans) as the single
todo/work-plan mechanism (the `todo-manager` skill). Do **not** stand up a separate todo
store.

```sh
cat-harness-tools/scripts/install-beans.sh && export PATH="$HOME/.local/bin:$PATH"
beans list
beans create "<title>"
bun run cat beans:claim <id>      # claim before you work
```

`beans ≠ sidecars`: never `beans create` bulk machine-generated queues (QA,
witness, watcher) — those stay as bulk JSON.

## Agent guidance

`AGENTS.md` is the agent-generic bootstrap pointer (read natively by Claude
Code, Gemini CLI, Antigravity, Cursor, Copilot); `CLAUDE.md` / `GEMINI.md` are
thin stubs that point to it. The rules live in skills: to change how agents
behave, edit the skill, not `AGENTS.md`.

## Documentation

- Prose docs live under `docs/` (this Jekyll site).
- **Skill schema reference** is generated — never hand-edit
  `docs/reference/skills/*.md`. Edit the JSON Schemas under
  `schemas/skills/<skill>/` and regenerate:

  ```sh
  bun run cat-harness-tools/scripts/gen-schema-docs.ts
  ```

- **Skill instructions** (`docs/reference/skill-instructions/*.md`) are also
  generated — never hand-edit them. Edit the skill bodies under `skills/`,
  `sdlc/skills/` or `work-plan/skills/` and regenerate:

  ```sh
  bun run cat-harness-tools/scripts/gen-skill-docs.ts
  ```

- The **TypeScript API reference** (`/api/`) is generated by TypeDoc in CI.
- The site is built and deployed to GitHub Pages by
  `.github/workflows/docs-site.yml` on every push to `main` that touches docs,
  schemas, or the source.

Preview locally:

```sh
cd docs
bundle install
bundle exec jekyll serve
```

## Shipping a change

Open the PR at the first commit and push small increments
(`skills/conduct/conduct-core/continual-progress.md`); take the branch to a clean,
green, pushed state with `sdlc/skills/sdlc-core/prepare-merge.md`. Keep the **formalism of the framework
separate from content** — content belongs in its own repository, and any content
in these docs is illustrative only.
