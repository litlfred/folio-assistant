Description

A TODO — one human actor's work state, as a knowledge-graph node.

What a todo is

A todo records that a person has something outstanding. It is not the agent work plan (beans/); it belongs to the content-review feedback workflow, and it is content, authored and owned by the folio, not by the harness.

It carries the four coordinates of the role model

> An actor performs a task in a process as a role, using that role's skills.

A todo is tagged by the same four things: who (ExternalIdentity), acting as what (TodoTags.roles), in which process (TodoTags.processes), on which task (TodoTags.tasks).

A task reference carries its process

A BPMN activity id is unique only within its process — A_Implement names one thing in crdm-requirements and could name another anywhere else. So TaskRef is a pair, never a bare string.

An identity is provider-qualified

litlfred is not an identity; github:litlfred is. A bare handle cannot be compared across systems, and two providers' namespaces are free to collide.

The link to a declared ActorDefinition is optional: somebody who comments on a pull request has a real outstanding item whether or not cat-harness/scenarios/actors/ declares them. actor: undefined means not linked, a third state — never "anonymous", and never silently resolved to a default actor.
