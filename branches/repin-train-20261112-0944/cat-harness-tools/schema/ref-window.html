Description

A COALESCING WINDOW over a watched ref — the writes a steward batched into one push, and nothing the host already knows.

Several workflows pushing gh-pages in a burst each trigger a Pages deployment, and each cancels the one in flight. A concurrency group cannot coalesce a burst: GitHub cancels a PENDING job when a newer one queues for the same group (cancel-in-progress: false governs only the RUNNING job). A steward can.

The discipline is in the skill, not here — sdlc/skills/sdlc-core/ref-stewardship.md carries what makes a ref need a steward, why a window is a different object from a hold, and the composition rule with the case that must still be reported.

A SIBLING of the merge queue's hold

HoldSchema in ./merge-queue.ts already has this object's shape: a lease with an expiry. But a hold is keyed by repository + pr and a window by ref, so it is a sibling type.

| HoldSchema | here | why | |---|---|---| | waitsOn (NonBlank prose) | ref (a declared special branch) | a window always waits on more arrivals to one ref, so the free-text field becomes a typed one | | since | since | identical | | expires | expires | identical, and the same expires > since refusal | | handoff | handoff | identical |

Decisions are stored; facts are read live

The rule MergeQueueEntrySchema enforces applies here unchanged, and FORBIDDEN_REF_FACT_KEYS refuses the tempting keys by name.

| stored here (a decision) | read live, never stored (the host's fact) | |---|---| | when the window opened, when it must close | the ref's tip SHA | | who holds it, and who takes over | whether the last deployment succeeded | | which routes were requested, by whom, when | whether the site is currently live |

expires is set once, at open

A window waits for the absence of a future event, so the clock is the only thing that can end it. A window that extends on every arrival never closes, which is why RefWindowSchema has no "extend".

Committed state, for handover

An instance lives in the declared workflow-state graph under beans/workflows/, committed, so a steward that takes over reads the same window rather than waiting forever or opening a second one.
