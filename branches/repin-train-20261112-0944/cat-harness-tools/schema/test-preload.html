Description

Register core's graph typologies before any test reads a declaration.

folio is registered by CORE as a load-time side effect (folio-graph-typology.ts: "a layer that cannot render must not own the renderable kind"), so whether readDeclaration accepts a layer's declaration could depend on whether anything had imported core yet — an IMPORT-ORDER dependency, and a test runner chooses its own order.

The registration trigger now sits at the foot of cat-harness.ts, so a reader cannot be called without the kind being registered and the suite passes without this preload. It is kept as a guard: a future test that reads a declaration through a leaf without loading a reader would otherwise pass or fail depending on where the runner puts it.

It does not hide a production module that forgets the import. This runs only under bun test. The gates — check:declared-paths, check:declared-assets, check:schema-nodes, sync-docs-harness — are separate bun run processes with no preload, and the server has its own entry, so a production module missing the registration still fails there.
