Description

A portfolio: an umbrella knowledge graph that LINKS other graphs' libraries, level by level, and copies none of them.

What a portfolio is

A portfolio names levels (L1, L2, … or any other ids its harness chooses), and each level names one or more LIBRARIES whose members belong there. A library is reached one of three ways:

  • library — a layer's own library catalogue, all of it or the items listed by their ids (such as IRIS handles);
  • discover — the repositories of an owner whose names start with one of prefixes, found when the portfolio is read, so a new repository joins without an edit here;
  • repos — repositories listed by name.

discover and repos may say which kind of member they take (memberKind, such as folio-document or fhir-ig). The word is the reader's: this kind does not interpret it, so a harness can add one without a change here.

Linked, never materialized

A member is addressed by its repository or item id and published where its own site publishes it. The portfolio holds the index a reader needs (title, date, cover, entry page), derived when it is read; it never holds the member's content. The owner, 2026-11-10: the umbrella graph links libraries of L1, L2, L3 documents.

Subclasses

A harness that fixes what its levels mean declares a child kind with this one as its parent and a refine over levels: a guidelines layer's guideline-portfolio pins the WHO SMART Guidelines levels L1 to L4.
