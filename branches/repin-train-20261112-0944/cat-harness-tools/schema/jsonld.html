Description

JSON-LD projection of the content block model.

Blocks are authored as TypeScript manifests — the builders in builders.ts are where author-time type checking lives, and pipeline/block-module.ts treats a manifest that throws on import as a finding. This module defines the published form: a .jsonld sibling next to each .ts, generated by pipeline/gen-block-jsonld.ts, so that

1. an external consumer can reference a block without a TypeScript toolchain, and 2. authored blocks and ingested documents (library/**) carry the same @context, the same @type vocabulary and the same edge terms — so one graph loader serves both.

Labels are not emitted as IRIs

A folio label looks like a JSON-LD compact IRI (def:foo) but is not one: def: names a block kind, not a namespace, and JSON-LD splits on the first colon. Emitted directly, def:quantum-universe and its cross-paper form some-paper:def:quantum-universe would expand to two IRIs for one block, and unital-groebner-bases:thm:bar would parse as an absolute IRI with scheme unital-groebner-bases that joins with nothing.

So @id is minted by resolveLabel, which resolves all three authored reference forms to one canonical relative IRI, and the label is additionally preserved verbatim in cat-harness:label for grep and round-tripping.

@id is relative

Emitted IRIs are relative (papers/<paper>/blocks/def-foo). Because JSON-LD 1.1 §4.1.3 ignores @base in a remote context, @base is in each document's own context (CONTENT_DOCUMENT_CONTEXT) as well as the published one, so a base-URL change rewrites the documents.
