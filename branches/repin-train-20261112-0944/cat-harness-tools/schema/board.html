Description

A board — the surface a folio's notes and its content are read on together.

board-positions.ts keys its document by board id; this is the object that id names: what a board is called and what it shows.

What a board SHOWS

Everything by default, with an optional declared filter: filter absent means the whole folio. The filter is a query, not a stored list, re-evaluated against the folio every time the board is rendered, so a board never goes stale and an empty folio still has a board to open.

The layering

This SCHEMA lives in the platform. A board INSTANCE lives under a folio's todos/. The tools that operate a board are kept separate, so the only functions here are readers over a declared document; nothing in this module writes, fetches or mounts anything.

The arrows run one way

folio → board → position → note. A board names content by page and node id and names notes not at all — the positions layer does that, one level down. Asserted at the import level in the tests, as for board-positions.ts.
