Description

Run context — what ONE run ran on, stated once, and cited by digest.

Test-plan executions, QA reports and tool runs all need the same version facts (the checker's hash and version, the commit under test — a block-qa verdict's reviewed_tree names its tree, the legacy reviewed_sha its commit — runtimes, the platform commit, the mount lock). This record states each fact once:

| field | the fact | reused from | |---|---|---| | platform | the commit of the checkout that ran | CommitShaSchema | | mounts | the mount lock's digest, and each mounted layer's pinned commit | LockedInstanceSchema | | profile | the tool profile selected, by name and digest | — | | releases[] | every tool and runtime release resolved, or why it could not be | ToolReleaseRefSchema, ReleaseDigestSchema | | invoker | the script, model or person that ran it | ActorKindSchema | | inputs[] | hash bases | HashBasisSchema | | prov | the PROV activity that records this context as prov:used | — |

Referenced by sha256, written once per run

A report carries RunContextRefSchema — { sha256 } — and never the context itself, so thousands of block-qa sidecars from one sweep cite one context. The digest is over canonicalRunContext's bytes, so two writers of one context agree on its reference.

Three states, never two

  • A release that could not be provisioned is could-not-provision WITH a reason; a context that omitted it would read as one that never needed it.
  • mounts is none, locked or could-not-determine. "No mount lock was found" and "this run mounts nothing" are different facts.
  • A system invoker must give its script_hash; the token unknown is allowed and is not a hash.

Run-context records are produced per run and have no directory: the run-level record that writes one says where.
