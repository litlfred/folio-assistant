Description

Which cards are OPEN on a board, and in what order they stack.

Two mechanisms; this module is one of them

| | trigger | who | |---|---|---| | semantic zoom | the card's rendered width crosses a declared threshold | automatic | | open / close | opening a card, or [x] | a person |

module:schemas/semantic-zoom owns the first; this owns the second. An open card is a WINDOW, not a zoom state: it is projected ON TO the board, and selecting any part of it raises it. Nothing in semantic-zoom.ts mentions windows and nothing here mentions widths: the card goes on becoming its avatar as the board shrinks, and the window it spawned stays.

SESSION-ONLY

board-positions.ts carries x and y and deliberately no z — "stacking order is a rendering decision the board makes from the document." Raising is the most frequent gesture on a board, so a committed z would make every selection a write and a merge conflict.

So the stack lives for as long as the page does, and this module holds no $schema tag and no file: it is state, not a document. If it should ever persist, it becomes one optional field in the DI document plus a serialiser, which is why the shape is already a plain array of ids.

An ARRAY rather than a map of z-numbers

The array IS the order, bottom to top, so there is no second fact to keep in step. A Record<id, number> could hold two cards at the same z, a gap, or a z for a card that is not open. zIndexOf derives the number on the way out.
