Description

structure.json: the structure of an ingested PDF, tagged _schema: pdf-structure/v1.

Two rungs write this file:

  • scripts/pdf-structure.py writes the whole artefact: source, metadata, toc, toc_source, sections and diagnostics.
  • scripts/pdf-pages.py, the no-outline rung, MERGES into whatever is there. It sets granularity: "page", source.text_source and a structure_note, rewrites sections at page granularity, and adds the rest of source only when it is absent (setdefault).

So the fields a page-granularity entry carries depend on whether pdf-structure ran on it first. That is why metadata, toc and diagnostics are optional here while sections and source are not.

One section shape, strictly

pdf-pages.py writes exactly the section shape pdf-structure.py writes, because gen-library-jsonld.ts reads sec.id, page_start and page_end. PdfSectionSchema is therefore .strict().

The text origin: one field, one vocabulary

Where the section text came from is source.text_source: "embedded" (the PDF's own text layer) or "ocr". A top-level text_source is rejected (the object is .strict()).
