Description

A sticky theme — named colour roles plus the three layouts, as a graph node.

A node, not a stylesheet

A theme declares named roles: a rule says var(--fa-sticky-surface) and what that resolves to is the theme's business, so changing a theme is not a find-and-replace of hex colours that misses a hover or dark-scheme variant.

The type and the themes are harness-layer nodes, while the todos that reference them stay in the todos graph.

All three layouts, or the theme is invalid

The three are laptop, mobile and card — the set harness.json's images[].layout already uses, each with its own textRegion because the crop differs. Missing a layout is invalid, never degraded: there is no fallback to another layout's geometry, because a theme that renders wrong on a phone ships while one that refuses to load is noticed.

Each harness has its own theme, by convention

| | | |---|---| | refused | deriving a theme from a ROLE, process, skill or graph typology — a note's appearance would depend on which lane happened to be reading it | | this | a HARNESS picking one theme and keeping it, written in that harness's own declaration |

Nothing computes it: harness.json names an id, and no code maps a harness to a theme.

A THEME IS REQUIRED; ART IS NOT. backdrop is optional, so a palette-only theme is COMPLETE. That is a different state from a theme whose backdrop is declared but whose crops are missing, which resolveThemeBackdrop refuses wholesale.

Today: grumpy-cyborg-agents (the sage hoodie on a sled pulled by robot cats) is cat-harness's, grumpy-cat (the plain sage hoodie) is folio-assist-core's, bootstrap (the cowboy in the desert) is bootstrap's, and engineer is reserved for testing surfaces.

Choosing a theme is an AUTHORING judgement — there is no mapping

A theme is picked by whoever writes the note, and nothing derives one from a role, a process, a skill or a graph typology. ThemedTodoFields.theme and the landing sticky's required theme are the whole selection surface: an id, set by an author. This is a rule, not a gap: a role is a swimlane, not a property of a thing (role-model.md), so a role→theme table would make a note's look depend on which process reads it and put presentation into the role graph.

The optional theme on ThemedTodoFieldsSchema encodes this: absent means nobody has chosen.

What the palette may NOT carry

The priority stripe is a WIDTH as well as a colour, so colour alone never carries the signal (WCAG SC 1.4.1). A theme sets the stripe's hue; it never sets its width to zero, and ThemeSchema has no field with which to try.
