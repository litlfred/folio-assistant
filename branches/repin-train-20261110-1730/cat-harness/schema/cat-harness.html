Description

The CatHarness declaration — what a layer IS, at its root.

Named for the harness: agentic-harness is the layer that defines Roles, Skills, Tools and the conventional directories, and every other layer inherits from it. A layer need not be a folio-assistant to have one — a Tool repo or a Test repo carries the same declaration.

Every layer carries one at its repository root (harness.json). It declares the directories the layer scans for content, and what kind of graph each one holds.

Directories, not a content-type field

The general object is a layer with directories, each holding a graph: Tool definitions under tools/, a knowledge graph under kg/, the schema graph under schemas/. folio is one graph typology among several — distinguished only by being renderable to a website (see BASE_GRAPH_TYPOLOGIES in ./graph-typology-registry.ts). A layer with no folio/ directory is ordinary.

Inheritance

A layer inherits its dependencies' directory conventions without restating them, by the same depth-first walk as schemas/kg/harness-config.ts and the same overlay order — deepest dependency first, root last, so the root wins.

Overriding is by graph id, not by path: a layer that wants its knowledge graph somewhere other than kg/ redeclares the kg id with a different path, and the inherited entry is replaced rather than duplicated.

Self-declarative

Each directory is a node with an @id and an @type, so the set of directories a layer scans is queryable like anything else in the knowledge graph.
