Description

Where a published thing is served: one resolver for the site's URL space.

| case | path | what it is | |---|---|---| | root | <base>/<path> | the root's rendering — its docs/ is installed by cat-harness, so it has no segment | | instance | <base>/<instance>/<path> | the layer presented as itself, on its own theme | | viewer | <base>/<locale>/<owner>/<graph>/<subject>/<path> | a viewer of one layer's assets, rendered by another layer's machinery; <locale>/ only when one is given |

  • The host is no exception: its graph document, Tools and subjects are the instance case, <base>/cat-harness/…, like every layer's. root is the index's own docs rendering, never a layer's graph.
  • The segment is the layer's name, never its stub: the stub names published FILES (<stub>.jsonld), the name names the layer.
  • The declared graph is a segment, because a layer may declare more than one renderable graph and two would otherwise collide on one URL.
  • A locale is a segment of VIEWER pages only, placed first as for every visualiser page (/<locale>/<declaring>/<kind>/…). The root and a layer as itself carry none, so a layer's .jsonld identifier does not change with a reader's language. With a locale the viewer case is exactly visualiserRoute's route, which its test asserts.

Paths here are site-relative and start with / unless base is given; a directory path ends with / exactly when the caller's path does (or is empty), so a page and a directory are never conflated.

Nothing here reads the disk: a consumer passes names it has already resolved, so the same answer comes back in a test, a generator and a workflow.
