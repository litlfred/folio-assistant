Description

Where a note is attached, as a three-state answer.

CarriedNoteSchema already carries targetLabel (the block label a note is attached to), exercised by sticky-todos.e2e.ts. What it cannot say is the difference between:

| | meaning | |---|---| | block | attached to one block, named by its label | | page | deliberately page-global, at the top of the page | | none | attached to nothing, and nobody has said otherwise |

With an optional string, page and none are both undefined, though the second is a defect and the first a choice.

Page-global is an ABSENCE of block, not a reserved block id

A sentinel like __page__ in targetLabel would put a non-label in a label field and collide with a real block of that label; and a page-global sticky (e.g. on the landing page) may have no block to point at.

Beans get NO anchor — a rule

A bean says what is being worked on; a sticky says where a note sits on a page. A move is recorded on a bean as a note, which workflow/bean-link.ts already writes, needing no new field. The bean schema is not changed: a bean's front matter is written by a third-party CLI, so an added field is not guaranteed to survive a round-trip.

targetLabel stays

An anchor of kind block is a targetLabel with its state made explicit, and anchorOf derives one from a note that has only the old field. New writers set anchor; every reader can answer from either.
