Description

A TOOL RUN RECORD — did the downstream tool run, did it succeed, and over which inputs.

Downstream tools (e.g. LSI indexing) are not part of the primary pipeline, so their success is a QA criterion family (generalising lsi-index-fresh): a stalled dependency stalls QA. Every downstream tool is a Tool node declaring downstream (schemas/tools/tool.ts#ToolDownstreamSchema), and each run writes one of these.

Three states

downstreamState reads a record against the current input fingerprint:

  • fresh — a SUCCESSFUL run whose recorded input fingerprint matches the current one. The only state that is a pass.
  • stale — a successful run over inputs that have since changed. The dependency moved, so the QA over it is stale.
  • not-run / failed — no record, or the last run failed. Never green: an output with no evidence that it was produced has not been shown to be current, however plausible the file on disk looks.

The fingerprint is the tool's

The member computes its own fingerprint and the record carries it, because only the tool knows what counts as a change (LSI ignores files that yield no unit, so a whole-directory hash would call an unchanged index stale).

No timestamp

The record is committed and rewritten by generators that skill:register checks for staleness; a time field would make every re-run a diff. What the run was OVER is the identity; when it happened is git log's answer.
