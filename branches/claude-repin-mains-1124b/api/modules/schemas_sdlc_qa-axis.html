    Module schemas/sdlc/qa-axis

    QA axes — what part of an instance a QA record is ABOUT, and one shared vocabulary for its counts.

    Owner, 2026-11-24: "build integrated page into platform" — ONE QA page per harness instance, integrating rendering, Lean, compute, the knowledge graph, translations, block QA and the rest, drawn by the platform for every harness rather than copied into each. Until then each QA file FORMAT had its own card or page (kg-qa/v1 on the per-layer page, block QA beside the folio site, the FHIR IG's qa.html, a paper's render-qa.json read by nothing), and the formats spelt their counts differently (totals against counts, n/a against na). An axis is the grouping a reader asks about ("is the Lean clean?"); a format is how one writer happens to record it.

    Three things live here, and nothing else should restate them:

    1. QA_AXES — the closed list of axes, in page order.
    2. QaCounts and normalizeCounts — pass / fail / warn / unknown / na. unknown is never shown as zero, and a record whose counts cannot be read is undefined, not {}.
    3. summarizeQaDoc / axisOf — the axis and counts of one record, read from its $schema first and its path second.

    A layer DECLARES its writers and the axes it answers for in its own <instance>.json (qa, QaDeclarationSchema); the reusable publish workflow runs the declared writers and the page draws one section per axis.

    Pure: no filesystem, no network. The page script receives QA_FORMAT_RULES as data, so the browser classifies exactly as the publisher does without a second copy of the rules.
