oa-frontmatter-is-the-routername and description live in the SKILL.md front matter, because that is what OpenAI routes on
OpenAI reads each skill's name and description from its front matter and puts them in the prompt context, so a skill is found and chosen by those two fields alone. A description written only in the body is invisible to routing. The base voice says WHAT a description must state; this is where OpenAI requires it to be.		structure · critical
OpenAI models expect names and descriptions to come from frontmatter (important for discovery and routing).

oa-routing-use-when-dont-use-whenThe body states when to use the skill AND when not to, with a few edge cases
Explicit routing guidance in SKILL.md: a 'Use when…' list, a 'Don't use when…' list, and the edge cases between them. The negative half is the point: it is what stops a skill being invoked where it does not apply.		structure · major
Add explicit routing guidance: “Use when…” vs. “Don’t use when…”, and a few key edge cases, all in `SKILL.md`.

OpenAI's upload limits: exactly one SKILL.md (matched case-insensitively), at most 500 files per version, a zip of at most 50 MB, and no uncompressed file over 25 MB. A bundle outside them does not upload, which is why this is a vendor rule.		formatting · critical
