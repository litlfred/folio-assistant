Description

A prefix-sharded identifier lookup for nodes a folio REFERENCES but does not hold.

Where it sits in search

Search indexes only MATERIALISED content (lunr, in the plain docs pipeline), this prefix-sharded lookup covers REFERENCED nodes, and delegation to the source is the fallback wherever canDelegateSearch allows.

The shape

One manifest.json per index, and one JSON shard per (namespace, prefix). An identifier kind/local lives in namespace kind, in the shard named by the first prefixLength characters of local. A reader who types an identifier fetches the manifest once and then one shard, so what they download is bounded by SHARD_BUDGET_BYTES, not by the corpus.

The prefix length is measured, not chosen

choosePrefixLength takes the smallest length at which no shard in that namespace exceeds the budget, per namespace: uniform hex UUIDs and word-skewed slugs need different lengths.

The budget (64 KiB) is a CEILING — a ~50 KB in-memory target rounded up to a power of two — so a typical shard is well below it.
