Description

What an EXTRACTION produced, and when — provenance for assets pulled out of a container.

Three timestamps, three meanings

| | says | |---|---| | dc.date.issued | when the PUBLISHER published the work | | materializedAt | when WE brought the bytes local (core's materialization.ts) | | extractedAt here | when a TOOL produced this file out of something else |

An extraction timestamp is never a publication date. A captured file's dates are when it was saved, not when the work was published, and its producer string (e.g. a browser's print-to-PDF) is often the only evidence that the artefact is second-hand.

Metadata, not contents

The default product of reading a container is this record — a list of what is inside, with sizes, types and digests — and NOT the files. Contents are extracted only on explicit request. An ExtractedAsset describes an entry; localPath is present only where that entry was asked for, and its absence is the normal state.

It is the contract behind the harness's asset-extraction skill, written by scripts/extract-assets.ts.
