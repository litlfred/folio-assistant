Description

What a Tool is.

A skill states a capability generically; a Tool is one concrete way to exercise it, and names the skills it satisfies. That separation is the SOP in skills/tools/folio-core/skills-and-tools.md; this schema makes it checkable.

Authoritative, and the only authority

Zod here, JSON Schema and JSON-LD generated from it — the carrier decision in skills/kg/kg-core/directory-conventions.md §"What lives in the schemas graph". The TypeScript type is z.infer, never declared alongside.

Three constraints

1. invoke must offer an arm the harness can run. agentic-harness assumes no MCP server, so a Tool whose only invocation is invoke.mcp is not usable by the layer that defines it — and would also make the MCP projector emit a server that proxies itself. It is rejected at parse time.

**2. io.*.schema is an absolute IRI**, not a bare string. A relative reference resolves differently depending on where a consumer fetched the Tool. Absolute or nothing — the same rule kg-export follows for @id and harness-schema-export for $id.

3. satisfies must be non-empty. A Tool that satisfies no skill is a mechanism nothing asks for. Whether the named skills exist is checked by scripts/check-tools.ts, which resolves them against the real skill locations.
