GitHub Pages (gh-pages)

Push a rendered Knowledge Graph to GitHub Pages at a publication root URL — a staging preview (branches/<slug>/) or the release root, the same steps either way — and report the push: a status (pushed, not pushed, could not determine) and one message carrying the commit merged onto gh-pages and the QA result. Its steps are bootstrap-tools’ render-kg-to-github-pages process, which first provisions the target: an orphan gh-pages branch, then Pages switched on to serve it.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

render-kg-to-cdn

Render a Knowledge Graph, or a list of its Subgraphs, for publication to a CDN at a publication root URL, and report a status and one message. The same step for a staging preview and for a release — only the root URL and the target differ. Names the target’s Tool, never its steps: GitHub Pages (gh-pages) is one Tool, and it carries its own subprocess.

Source: cat-harness/skills/process/workflow/render-kg-to-cdn.md.

Also satisfied by: ci-docs-site, publish-gh-pages.

The skill declares no I/O contract (schemas/skills/render-kg-to-cdn/{input,output}.schema.json).

How it is deployed and reached

  • GitHub Actions. No workflow in this checkout runs its command.

When a host it reaches is refused:

host / errorremedy
github.comnone: Publishing IS a push to the gh-pages branch; there is no offline arm. To look at a page, build it locally with bun run cat preview:site.
when to choose it
whenThe CDN target is GitHub Pages: this repository’s docs site and its review previews, and every layer whose declaration names a GitHub repository.
limitsGitHub only. Pages cannot serve server-side redirects or custom headers, and a full-replace push to the gh-pages branch deletes what the build did not produce unless the caller restores it first (docs-site-publish). Another CDN is another Tool satisfying render-kg-to-cdn.
costFree for a public repository: Pages and the Actions minutes its workflow uses. A deploy takes a minute or two to be served.
