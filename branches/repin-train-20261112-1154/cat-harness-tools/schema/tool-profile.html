Description

Tool profiles — a named set of tool releases a run selects as one.

A test scenario selects a profile (default, ci-2026-10, lean-4.35-test) to load a different set of tool releases; a resolver (not built yet) is to provision every release it names.

A profile names tools, never a runtime

Runtimes come in transitively, through each release's own runtimes[]. A profile that named a JRE would pin java for every tool in it, and different tools may need different javas. So:

  • structurally, every key of tools must equal the name of the release it maps to. plantuml: "temurin-jre@21.0.4+7" is refused by the schema;
  • against the graph, toolReleaseGraphProblems refuses a profile whose ref resolves to a release declared role: "runtime" — a fact about OTHER files, which the schema alone cannot see.

Why the graph checks live here

They need both families, and tool-release.ts must not import this module back. Everything a check needs to reject a profile or a dangling runtime ref is in toolReleaseGraphProblems; scripts/tool-releases.ts --check runs it over every declared directory.
