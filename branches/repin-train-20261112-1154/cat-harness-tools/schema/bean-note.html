Description

A BEAN NOTE — one pull request's addendum to a bean, in a file of its own.

Appending to one bean from several pull requests conflicts on every merge, and the merge-main bot refuses a bean conflict (beans: refuse in merge-conflict-patterns.ts). A note is a file of its own, so two pull requests adding notes touch two different paths and git merges them with nothing to resolve.

The naming rule

<bean-id>--<YYYY-MM-DD>--<branch slug>.md

The branch is the key that makes two writers disjoint: one branch is one pull request's head, so two open pull requests never share it. It is also known at the FIRST commit, which a pull request number is not — open the pull request after that commit, not before it. The date prefix sorts a bean's notes in the order they were started.

One branch writes one file per bean. A second note from the same branch is a new section in the same file, found by its front matter (bean + branch) rather than recomputed from today's date — so a branch that runs over midnight does not split its notes.

The file declares what it is

Front matter carries $schema: folio-bean-note/v1, the bean, the branch and the date the note was started. A file in the notes directory that does not carry the tag is a finding, never silently skipped, and the check recomputes each file's name from its own front matter: a name that does not match is a finding.
