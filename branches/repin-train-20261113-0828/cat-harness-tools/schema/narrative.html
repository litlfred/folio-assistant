Description

A generated narrative, and who stands behind it.

An image description, a transcript, a dataset summary: agent-drafted, human-confirmed, so the state is a state machine, not a boolean.

Two attributions, because they are two acts

drafted_by is who wrote the words; confirmed_by is who accepted them. A reader of a narrative most wants to know whether a person has agreed to it.

An agent cannot confirm its own draft

confirmed_by.kind must be "human", structurally. Without it, "confirmed" degrades into "an agent said so twice".

rejected is a state, and it keeps its reasons

A rejected draft is kept, with a reason, so it is neither silently re-offered nor redrafted identically — the same demand schemas/sdlc/qa-review.ts's Decision makes.

One narrative per language

A narrative carries its language as a BCP 47 lang, and a slot holds one narrative PER language, each with its own author, model version and review state: a translation is drafted and confirmed like any other narrative, and a missing language is visibly absent rather than silently the source text.

lang is required on every WRITTEN narrative; the empty slot, NOT_AUTHORED, claims no language. NarrativeSlotSchema accepts the single form or a list with distinct languages, and readers go through narrativesOfSlot. The superseded history of block summaries requires lang too, and authored figures carry a slot (constraints.ts).

Not a second review model

Attribution and its script | agent | human vocabulary come from schemas/content/attribution.ts, which block-qa.ts also re-exports.
