Description

What a card's open panel offers — the kind declares, the platform fixes.

Each content type controls its own rendering, avatar (avatars.ts) and zoom threshold (semantic-zoom.ts), and can open a full-screen panel. The kind declares its controls ([linksrc], [edit], …); the platform fixes the chrome. [x] is in the same place with the same behaviour on every panel, so a reader learns the frame once.

Three states

| | what it means | how a reader sees it | |---|---|---| | not declared | this kind does not offer it | no control | | declared, servable | offered and usable | the control | | declared, unservable | offered, and this deployment cannot | no control, and a reason |

An [edit] the pipeline cannot perform would 404 on a private repository for the reader who cannot edit, so a declared-but-unservable control is HIDDEN — and servableControls returns why, because "this kind does not offer edit" and "this deployment cannot serve edit" are different facts.

Validated against a KNOWN LIST, so a typo is a finding

Otherwise "edti" would be a control that silently never appears.
