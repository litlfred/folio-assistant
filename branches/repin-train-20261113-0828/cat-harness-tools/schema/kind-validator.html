Description

Resolving a graph typology's validator — the one parameter that turns "validate a node" from one case per schema into a lookup.

Skills' inputs and outputs are constrained by schemas through one common pattern, not a Tool per Zod schema. The parameter is the graph typology: harness.json already says which directory holds which kind, and GraphTypologyDef.validator supplies the schema.

A downstream layer inherits the platform's tools/ graph but not its CI workflows, so this is how a folio built on the platform validates its own graph.

Three states

| | | |---|---| | resolved | the kind declares a validator and it loaded | | undeclared | the kind declares none — could not determine, never "valid" | | unresolvable | it declares one that does not load — a defect, and loud |

Many kinds are undeclared, so collapsing it into success would report a clean sweep over most of the corpus. The result is a union, so a caller cannot read a verdict without handling the middle state.
