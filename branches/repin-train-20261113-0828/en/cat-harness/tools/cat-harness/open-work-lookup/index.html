Does a path or bean exist on main or any open PR

Answer whether a path, a path prefix or a bean id appears on a repository’s default branch or on the head of any of its open pull requests, and where: the PR number, head branch, first commit author and creation time. A path or prefix matches files at the default branch and files each open PR changes; a bean id matches PR titles, bodies and head branch names. Repositories or PRs that could not be read are listed, so an empty answer is never mistaken for absence.

How it is deployed and reached

  • Command line. From the repository root: bun run cat lookup:open-work. cat lookup:open-work runs bun run cat-harness-tools/scripts/open-work-lookup.ts (declared in cat-harness-tools/package.json).
  • In process. scripts/open-work-lookup.ts — loaded by the harness directly, with no server.
  • GitHub Actions. No workflow in this checkout runs its command.

As an API: its operation in the OpenAPI document and the MCP tool list of its layer.

runtimebun

When a host it reaches is refused:

host / errorremedy
api.github.comnone: No declared Tool lists open PRs another way. A session with the GitHub MCP server can list them with list_pull_requests and read each one’s files.
when to choose it
whenBefore starting work that a sibling may already have in flight, and before publishing that a path or a piece of work does not exist.
limitsOpen PRs only, not unpushed local branches or closed PRs. It uses the GitHub REST API, not GraphQL, because cloud sessions are refused GraphQL. A PR’s changed-file list is capped by the API at 3000 files; a bigger PR is listed under unread rather than guessed. For the current checkout alone, git show origin/main:<path> in its own command is enough.
costOne paged REST listing of open PRs per repository, plus one files listing per open PR for a path or prefix query.
