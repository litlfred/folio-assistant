depends-on.ts — instance-versioning.md §3.4's record, and the gaps it cannot fill.

kg-export emits, per publishable layer, {packageId, version, uri} per dependency — the fields FHIR's ImplementationGuide.dependsOn carries, so an external consumer reads this layer's dependency set as it reads a FHIR IG's.

A dependency that cannot be expressed is REPORTED, never dropped

Most layers are not publishable (§3.1), so many edges point at something with no id and no version. Emitting dependsOn: [] would say the layer depends on nothing; a partial record with an empty version would fail a consumer. So each such edge becomes a DependsOnGap carrying WHICH reason applies — undecided (nobody said) and internal (somebody said no) are different gaps with different remedies.
