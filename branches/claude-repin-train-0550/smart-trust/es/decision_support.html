Antecedentes

Las reglas de negocio para credenciales sanitarias son las instrucciones, directrices y normas que expresan políticas sanitarias como “esta pauta de vacunas cumple los requisitos de entrada de la jurisdicción” o “este paciente debería completar su calendario de vacunación”. Estas políticas pueden respaldar diversos escenarios, como la evaluación de pruebas de vacunación o la continuidad de la atención.

La aplicación de reglas de negocio en el contexto de las redes de confianza para credenciales sanitarias requiere un enfoque computable y basado en estándares para definir las reglas y, posteriormente, evaluarlas sobre las credenciales. Por ejemplo, las personas que deseen comprobar, antes de viajar, si sus credenciales de vacunación cumplen los requisitos de entrada en frontera deben poder evaluar las reglas de negocio de diversas jurisdicciones de destino sobre diversos formatos de credenciales.

La iniciativa DDCC de la OMS utiliza Clinical Quality Language (CQL), un estándar para reglas de negocio del ámbito sanitario, como representación computable de las reglas de negocio que se aplican a las credenciales sanitarias en su red mundial de confianza. CQL define una representación de la lógica legible por personas que puede evaluarse sobre conocimiento clínico, incluidas las credenciales sanitarias. CQL es un lenguaje específico de dominio pensado para que los expertos del ámbito clínico puedan tanto redactar como leer expresiones clínicas, y no requiere conocimientos de desarrollo de software. Una vez redactado el CQL, para ejecutarlo sobre conocimiento clínico primero hay que traducirlo a su representación canónica, el Expression Logical Model (ELM). La expresión ELM resultante del CQL puede ejecutarse sobre una credencial sanitaria DDCC mediante un motor de ejecución de CQL. El resultado puede empaquetarse y compartirse, lo que significa que la ejecución de CQL no requiere un servidor central y es independiente de la plataforma. Esto garantiza que el CQL pueda ejecutarse sobre datos de salud sin necesidad de compartir datos de salud personales.

Las credenciales sanitarias pueden especificarse mediante múltiples estándares. Las credenciales sanitarias DDCC, que pueden evaluarse con reglas de negocio CQL, se especifican mediante el estándar Fast Healthcare Interoperability Resources (FHIR). FHIR es un estándar que permite el intercambio electrónico de información sanitaria. Se basa en estándares de Internet comunes y ampliamente utilizados en la industria, como el protocolo de transferencia de hipertexto (HTTP), la notación de objetos de JavaScript (JSON), la transferencia de estado representacional (REST) y el estándar Open Authorization (OAuth).

Las reglas de negocio en la práctica

En la práctica, el uso de CQL para aplicar reglas de negocio a las credenciales sanitarias es un proceso que se desarrolla en varios pasos. Por ejemplo, en un escenario en el que un ministerio de salud pretende implantar requisitos de pruebas de COVID-19 para la entrada en un país, a lo largo del ciclo de vida de las reglas se seguirían estos pasos:

  1. Conceptualización de las reglas: en primer lugar, las propias reglas deben decidirse a nivel de gobernanza. En este ejemplo, el ministerio de salud podría decidir exigir una prueba negativa de COVID-19 realizada en las 72 horas anteriores para permitir la entrada en un país

  2. Elaboración de las reglas: las reglas pueden ser redactadas en CQL por expertos del ámbito clínico. En este ejemplo, el CQL expresaría el plazo de 72 horas e indicaría qué pruebas de COVID-19 son aceptables.

  3. Publicación de las reglas: las reglas CQL pueden empaquetarse como un recurso Library de FHIR y publicarse en un servicio sanitario de confianza en línea. En este ejemplo, la publicación de las reglas permitiría a un viajero obtener las reglas publicadas para ejecutarlas en una aplicación de verificación universal sobre su SMART Health Card antes de viajar, a fin de asegurarse de que cumple los requisitos de entrada.

  4. Verificar las credenciales sanitarias: antes de poder ejecutar CQL sobre las credenciales sanitarias, las credenciales deben validarse para garantizar su autenticidad. Esta validación puede recurrir a una infraestructura criptográfica federada para compartir la infraestructura de autenticación entre jurisdicciones.

  5. Convertir las credenciales sanitarias al formato admitido para la verificación: la iniciativa DDCC de la OMS define un estándar común basado en FHIR para las credenciales sanitarias sobre el que puede ejecutarse CQL. Las credenciales en otros estándares pueden convertirse al estándar FHIR DDCC mediante los StructureMaps y ConceptMaps de FHIR definidos en la guía de implementación DDCC.

  6. Ejecutar el CQL sobre las credenciales sanitarias: una vez convertidas las credenciales, el CQL puede ejecutarse sobre ellas y obtenerse un resultado. En este ejemplo, los resultados mostrarían si el viajero cumple o no los requisitos de viaje.

Elaboración de CQL

El CQL expresa la lógica de las reglas de negocio de una forma a la vez legible por personas y computable. Para que la lógica pueda calcularse sobre las credenciales sanitarias de manera escalable y normalizada, debe redactarse con respecto a un formato estándar común de representación de las credenciales.

Herramientas de elaboración

El CQL puede redactarse con cualquier editor de texto; no obstante, utilizar un entorno de desarrollo integrado (IDE) que admita específicamente CQL puede facilitar el trabajo. El IDE Visual Studio (VS) Code dispone de una extensión para CQL que ofrece resaltado de sintaxis al escribir CQL.

Estructura de CQL

Los artefactos CQL se organizan en torno al concepto de biblioteca. Una biblioteca CQL puede entenderse como un contenedor de una instancia concreta de lógica de negocio. Un archivo CQL comienza con la declaración del nombre y la versión de la biblioteca:

library DDCCPass version '1.0.0'

Cada biblioteca CQL opera sobre uno o varios modelos de datos concretos. En el caso del CQL destinado a ejecutarse sobre credenciales sanitarias DDCC, el modelo de datos es FHIR, que puede especificarse con la declaración using:

using FHIR version '4.0.1'

Las bibliotecas CQL también pueden contener declaraciones de terminología, como sistemas de códigos (codesystems) y conjuntos de valores (valuesets). Estas declaraciones permiten al CQL definir un nombre local para representar un sistema de códigos o un conjunto de valores utilizado en la lógica CQL:

valueset "WHO Specimen Sample Origin": 'https://smart.who.int/ddcc/ValueSet-who-ddcc-sample-origin-covid-19.html'

El nombre local puede utilizarse después para hacer referencia al sistema de códigos o al conjunto de valores en el CQL:

define "ValidSampleOrigin": [Observation] O where O.method in "WHO Specimen Sample Origin"

Los sistemas de códigos y conjuntos de valores a los que se hace referencia en las credenciales sanitarias DDCC se encuentran en la IG DDCC:

  • Sistemas de códigos de la IG DDCC
  • Conjuntos de valores de la IG DDCC

La información completa sobre la elaboración de CQL, con ejemplos, se encuentra en la Guía de elaboración de CQL (CQL Authoring Guide). Pueden consultarse directrices y buenas prácticas adicionales en las Directrices de CQL de la IG CRMI.

CQL para credenciales sanitarias

La IG DDCC de la OMS especifica las credenciales sanitarias mediante el estándar FHIR, y el CQL que expresa reglas de negocio sobre las credenciales opera sobre los recursos FHIR que componen una credencial. El Bundle de documento de la credencial sanitaria DDCC contiene un recurso Patient mínimo junto con los recursos Immunization vinculados correspondientes, que representan la información sobre las vacunas administradas, y recursos Observation, que representan los resultados de las pruebas.

Empaquetado de CQL para su distribución

El CQL puede empaquetarse para su distribución en un recurso Library de FHIR, destinado a describir y compartir artefactos de conocimiento como el CQL. Las Directrices de empaquetado de la IG CRMI explican cómo deberían empaquetarse las bibliotecas CQL. Pueden encontrarse ejemplos de CQL empaquetado en recursos Library de FHIR en las Bibliotecas de artefactos de conocimiento de la IG DDCC.

Ejemplo de CQL

El siguiente CQL de ejemplo muestra un caso sencillo de reglas de negocio aplicadas a las inmunizaciones:

// Declare the name and version of the Library of functions
library DDCCPass version '1.0.0'

// The version of FHIR we are using
using FHIR version '4.0.1'

// Execute all business rules relative to a specific Patient content
context Patient

// Define boolean valued business rule to check if there is an immunization that was completed
define "Completed Immunization": exists ("Completed Immunizations")

// Define a list of completed immunizations for which the dose number is the same as the series dose
// Immunization resources are queried from those that reference the Patient we are executing against
define "Completed Immunizations":
  [Immunization] I
    where ( I.protocolApplied.doseNumber.value = I.protocolApplied.seriesDoses.value )

Recursos para la elaboración de CQL

Véanse Introducción a CQL, Guía de elaboración de CQL, Directrices de CQL de la IG CRMI y Directrices de empaquetado de la IG CRMI.

Ejecución de CQL

Una vez redactado y empaquetado en un recurso Library de FHIR para su distribución, el CQL puede ejecutarse en un entorno de ejecución de CQL. Antes de ejecutarse, el CQL debe convertirse en su representación ELM mediante el traductor de CQL a ELM (CQL-to-ELM Translator). Esta conversión puede realizarse con el servicio de traducción de CQL a ELM, que también está disponible como imagen Docker. El ELM resultante puede ejecutarse después en un motor de ejecución de CQL. Entre los motores de ejecución de CQL disponibles figuran:

  • JavaScript CQL Execution Framework
  • Java CQL Evaluation Engine

También existe un CQL Evaluator, que combina el traductor de CQL a ELM (CQL-to-ELM Translator) con el Java CQL Evaluation Engine.

Terminología

La ejecución de CQL también requiere que estén presentes las referencias terminológicas adecuadas. Para ejecutar CQL en el Java CQL Evaluation Engine se necesita acceso a un servidor de terminología FHIR. El JavaScript CQL Execution Framework, además de admitir el uso de servidores de terminología, permite pasar recursos terminológicos a la biblioteca en el momento de la ejecución.

Mapas de estructura y mapas de conceptos

La guía de implementación DDCC define tanto la representación estándar común con respecto a la cual puede redactarse el CQL como los mapeos para traducir diversos formatos de origen a esa representación común. Los formatos de origen son

  • SMART Health Cards: vacunación y pruebas (SMART Health Cards)
  • Certificados COVID digitales de la Unión Europea (EUDCC)
  • Sellos digitales visibles de la Organización de Aviación Civil Internacional (ICAO VDS-NC)
  • Infraestructura digital para credenciales abiertas verificables (Digital Infrastructure for Verifiable Open Credentialing, DIVOC)

La representación común a la que deben transformarse estos formatos de origen de credenciales sanitarias antes de evaluar las reglas de negocio CQL es la Documentación digital de certificados de COVID-19 de la Organización Mundial de la Salud (DDCC de la OMS)

La traducción entre formatos requiere mapear correctamente tanto la estructura de la credencial como los conceptos clínicos expresados en ella.

Mapear la estructura requiere extraer los datos del formato de origen y expresarlos en el formato de destino. Por ejemplo, el nombre del titular de la credencial tiene una representación distinta en cada formato y debe mapearse correctamente al formato de destino. El mapeo de la estructura de la credencial se realiza mediante StructureMaps de FHIR. Los StructureMaps definen reglas que describen cómo se relacionan dos estructuras distintas y proporcionan la lógica que define cómo convertir automáticamente instancias de una estructura a la otra.

Además de mapear la estructura general, es necesario mapear correctamente los conceptos clínicos. Por ejemplo, un formato puede utilizar LOINC para representar el tipo de una prueba médica, mientras que otro puede utilizar SNOMED CT. El mapeo de los conceptos clínicos de un formato a otro se realiza mediante ConceptMaps de FHIR. Un ConceptMap define una correspondencia entre un conjunto de conceptos de un sistema de códigos y conceptos de otro sistema de códigos.

Para traducir formatos con los StructureMaps se necesita un motor de mapeo. Tenga en cuenta que el motor de mapeo en Java también requiere el uso de un servidor de terminología; de forma predeterminada utiliza tx.fhir.org.

Referencias:

  • Mapas de estructura de la IG DDCC
  • Mapas de conceptos de la IG DDCC
  • Implementaciones de motores de mapeo

Introducción práctica a CQL

En este documento se describe cómo ejecutar reglas de negocio escritas en Clinical Quality Language (CQL) sobre las credenciales para validar que los datos proporcionados cumplen los requisitos empresariales de la jurisdicción.

Descripción general

Para ejecutar reglas de negocio CQL sobre un registro de vacunación pueden seguirse los siguientes pasos generales, que se describen en detalle a continuación:

  • Partir de una credencial de vacunación en un formato admitido y de un conjunto de reglas de negocio escritas en CQL
  • Configurar el servidor FHIR Matchbox para transformar las credenciales
  • Identificar el StructureMap correcto para convertir la credencial de vacunación al modelo lógico CoreDataSet de DDCC
  • Utilizar Matchbox para transformar la credencial en una instancia del modelo lógico CoreDataSet de DDCC y, después, en la instancia de recurso DDCC correspondiente
  • Configurar el servicio de traducción de CQL (CQL Translation Service) para convertir el CQL en la representación Expression Logical Model (ELM)
  • Configurar un proyecto Node.js con las dependencias de CQL adecuadas para disponer de un entorno de ejecución para la representación ELM
  • Ejecutar las reglas de negocio sobre la instancia FHIR

Convertir las credenciales de vacunación en una instancia de recurso DDCC

El proceso comienza con la conversión de la credencial de vacunación que se va a evaluar al modelo FHIR DDCC. Para los ejemplos de este documento partiremos de una carga útil de credencial de ejemplo en formato SHC, que puede descargar:

curl https://raw.githubusercontent.com/WorldHealthOrganization/ddcc/main/structuremap-tests/fixtures/shc/example-00-b-jws-payload-expanded.json --output example-00-b-jws-payload-expanded.json

Las credenciales pueden convertirse con los StructureMaps adecuados mediante el servidor FHIR Matchbox.

Ejecución de la imagen Docker de Matchbox

El servidor Matchbox puede ejecutarse mediante su imagen Docker. El siguiente comando inicia la imagen Docker en una máquina local que escucha en el puerto 8080:

docker run -d -p 8080:8080 --restart unless-stopped eu.gcr.io/fhir-ch/matchbox:v314

NOTA: En el momento de redactar este documento, la última versión de Matchbox no gestiona correctamente las transformaciones de StructureMap necesarias; asegúrese de que la versión de Matchbox con la que realiza las pruebas esté actualizada. La imagen Docker de Matchbox no parece tener una etiqueta latest correcta, por lo que debe especificar el número de versión real de la imagen Docker más reciente.

Al ejecutar Matchbox de esta forma se utiliza un almacén de datos en memoria en lugar de una base de datos subyacente, por lo que el estado no se conserva entre distintas instancias del contenedor.

Carga de las IG en Matchbox

Matchbox necesita tener cargadas las IG adecuadas para realizar las traducciones deseadas. La IG DDCC y la IG SHC pueden cargarse con los siguientes comandos curl contra el servidor Matchbox:

curl -X 'POST' \
  'http://localhost:8080/matchbox/fhir/ImplementationGuide' \
  -H 'accept: application/fhir+json' \
  -H 'Content-Type: application/fhir+json' \
  -d '{ "resourceType": "ImplementationGuide", "version": "1.0.0", "name": "fhir.who.ddcc", "url": "http://smart.who.int/ddcc/package.tgz" }'

curl -X 'POST' \
  'http://localhost:8080/matchbox/fhir/ImplementationGuide' \
  -H 'accept: application/fhir+json' \
  -H 'Content-Type: application/fhir+json' \
  -d '{ "resourceType": "ImplementationGuide", "version": "0.6.2", "name": "hl7.fhir.uv.shc-vaccination", "packageId": "hl7.fhir.uv.shc-vaccination" }'
Conversión de la credencial de vacunación en un recurso FHIR DDCC

Se trata de un proceso en dos pasos. El primero consiste en convertir la carga útil de la credencial de vacunación al modelo lógico CoreDataSet de DDCC mediante el StructureMap adecuado de la IG DDCC:

curl -X 'POST' \
'http://localhost:8080/matchbox/fhir/StructureMap/$transform?source=http://smart.who.int/ddcc/StructureMap/CertSHCtoCoreDataSet' \
-H 'accept: application/fhir+json' \
-H 'Content-Type: application/fhir+json' \
-d @example-00-b-jws-payload-expanded.json \
-o example-00-a-DDCCCoreDataSet.json

Como resultado debería obtenerse un nuevo archivo con la información de la vacuna en el formato intermedio CoreDataSet. Los datos en el formato intermedio pueden convertirse después en una instancia de recurso FHIR DDCC:

curl -X 'POST' \
'http://localhost:8080/matchbox/fhir/StructureMap/$transform?source=http://smart.who.int/ddcc/StructureMap/CoreDataSetVSToAddBundle' \
-H 'accept: application/fhir+json' \
-H 'Content-Type: application/fhir+json' \
-d @example-00-a-DDCCCoreDataSet.json \
-o example-00-a-DDCC.json

El registro ya está listo para evaluarse con las reglas de negocio.

Ejecución de CQL sobre credenciales de vacunación convertidas

Ejecutar reglas de negocio CQL sobre un registro requiere traducir el CQL a la representación Expression Logical Model (ELM) y ejecutar el ELM en un motor de ejecución de CQL. En este documento partiremos de uno de los ejemplos de la IG DDCC:

// Declare the name and version of the Library of functions
library DDCCPass version '1.0.0'

// The version of FHIR we are using
using FHIR version '4.0.1'

// Execute all business rules relative to a specific Patient content
context Patient

// Define boolean valued business rule to check if there is an immunization that was completed
define "Completed Immunization": exists ("Completed Immunizations")

// Define a list of completed immunizations for which the dose number is the same as the series dose
// Immunization resources are queried from those that reference the Patient we are executing against
define "Completed Immunizations":
  [Immunization] I
    where ( I.protocolApplied.doseNumber.value = I.protocolApplied.seriesDoses.value )

Puede guardar este ejemplo en un archivo llamado DDCCPass.cql y modificarlo como desee antes de continuar.

Traducción de CQL a ELM

El CQL puede traducirse a ELM con la imagen Docker del servicio de traducción de CQL (CQL Translation Service). El siguiente comando inicia la imagen Docker en una máquina local que escucha en el puerto 8081:

docker run -d -p 8081:8080 --restart unless-stopped cqframework/cql-translation-service:latest

Una vez en funcionamiento el servicio de traducción, el CQL puede traducirse a ELM con el siguiente comando curl:

curl -X "POST" \
--url "http://localhost:8081/cql/translator/" \
--header "Content-Type: application/cql" \
--header "Accept: application/elm+json" \
--data-binary @DDCCPass.cql \
--output DDCCPassELM.json
Extracción de ELM a partir de un recurso Library de FHIR

Como alternativa a traducir el CQL, si el CQL deseado ya existe y la traducción a ELM está empaquetada junto con el CQL en un recurso Library de FHIR, el ELM puede extraerse de dicho recurso Library. En este documento se describe cómo extraer el ELM mediante un proyecto sencillo de Node.js. Si Node.js no está disponible, primero habrá que instalarlo. Puede crearse un nuevo proyecto de Node.js con npm:

mkdir ExtractELM
cd ExtractELM
npm init --yes

El siguiente código JavaScript de ejemplo puede servir como punto de partida:

// This example loads a FHIR Library, extracts the ELM, and writes it to a file

const { argv, exit } = require('process');
const fs = require('fs');

if (argv.length < 4) {
  console.log(`Usage: ${argv[0]} ${argv[1]} <FHIR-Library> <ELM-File>`);
  exit();
}

const libraryFile = argv[2];
const elmFile = argv[3];

// Load the Library contents and parse the JSON
const library = JSON.parse(fs.readFileSync(libraryFile), 'utf8');

// Find the ELM data
const elmContent = library.content?.find(c => c.contentType === 'application/elm+json')
if (!elmContent?.data) {
  console.log('No ELM content found in Library');
  exit();
}

// Base64 decode the ELM
const elm = atob(elmContent.data);

// Write the ELM to the desired output file
fs.writeFileSync(elmFile, elm);

Puede descargarse un ejemplo de recurso Library de FHIR que contiene ELM:

curl https://raw.githubusercontent.com/WorldHealthOrganization/ddcc/main/input/resources/Library-DDCCPass-1.0.0.json --output Library-DDCCPass-1.0.0.json

Una vez descargado el recurso Library de FHIR, puede ejecutarse el código para extraer el ELM del recurso Library:

node main.js Library-DDCCPass-1.0.0.json DDCCPassELM.json

La ejecución del script debería generar un archivo con la traducción a ELM deseada.

Ejecución de ELM sobre credenciales de vacunación convertidas

La traducción a ELM del CQL puede ejecutarse sobre el registro de vacunación con la biblioteca JavaScript CQL Execution Framework junto con la fuente de datos FHIR para la ejecución de CQL en JavaScript (JavaScript CQL Execution FHIR Data Source). En este documento se describe cómo configurarlo en un proyecto sencillo de Node.js. Si Node.js no está disponible, primero habrá que instalarlo. Puede crearse con npm un nuevo proyecto de Node.js con las bibliotecas CQL necesarias:

mkdir CQLDemo
cd CQLDemo
npm init --yes
npm install cql-execution cql-exec-fhir

Una vez configurado el proyecto, el ELM de las reglas de negocio CQL puede evaluarse sobre la credencial de vacunación convertida en instancia de recurso DDCC. El siguiente código JavaScript de ejemplo puede servir como punto de partida:

// This example loads an ELM file and vaccination records and evaluates
// the ELM against each record

const { argv, exit } = require('process');
const fs = require('fs');
const cql = require('cql-execution');
const cqlfhir = require('cql-exec-fhir');

if (argv.length < 4) {
  console.log(`Usage: ${argv[0]} ${argv[1]} <ELM-file> <vaccination-record>...`);
  exit();
}

const elmFile = argv[2];
const recordFiles = argv.slice(3);

// Load the ELM and set up the execution environment
const elm = JSON.parse(fs.readFileSync(elmFile), 'utf8');
const library = new cql.Library(elm);
const executor = new cql.Executor(library);

// Load all the vaccination records
const patientSource = cqlfhir.PatientSource.FHIRv401();
const records = recordFiles.map(filename => JSON.parse(fs.readFileSync(filename, 'utf8')));
patientSource.loadBundles(records);

// Execute the business rules against the records and show the results
const results = executor.exec(patientSource);
console.log(results);

Este código puede ejecutarse para aplicar las reglas de negocio al recurso con el siguiente comando:

node main.js DDCCPassELM.json example-00-a-DDCC.json

La ejecución del script debería producir resultados similares a los siguientes:

    }
  },
  unfilteredResults: {},
