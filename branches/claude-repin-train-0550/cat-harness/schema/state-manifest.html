Description

The ROOT MANIFEST of a special branch — what the branch is, where it came from, and whether it is the store or a copy.

Every state-manifest/v1 branch carries a root manifest.json stating the facts a reader cannot recover from the branch's files: its status, the commit it was seeded from, when, and how it is written. This is that field set, so the branch README is RENDERED from it (branch:readme) rather than kept by hand.

Two shapes, discriminated by the keying

| keyedBy | branches | carries | |---|---|---| | tip | beans, todos, fsh-guts, health, issue-marks, merge-queue, state | subgraph, source {ref, sha}, seededAt, refreshedAt?, graphs[] | | route | uml-overview, ig-docs | seededFrom, seededAt, writer, gate, bean, directories[] |

They differ because the WRITE differs (subgraph-source.ts): a tip-keyed branch is somebody's state, seeded once from main and then edited; a route-keyed one is regenerable output with one named generator and the gate that checks it.

qa-reports is commit-keyed and carries no manifest at all; it is not a state-manifest/v1 branch, and its README is rendered from its declaration alone (see branch:readme).

Extra keys are kept, not refused

Both shapes are passthrough, so recorded notes such as a retired branch's retiredAt, retiredReason, supersededBy and _comment entries survive.
