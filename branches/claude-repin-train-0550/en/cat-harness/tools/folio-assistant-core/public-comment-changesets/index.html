Public-comment change-sets

Bring a public review’s change-sets back in line with GitHub: open the primary issue of each change-set somebody has engaged with, link the other issues that discuss it, and re-render each issue’s change-set section from its changesets/CS-*.json record. The nightly half of what the folio’s public-comment workflow does on each issue event (github); check validates the records without writing.

How it is deployed and reached

  • Command line. From the repository root: bun run folio-assistant-core/scripts/public-comment-changesets.ts.
  • GitHub Actions. 3 workflow line(s) run its command:
workflowline
folio-assistant-core/.github/workflows/public-comment-check.yml47run: bun run folio-assistant-core/scripts/public-comment-changesets.ts check --store "$STORE"
folio-assistant-core/.github/workflows/public-comment-check.yml62run: bun run folio-assistant-core/scripts/public-comment-changesets.ts reconcile --store "$STORE"
folio-assistant-core/.github/workflows/public-comment.yml81run: bun run folio-assistant-core/scripts/public-comment-changesets.ts github --store "$STORE" --event "$GITHUB_EVENT_PATH"

When a host it reaches is refused:

host / errorremedy
github.comnone: The issues live on GitHub; offline, check still validates the records and nothing is opened or re-rendered.
when to choose it
whenChange-set records and their GitHub issues may have drifted: a recommendation made from the CLI, an issue edited by hand, or a missed workflow run.
limitsWrites only under the store and to issues of the current repository. One run at a time, like the workflow it backs.
costSeconds plus one GitHub API call per change-set that has issues.
