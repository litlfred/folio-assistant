OpenAPI ingest from source

Ingest the OpenAPI documents a layer’s cat-openapi.config.json lists under documents from a local checkout of their repository, read AT a branch, tag or commit (git show), verbatim, with a provenance recording the resolved commit and the document’s sha256. --check verifies the committed copies offline.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

library-ingestion

The BASIC ingestion flow every asset takes: an upload is accepted, its metadata goes into the knowledge graph, and the asset lands in library/<slug>/ if it is materialized. The two entry points (a drop in uploads/, or materializing an asset a remote graph lists), what happens to the upload afterwards, and why content-type methods refine this flow from above rather than living in it. Command: bun run cat ingest.

Source: cat-harness/library/skills/library-core/library-ingestion.md.

Also satisfied by: ingest-extended, ingest-stdlib, l1-complete-check, narrative-queue, openapi-ingest-rendered, transcribe-faster-whisper, transcribe-vosk, transcribe-whisper-cpp.

The skill declares no I/O contract (schemas/skills/library-ingestion/{input,output}.schema.json).

How it is deployed and reached

  • Command line. From the repository root: bun run cat openapi:ingest. cat openapi:ingest runs bun run cat-harness-tools/openapi/scripts/ingest-openapi.ts (declared in cat-harness-tools/package.json).
  • GitHub Actions. No workflow in this checkout runs its command.

As an API: its operation in the OpenAPI document and the MCP tool list of its layer.

when to choose it
whenA layer holds an OpenAPI spec whose source is a repository (e.g. a gateway’s spec file) and the KG should describe it, pinned to a commit.
limitsReads a LOCAL checkout; fetching the repository is the caller’s. A document that is not OpenAPI 3 fails rather than being written.
costOne git read and one JSON parse per document. No network.
