The platform’s quality gates

Run the checks CI runs, derived from the workflow rather than listed here. One Tool for all of them, not one per gate: the list is computed from .github/workflows/code-quality-gates.yml at call time, so it cannot drift from what CI actually enforces.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

platform-gates

bun test passing is not the gates passing. What to run before you push, why the list is derived from the CI workflow rather than written down, and what a *:check failure is actually telling you to do.

Source: cat-harness/skills/process/process-core/platform-gates.md.

Also satisfied by: ci-code-quality-gates, judge-tree.

The skill declares no I/O contract (schemas/skills/platform-gates/{input,output}.schema.json).

continual-progress

Make in-flight work trackable by others in real time — open a PR from the first commit, push small coherent increments continuously (never hoard uncommitted work), keep a live status checklist in the PR body, and post brief intent on the PR + any overlapping sibling PRs. Use on any multi-step or long-running task, especially when siblings/agents or the author may need to follow, cherry-pick, or take over mid-flight.

Source: cat-harness/skills/conduct/conduct-core/continual-progress.md.

Also satisfied by: beans-cli, beans-manual.

The skill declares no I/O contract (schemas/skills/continual-progress/{input,output}.schema.json).

How it is deployed and reached

  • Command line. From the repository root: bun run cat gates. cat gates runs bun run cat-harness-tools/scripts/gates.ts (declared in cat-harness-tools/package.json).
  • GitHub Actions. No workflow in this checkout runs its command.

As an API: its operation in the OpenAPI document and the MCP tool list of its layer.

installnone
runtimebun
networkno
when to choose it
whenBefore any push, and as the answer to “what checks this?”. It matters most where CI is not: tools/ is an INHERITED declaration and .github/workflows/ is not, so a downstream layer gets this Tool and none of the gates it names.
limitsIt runs what the workflow declares, so a check CI does not run is a check this does not run. The default omits the browser jobs; --all adds them, and render:bpmn:check needs Chromium.
costThe fast set is about a minute, dominated by bun test. --all adds a browser render.
