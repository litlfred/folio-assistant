Build, check and (on request) publish a layer’s own site, or a branches/ preview

From a checkout whose layers arrive by remote mount: mount the pinned closure, install, run the layer’s own gates (--pre), compose the harness chrome for THIS layer, run its source steps, build with Jekyll at the base path read from the git remote (/<repo>, or /<repo>/branches/<branch> for a preview), run the post-build steps (mount-instance-docs, pdf-viewer, set-html-lang, publish-id-lookup, rail-standalone-pages), and check that every relative or base-rooted link in every page resolves to a file under the site, reading each page with an HTML parser. Any failing step stops the run; a link that does not resolve means nothing is published. It never decides to publish: only --publish does, and then a root publish keeps branches/ and _render-log/ on the branch, and a preview replaces only its own branches/<branch>/.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

remote-mount

Bring a harness, and every layer it depends on, into a checkout that does not hold it, from another repository at a pinned commit, as declared directories with a lock: a source.remote entry in the downstream’s root index.config.json (legacy: remoteMounts on its declaration) and mountDefaults on the harness. Covers when to mount and when to subscribe instead, why there are no submodules and no .deps/, the transitive closure through needs and gitlinks, overrides by id, the lock, and the three states.

Source: cat-harness/skills/kg/kg-core/remote-mount.md.

Also satisfied by: index-config-migrate, instantiate-harness, kg-retrieve-npm, mount-from-lock, npm, subgraph-index-package, ci-standing-repin.

The skill declares no I/O contract (schemas/skills/remote-mount/{input,output}.schema.json).

How it is deployed and reached

  • Command line. From the repository root: bun run cat site:instance. cat site:instance runs bun run cat-harness-tools/scripts/build-instance-site.ts (declared in cat-harness-tools/package.json).
  • GitHub Actions. No workflow in this checkout runs its command.

when to choose it
whenPublishing a layer’s site, or a branch preview of it, from an agent or a Routine: the agent-run replacement for a pages workflow.
limitsLayer sites only. A FHIR IG’s site (the IG pipeline layer’s stage-ig-sites) is not built here yet; it needs the IG’s FHIR packages, which some environments cannot reach.
costA full mount, install and Jekyll build: minutes, not seconds. --no-mount reuses what is on disk.
