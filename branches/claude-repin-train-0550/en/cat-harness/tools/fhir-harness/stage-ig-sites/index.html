Stage every IG whose instance records its source, one Jekyll site each

Clone each IG whose instance records a sushi-config source in fhir-artifact-index/menu.json, at the recorded commit, and stage it with build-ig-site (theme, artefact pages, post-processing fills, edit links to the IG’s default branch). Served at /<instance>/ when its docs declare igSite (its artefact pages copied in; a collision is refused), else /<instance>/ig/. Prints one <instance> <jekyll source> <at> line per IG for the caller’s jekyll build.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

ig-build-pipeline

The bare FHIR IG pipeline — FSH to SUSHI to the IG Publisher to a pages branch, with no pre-processing and no post-processing. What this layer runs, what it emits, and the list of things it deliberately refuses to know about. Owns the AST cache lifecycle: an IG site is built from the AST on its cache branch, the publish refuses a stale one, and the reusable ig-ast-refresh.yml is the one writer. Owns what an IG reader may read: contentTypes.ig.include in the repository’s index.config.json, and the legacy warning for a repository that declares none. Read before adding anything to fhir-harness, before onboarding, converting or changing the workflows of an IG repository, and before publishing an IG site.

Source: fhir-harness/skills/fhir-ig-base/ig-build-pipeline.md.

Also satisfied by: build-ig-site, fhir-core, ig-artifact-jsonld, ig-ast-refresh, ig-index-build, ig-page-render-qa, ig-pages, ig-publisher-i18n, ig-repo-site, ig-site-data, ingest-ig-menu, jsonld-vocabularies, logical-model-schemas, strip-library-binaries, strip-library-content, terminology-index, valueset-schemas.

The skill declares no I/O contract (schemas/skills/ig-build-pipeline/{input,output}.schema.json).

docs-generation

How a checkout of this harness generates and publishes its docs site: regenerating derived references, composing the docs layers and each layer’s site into one Jekyll source, building it with just-the-docs, the post-build passes, the TypeDoc API reference, the knowledge-graph export, and the full-replace publish to gh-pages and its branches/ previews.

Source: cat-harness/skills/ui/ui-core/docs-generation.md.

Also satisfied by: bpmn-checklist, bpmn-render, ci-post-merge-regen, pages-index, pages-publish, readme-audit, readme-sync, render-order, schema-docs, shared-assets, site-build-local, site-search-index, site-search-scopes, skill-docs, subgraph-readmes, upload-step-docs, proof-dependency-graph.

The skill declares no I/O contract (schemas/skills/docs-generation/{input,output}.schema.json).
