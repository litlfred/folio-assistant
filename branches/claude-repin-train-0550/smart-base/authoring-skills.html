Authoring Skills

Each authoring skill is modeled as a FHIR Requirements resource conforming to the SGRequirements profile. Each skill states a capability (e.g. “Can review terminology”) and contains checklist statements that define the criteria for demonstrating that capability.

Skills are organized by domain and assigned to authoring personas to define each persona’s skill package.

BPMN Swimlane Validation

As part of the BPMN authoring and review process, every innermost swimlane in a BPMN diagram SHALL correspond to an ActorDefinition resource. A lane names its ActorDefinition by id: its partitionElementRef (a top-level <bpmn:resource> whose id is the ActorDefinition’s FSH Instance: id), or else its own id. A lane is never matched by its display name or by a file name. The bpmn-validate tool in the smart-base knowledge graph checks this, together with the diagram’s structure and the absence of Camunda or Zeebe extensions, on every pull request that changes a .bpmn.

When a swimlane has no matching ActorDefinition, the author must resolve by:

  1. Referencing an ActorDefinition from a dependency IG
  2. Creating a new ActorDefinition in this IG
  3. Correcting the lane’s binding (its partitionElementRef or id)
