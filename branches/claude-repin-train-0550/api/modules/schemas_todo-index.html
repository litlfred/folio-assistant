    Module schemas/todo-index

    The published todo index — folio-todo-index/v1.

    Graph Node

    schema

    v1 is defined as what is actually published (including viewHref, editHref, theme, themeArt and repoWeb). The one reader is ours (docs-ui.js), and the emitter is checked against this module, so the next field cannot land unnoticed.

    target

    targetLabel is page-qualified, sec:<page>-<node>, because a bare node id such as what-is-not-built-yet can exist on two pages. Splitting it back is ambiguous (node ids contain -), and a downstream consumer must never have to string-manipulate, re-derive, or assume a rule in order to use what we publish. So target gives the page and node as fields. targetLabel STAYS: target is additive, and mountPageStickies matches on the whole label string.

    target is a DERIVED JOIN

    readTodoFiles hands the emitter only todo.targetLabel. The page and node live on the PAGE side, where blockLabel(page, node) reads a block's own declared label. So target comes from a reverse index label -> (page, node) built from the page walk the same script already performs.

    A label that resolves to no block emits no target. Absent is the third state: mountPageStickies reports a dangling targetLabel rather than dropping it, and a target guessed from a split would be wrong.
