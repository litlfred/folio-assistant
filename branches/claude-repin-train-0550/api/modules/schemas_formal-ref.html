    Module schemas/formal-ref

    Dependency injection point for FORMAL REFERENCES — the lean: field's grammar and the package list it resolves against.

    The grammar is science-layer vocabulary even though the lean field sits on shared kinds (remark, example, algorithm, simulator). Core reaches it only through this module, so it has no core → sci import edge.

    What core needs is NOT the grammar

    Every core call site does the same three steps: parseLeanRef(ref), leanPackageByName(pkg), then build source paths from the package's lakeRoot and the parsed module / decl / name. Core wants candidate source paths, which it tries with its own file access (ctx.fileExists, readFileBranch, existsSync, a grep).

    So FormalRefResolution is a resolution record, and the grammar, the package registry and the path convention stay behind it in the layer that owns them. Core does not learn what a Lake root is, what a module path is, or that the separator is a dot.

    The same shape as the other DI points

    pipeline/references-registry-di.ts (the bibliography) and value-registry-di.ts (the values registry) have the same shape: a configure…, a …Configured() predicate, and a getter that returns undefined rather than throwing.

    The predicate lets a caller tell "nothing configured" from "the check did not run". Every consumer must distinguish the two and say "not checked" rather than silently take the undefined branch — otherwise a lookup that returns undefined makes checks fail closed or open in opposite directions.
