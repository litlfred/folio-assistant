    Module schemas/sticky-contribution

    A sticky is a CONTRIBUTION from a layer, declared by that layer.

    Graph Node

    schema

    Each initiator creates its own sticky; the landing set is composed from the layers present rather than enumerated in one place — a layer owns what it can serve, and the layer above does not enumerate it (folio-graph-typology.ts).

    A DECLARATION, not a code registry

    code registrydeclaration
    bootstrap can contributeno — bootstrap/ holds no TypeScript, and bootstrap/harness.json declares a layer that may not import from the layer composed on top of ityes
    a downstream folio can contributeonly by shipping codeyes
    inheritancehand-wiredalready resolved, resolveDirectories-style
    expressivenessarbitrarythe fields below, and no more

    The first row settles it. The cost is a small vocabulary for "my description" and "the four onboarding links". A sticky's text is subject matter, which AGENTS.md puts in the folio as data.

    When a sticky is minted, and its docs link

    1. A harness's sticky is its initiation's last act. Each layer declares its own card in its own harness.json. The minting is not yet split: scripts/ensure-landing-sticky.ts runs at the end of cat-harness's initiation and writes every layer's card. contributingRoots already takes a LIST of roots, so per-harness minting is a caller change.
    2. Every sticky links to ITS OWN harness's docs, not the composing layer's — bootstrap's card points at bootstrap/README.md on the forge.

    Harness vocabulary, not core

    The declaration field lives on CatHarnessDeclarationSchema (schemas/kg/cat-harness.ts), so defining the shape in landing-sticky.ts would make the harness import core, which check:partition:edges reports. repo-partition.ts classifies this module agentic-harness: it is declaration vocabulary and imports only zod. StickyLinkSchema is defined here and re-exported from landing-sticky.ts.
