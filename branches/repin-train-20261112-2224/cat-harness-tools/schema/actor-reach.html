Description

Network reach is a property of an ACTOR, and how it composes with the deployment's. An air-gapped actor cannot use an API, so a process such as signing needs a route through a human actor.

One vocabulary, two levels

NetworkReach is the deployment's scale (Topology.network in cat-harness.ts); this module reuses it for actors rather than minting a second one. The two levels mean different things:

| level | what the value asserts | |---|---| | deployment | an aggregate over the machine actors in it | | actor | what this participant can reach |

This matches topologyConflicts: "At deployment level mixed MEANS THE ACTORS DIFFER FROM EACH OTHER."

The composition is ASYMMETRIC

  • air-gapped deployment ⟹ every actor air-gapped. Nothing inside can reach out; the bound is total.
  • internet deployment ⇏ every actor connected. A connected site may still hold an isolated signing host.
  • egress-restricted deployment ⇏ anything about a given actor. It says some egress is restricted, not which participant's.

So an undeclared actor under a non-air-gapped deployment is REACH_UNKNOWN — not the deployment's value.

unknown is the third state, and it is never "reachable"

Every consumer must route unknown the way it routes air-gapped: to the path that needs no network; otherwise a signing gateway could produce an unsigned report that looks signed ("could not check is never green").

What this module does NOT do

It does not choose a route. The branch is computed by sdlc/processes/decisions/signing-route.dmn and executed by the gateway in qa-report-signing.bpmn; this module supplies the fact the table reads.
