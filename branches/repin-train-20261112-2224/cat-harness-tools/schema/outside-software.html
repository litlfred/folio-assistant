Description

Outside software — the core every record of somebody else's software shares: its name, its version, its SPDX licence and where that was read, the digest of its bytes, and where the bytes come from. Never the bytes.

Two kinds record outside software, and both extend this core:

| kind | $schema | what the platform does with it | adds | |---|---|---|---| | tool-release | folio-tool-release/v1 | RUNS it | role, kind, entry, runtimes, platform, note | | software-library | software-library/1.2.0 | IMPORTS it, or keeps it vendored | range, dev, usedBy, shim, vendored, layer |

They stay two kinds because their rules differ (a library is never run, and a lockfile's integrity is sha512). Each kind NARROWS a core field where its own rule needs it: tool-release narrows name to a tool name and digest to sha256; software-library narrows name to an npm package name and source to a URL.

What is written once against the core

  • outsideSoftwareRef and parseOutsideSoftwareRef — the name@version ref. Split at the LAST @, because a scoped npm name (@scope/pkg) starts with one.
  • outsideSoftwareLicenceProblem — the licence checked against the PINNED SPDX License List with check:source-licence's own checkLicenceExpression, never a second parser.
