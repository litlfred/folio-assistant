Description

A library entry's ONE IRI — the address of its published JSON-LD.

The asset (the entry's manifest) is named by the URL its JSON-LD is published at, and that URL dereferences to the file. The viewer page at <site>/cat-harness/library/<instance>/<id>/ is a RENDERING of it: a second resource with its own IRI, which points TO the asset and is never named by it.

The IRI is …/assets/library/jsonld/<instance>/source/<id>: extensionless, its last two segments the node's kind and id (source, from the entry's class SourceDocument; issue #1830, Q-THIN-2 A, Q-THIN-6 B). Beside it:

    It sits under assets/library/, not /library/<instance>/, which is each instance's own mount route (mount-instance-docs.ts, rule 2). Block ids are not published addresses: they key summaries.json, LSI indexes and kg-qa sidecars.

    ONE function, called by the writer of the @id (gen-library-jsonld) and the publisher of the file (gen-library-viz), so the IRI and the place the file lands cannot disagree.

    It holds no Zod type: the rule it publishes is the address, not a shape. It is a graph node anyway (owner, 2026-11-10) so the rule has a page beside the library schemas a reader is directed to (library-nodes, document-structure), instead of being findable only in the source.
