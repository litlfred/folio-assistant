Description

The render log — what was published to the publish branch, when, and why: each staging rendering added or deleted, logged on the publish branch.

A SPECIALISATION of folio-log/v1, not a second logger

schemas/sdlc/log-entry.ts already answers "what does an entry look like": id, at, summary, detail, references, and a three-state capture. A render entry IS a log entry, with a rendering event and a rendering subject. It is a different store:

| | activity log (folio-log/v1) | render log (this) | |---|---|---| | subject | what an AGENT did | what was PUBLISHED | | store | fsh-guts/logs/, in the repo | the publish branch itself | | published | no | yes |

It lives on the publish branch because it describes what is ON that branch: a record of a deleted artefact is useful only where the absence can be seen.

Append-only

An entry is never rewritten, and a removal is a NEW entry, so removed does not delete the rendered entry that precedes it; "what happened to branches/x" is answered by reading forward.

What is NOT here

No size, no liveness: those belong to the health sweep, which reports and never acts. A log entry records an EVENT at the moment it happened.
