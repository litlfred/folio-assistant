Description

The bean graph — what beans/ is, rather than where it happens to be.

beans/ is a graph with named nodes, each node a store with its own kind and path:

 // beans/beans.json
{
  "name": "folio-assistant",
  "nodes": [
    { "id": "defs",      "path": "defs",      "kinds": ["bean-defs"] },
    { "id": "workflows", "path": "workflows", "kinds": ["workflow-state"] }
  ]
}

The graph states the layout; the harness config does not restate it. The path is also written in .beans.yml, because the third-party beans binary reads only that; that duplication stays checked.

Paths are relative to the graph root

A node's path is resolved against the directory holding beans.json, not against the repo root, so moving beans/ to work/ requires editing nothing inside it. A path escaping its own root (.., or absolute) is rejected: a folio must not scan a directory its graph does not own.

Three states

  • Absent → undefined. An unmigrated repo falls back to the documented defaults; this is ordinary, not an error.
  • Present but unreadable → throws, rather than leave every consumer guessing where the work plan is.
  • Unknown node kind → rejected, not accepted and ignored. A node whose kind nothing understands is a store nothing will read.

It defers to cat-harness.ts

A bean-graph entry IS a ContentDirectory: an id, a path, and the graph typologies found there (BASE_GRAPH_TYPOLOGIES). Same schema, same open registry, same JSON-LD projection. Only what is SPECIFIC to the bean graph is here: paths resolve against this file's own directory rather than the layer root, and at most one directory may hold workflow-state.
