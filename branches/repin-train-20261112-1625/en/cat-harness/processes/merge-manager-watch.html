Merge manager watch: wake, read the queue live, route

Process_MergeManagerWatch · strict (defaulted) · 11 step(s)

The loop run by the session that holds the merge-steward lane (actor merge-manager, skill merge-manager-watcher): elected, appointed, or holding it for its own PRs only. Each wake reads the open PRs, the runner queue, main’s verdict and the PR owners live, acknowledges merge requests within the heartbeat, and routes to the train, a direct merge, runner relief, a saturation meta-merge, a stalled-agent takeover, or a fixer for a red main in any harness repository (owner, 2026-11-10: “That should be a part of merge manager (dispatch an agent to fix them)”, “Add to process”). Every merge waits for the owner’s own OK, given in the merge manager’s session as one card per batch (owner ruling, 2026-11-07, card Approvals, B). How a sibling finds or elects the merge manager and sends it a request is Process_MergeRequest.

How it connects

  • Called by: Merge request: find or elect the merge manager
  • Calls: A merge train, Saturation meta-merge: land the ready PRs when the runners are full, Stalled-agent triage: collect handovers, consolidate themes, recommend, re-route

Merge stewardmerge-stewardThe merge manager: the one session holding the merge-steward lane, by the owner’s word, by election, or for its own PRs only. Each wake it reads the open PRs, the runner queue, main’s verdict and who owns each PR, acknowledges requests within the heartbeat, then routes to the process the queue needs or stays idle. Dispatch a fixer
Task_DispatchFixer		Merge stewardmerge-manager-watcherOne fixer agent per cause, never one per repository. Give it the failing run, the cause and the repository: pins out of step go to the next re-pin train on the index; the layer’s own bug to a fix PR in that layer; a lower layer’s bug to a fix PR in the lower layer, then a re-pin. It opens a draft fix PR, linked from the main-red issue. The fix is a non-content P0 PR and follows the normal merge rules: the six-line request, the owner’s batch card, full-tier CI green as judged. Close the loop when the next main run is green and the main-red issue closes. Never silence the failure, and never skip, disable or quarantine a gate or a test.
