Description

The diff renderers a reviewer chooses between on the review page.

Why a registry

No single diff suits every block kind: a word diff of a table's Markdown is unreadable, and a side-by-side view of a one-word edit hides the word. So each renderer is declared here as DATA (what it needs, which block kinds it defaults for), and the page offers every renderer that can run on a block, with a default chosen by that block's kind.

It lives in the harness because it describes RENDERING TOOLS, and the page that uses it (gen-review-page.ts) is harness code too.

What a renderer NEEDS decides whether it is offered

  • text: the block's prose on the sides it has (changeset-text.json).
  • pages: a URL for each side (the preview, and main from staging.json).
  • screenshots: a picture of the block on each side, from the folio-block-screenshots Tool's visual-diff.json.

A renderer whose input is missing for a block is still LISTED, disabled, with the reason, so it does not read as nonexistent.

Shipped

Word diff, inline rendered diff, side-by-side and the visual diff. A DAK structural diff is NOT listed: a registry entry with nothing behind it is a declared-but-absent Tool.
