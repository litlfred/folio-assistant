Description

A confirmation the owner has given in advance, scoped and dated.

Skill: [confirmation-waiver](../skills/conduct/conduct-core/confirmation-waiver.md). A person may waive confirmation rights for a session or a process run; the waiver is context-dependent and kept with memory.

A kind of its own, not a memory label

A waiver is context like memory — a running process READS it and no step writes it — so it is declared over the same directory. It is a separate kind because MemoryNodeSchema carries no status by design, and a waiver's entire content is that it expires.

Every field is required

A waiver moves a decision from the agent to the person; each field closes off a way to fake that move:

  • no grantedBy → an agent's own decision wearing a hat;
  • no quote → the agent's paraphrase, which can widen a scope silently;
  • no gate → a blanket permission nobody can audit;
  • no scope → a grant that outlives the situation that justified it;
  • no expires → indistinguishable from one nobody remembered to withdraw.

So the schema has no .optional() anywhere, and a malformed waiver is not a lenient waiver — it is no waiver, and the gate it named still stands.
