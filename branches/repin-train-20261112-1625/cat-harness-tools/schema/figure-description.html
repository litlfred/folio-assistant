Description

What a person or agent SAYS a drawn figure shows — the judgement half of the vector arm.

A third file

Measurement and judgement are kept apart:

| | measurement, machine-derived | judgement, someone looked | |---|---|---| | raster | <entry>/images.json | <library>/image-verdicts.json | | vector | <entry>/vector-labels.json | <library>/figure-descriptions.json |

A narrative in vector-labels.json would mix measurement and opinion, and would be overwritten on the next extraction. It is not images.json either: a drawn figure places no image object, so there is no entry to hang a narrative on.

basis is required

A description from labels alone can name every part correctly and still get the RELATION wrong (labels line up as a table while the drawn arrows cross), and miss glyphs that carry no text. So a labels-only description is safe as an INVENTORY and unsafe as an ACCOUNT, and FigureDescriptionSchema.basis records which one the reader holds.

Only a human confirms

The state machine is NarrativeSchema's: confirmed_by.kind must be "human", and an agent cannot confirm its own draft.
