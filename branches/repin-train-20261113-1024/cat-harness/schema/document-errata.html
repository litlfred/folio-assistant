Description

Errata of a library document: places where the SOURCE's own text is wrong, recorded beside the L1 entry without changing that text.

Owner, 2026-11-11 (who-iris, card Q-ODD-1 = A, and "add to L1 doc schema errata"). Reading every derived block of the IRIS pilot turned up errors that are in the publications themselves, not in the extraction: a workshop report whose title says June 2006 and whose introduction says June 2005 (10665/205022), a Spanish edition that announces "nueve recomendaciones" where the English and French list ten (10665/354399), a confidence interval "48.7 to 48.7" (10665/381036). The blocks are the source's own words (provenance: "ingested") and stay exactly as printed. An erratum says what is wrong, where, and what the evidence is.

A sidecar, like the block summaries

library/<slug>/errata.json, one file per entry, beside summaries.json (../content/block-summary.ts). It is AUTHORED, never written by an ingest rung, so a re-ingest keeps it. Each erratum's explanation is a NarrativeSlotSchema: an agent's note is a draft that names its model, a person confirms or rejects it with bun run cat narratives, and it can be given in several languages.

What an erratum is NOT

  • An extraction defect (a garbled OCR line, a block cut in the wrong place). Those are fixed by re-deriving the entry, not recorded here.
  • A correction of the text. reading is the reading the evidence supports, offered beside the source; nothing replaces the printed words.
  • A place for content the owner has not asked to be flagged (personal data in a participant list, a "do not distribute" notice). Those are decisions about the document, not errors in it.
