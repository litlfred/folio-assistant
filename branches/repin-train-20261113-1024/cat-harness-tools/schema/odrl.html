Description

W3C ODRL 2.2 policies: what an Actor may do, scoped by Process, Task and Role.

Policies are their own graph typology; an unauthenticated reader may visualize and render only. The design is docs/proposals/odrl-prov-actor-model.md.

The subset

A Policy (Set, Offer, Agreement) holding permission and prohibition rules (plus optional duty obligations), each naming an assignee, an action, an optional target, optional constraints and optional duty rules. Refinements and party collections have no reader yet, so they are not accepted. A key outside the subset is refused rather than dropped (.strict()): a permission rule must never silently mean less than it says.

Terms are written as compact IRIs, as ODRL's own JSON-LD context writes them: odrl:display, cat-harness:perform-task, and a bare action id for one the folio profile declares (content-authoring).

Actions inherit through includedIn

The folio profile is skills/permissions/permissions.json: every action says which broader actions it is includedIn, ending at ODRL's own common vocabulary. A permission to a broader action permits every action included in it. The graph is walked with a visited set, so it need not be a tree or acyclic, and a cycle cannot hang a decision.
