Description

An agent's summary of a library block, kept BESIDE the block as a QA sidecar, drained as part of general document ingestion.

A sidecar, not a field on the block

A prose block is the source's own text (provenance: "ingested", regenerated by re-ingestion; library is holds: "derived"). A summary is somebody's account of it, so it lives in library/<slug>/summaries.json, one file per entry — the placement images.json uses for image descriptions.

One vocabulary for the state and the author

Each summary IS a NarrativeSchema: draft, confirmed, rejected, with drafted_by an AttributionSchema that must name its model when the author is an agent, and confirmed_by that must be a human. bun run cat narratives reviews these drafts exactly as it reviews image descriptions.

source_hash — a changed source reads as STALE

As with the kg-qa sidecars (schemas/sdlc/kg-qa.ts), the record carries the hash of what it judged. The hash is of proseBody — the text the summariser was shown — so a front-matter change alone does not mark a summary stale, and a change to one word does.

Absence is the "not yet summarised" state

A record whose narrative is not-authored is refused.
