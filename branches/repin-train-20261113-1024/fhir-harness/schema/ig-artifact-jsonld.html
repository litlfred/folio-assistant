Description

One FHIR IG artefact as a JSON-LD node — the asset an artefact's thin page renders (kg-viewer rule 3: one IRI per asset, its page a separate resource that loads it).

Borrowed vocabularies, nothing minted

Owner, 2026-10-11 (option A): "tiny html w/ dynamic load from json(ld) KG", with the JSON-LD free of anything WHO's (fhir-harness/AGENTS.md).

| term | what it says | |---|---| | @type fhir:<resourceType> | the FHIR RDF class (http://hl7.org/fhir/), as FHIR's own Turtle types a resource | | dcterms:identifier | the index key, <resourceType>/<id> | | schema:name, dcterms:title, dcterms:description, schema:version | the resource's own name, title, description, version | | dcterms:type | the Publisher's artifacts.html grouping | | schema:sameAs | the FHIR canonical URL: the artefact's identity, never where its bytes are | | schema:encoding | each representation as a schema:MediaObject (schema:contentUrl, schema:encodingFormat, dcterms:source): first the reduced copy the site serves at its root as <Type>-<id>.json (local), then the full copy in the AST cache by raw URL (mirror), then the IG's own published file (upstream) | | schema:creativeWorkStatus | materialized or referenced, the index's own two states | | prov:wasGeneratedBy | for a compiled copy, the toolchain (schema:instrument) and the revision it built (prov:used) | | dcterms:isPartOf | the IG, by package id, version and canonical base | | dcterms:conformsTo | the resource's own meta.profile, each profile by its canonical URL | | dcterms:subject | the resource's own code concept, each coding a schema:DefinedTerm (schema:termCode, its display as schema:name, its system as schema:inDefinedTermSet), and the concept's text, when it has one, a schema:DefinedTerm with only a schema:name |

The last two are what an INSTANCE (an artefact with no canonical URL) states about itself, and are written for instances only. A configuration instance (a Basic that is a page, a role or a task) has no title or description, and its list row was empty until it showed them (owner, 2026-10-12). Both are copied from the resource, never looked up: a coding with no display has no schema:name.

FHIR RDF is used for the CLASS only. Its property shape (fhir:url [ fhir:v "…" ]) describes a whole resource, which this node deliberately is not: the resource's bytes are one of its schema:encodings, and the page fetches them. A node that restated half a resource in FHIR RDF would be a second, partial copy that could disagree with the first.

The node carries NO link to its renderings: the page points at the node, never the other way round (thin-page.ts).

$schema names the family for check:kind-validators. It is not a term of the context, so a JSON-LD processor drops it on expansion and it adds no triple.
