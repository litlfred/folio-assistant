Description

The codes a PUBLISHED IG carries at ONE pinned version.

check:term-mapping's fhir half asserts "this code is in the published base IG at version X", not "this code is in the collection this organisation curates today"; only the first is reproducible from the repository. So the codes are snapshotted rather than fetched (which also keeps the gate off the network).

It is DERIVED, and the version is not its own to state

PinnedTerminologySchema.pin names the external-schema record the version comes from, and the pin-ig-terminology Tool refuses to write unless the clone's own sushi-config.yaml declares that version, so a snapshot cannot be labelled with another version.

It lives beside the record it pins

In external-schemas/. loadSpecs reads each file's $schema and skips a different declared kind, while still parsing strictly anything that claims to be a record or declares nothing.
