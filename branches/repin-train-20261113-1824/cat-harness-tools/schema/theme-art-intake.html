Description

Theme art arriving as three files — accepted, or refused with a reason.

Part of document ingestion, not a second process: theme art is an arrival with a different payload, so this adds a check keyed on the payload to the same completeness gate.

The constraints

| constraint | why | |---|---| | THEME_ART_LAYOUTS complete | resolveThemeBackdrop refuses an incomplete backdrop wholesale, so the theme renders with no art at all. | | distinct content | byte-identical files for different roles are refused. | | orientation per layout | a portrait crop is not a landscape crop scaled down; the quiet area a sticky's text sits in moves. | | dimensions measured | a retyped width makes images[].width a false declaration. | | weight and format | large PNGs are refused where webp siblings are expected. | | a declared destination | art outside a declared directory is seen by no gate (check-declared-assets walks declared→disk). |

The contract: success, or a NAMED failure

Every ThemeArtFailure carries the layout it is about, what was found, and what to do about it. All failures are collected rather than thrown one at a time, because art arrives as a batch.

Dimensions are READ, never accepted

measureImage parses the file header. This module takes bytes and emits the declaration; the caller is never asked for a width.
