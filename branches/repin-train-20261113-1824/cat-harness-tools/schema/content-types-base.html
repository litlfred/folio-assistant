Description

The content types this layer owns, registered at load time.

Separate from content-type.ts as folio-graph-typology.ts is separate from cat-harness.ts: the registry is a mechanism and the entries are a layer's opinion, declared only by the layer that owns them.

Two are registered here — harness and folio.

They are NOT the same type

harness says this is a layer: a name, a stub, the directories it holds. folio says this authors folio content: it carries contentType, and folio_init writes it.

                       declared   contentType
  cat-harness/            yes         NO
  the repository root     yes         yes

Both are stated by one <name>.config.json, so the discriminator is its CONTENT: folioMarkerFilename returns the file only when it declares a contentType. A bare {"name":"x"} is an instance and not a folio. This is what isFolio in folio-intent.dmn means.

dak, sushi and ig are NOT here

The DAK layer depends on core, so core recognising a DAK would be core importing downstream (check:partition:edges refuses it). dak and sushi live in module:schemas/dak-content-type, registered by the layer that owns the model. ig is registered nowhere: nothing declares an IG layer, so there is no marker file to recognise.
