Description

The metamodel a model actually uses, derived from the model and checked against ArchiMate's relationship table. Never drawn by hand.

Owner, 2026-10-31: "i dont really like native UML, rather derived", then "make mechanical tools as parts of skills/processes". A reference architecture's metamodel (which element types it uses, and which relationships it draws between them) used to be a hand-drawn view, with placeholder elements named after the types. Here it is computed:

  • every element type in the model, with how many elements it has;
  • every pattern (source type, relationship type, target type), with how many relationships follow it and which ones;
  • for each pattern, whether ArchiMate allows it (Appendix B, as Archi holds it: archimate-relationships.json, written by scripts/import-archi-relationships.ts);
  • the placeholder elements: an element whose name is its own type's name ("Goal", "Application Component (MS)"). They are how a metamodel gets drawn by hand, so they and their relationships are listed, and kept out of the patterns, which describe the architecture itself.

The same result is written as JSON, as Graphviz DOT (laid out to SVG by archimate-pages), and as a Mermaid class diagram.
