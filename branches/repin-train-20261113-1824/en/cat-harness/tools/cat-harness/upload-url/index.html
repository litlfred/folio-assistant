Where to drop a file — the queue’s upload URL

Compose the forge URL a person can drop a file at, from the layer’s own declaration: the uploads graph’s directory, resolved against the ROOT its scope names, expressed relative to the repository, and appended to the origin remote as GitHub’s /upload/<branch>/<path>. Every failure is NAMED and no URL is guessed — no declaration, no declared uploads graph, a declared queue absent from disk, no origin remote, and a non-github.com remote each return a reason and a remedy instead. The declared path is relative to the LAYER and a forge URL needs it relative to the REPOSITORY, so pasting the declared path can mint a 404.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

upload-routes

How a file actually REACHES uploads/ — the two mechanisms that write bytes into a declared queue, the persona that performs one of them on somebody’s behalf, and what each writer owes that the route does not do for them. The step before intake and after acquisition.

Source: cat-harness/library/skills/library-core/upload-routes.md.

Also satisfied by: subgraph-readmes.

The skill declares no I/O contract (schemas/skills/upload-routes/{input,output}.schema.json).

content-acquisition

Getting a resource INTO the graph in the first place — accepting one offered unprompted, or asking for one and then asking for it to be uploaded. The channels are plural and open: uploads/ is one, the conversation is another. Runs before document ingestion, which begins only once a file has landed.

Source: cat-harness/library/skills/library-core/content-acquisition.md.

The skill declares no I/O contract (schemas/skills/content-acquisition/{input,output}.schema.json).

when to choose it
whenYou are about to tell somebody where to put a file, in any channel. Reach for it every time, not only when unsure: a hand-written path breaks silently when a directory moves. It also answers “which queue” when a checkout declares more than one (one per layer): the answer is whichever layer root you pass, never a literal.
limitsIt answers WHERE, and nothing else. It does not upload, does not check whether the person has write access, and cannot tell you which of several declared queues should own a given file — that is undecided and upload-routes says so rather than picking. The /upload/<branch>/<path> form is GitHub’s, so another forge gets a named refusal rather than a guess. And the URL it hands back opens the route with the FEWEST guarantees: the web form has no working tree, so no pre-commit hook and no generator run happen on it, and everything upload-routes lists has to be discharged afterwards from a checkout.
costOne read of the declaration and one of the git remote; no network at run time and nothing installed.
