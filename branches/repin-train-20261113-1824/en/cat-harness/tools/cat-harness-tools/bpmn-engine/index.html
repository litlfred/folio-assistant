BPMN workflow engine

Run a declared BPMN process as an instance: workflow_start opens one for a subject, workflow_next reports what is enabled, workflow_complete records a step or answers a decision (a DMN-computed one from facts) and REFUSES a step that is not enabled. State is committed under the work plan, so which edge was taken is a record, not a memory.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

process-state

Track where you are inside a running process — which task, in which swimlane, under which role — and recover deliberately when you find yourself outside it. Read before completing a workflow step, and whenever something unexpected interrupts one. Covers what to do about notes and stickies you re-anchored while off-process, which leave no trace in the artefact.

Source: cat-harness/skills/process/workflow/process-state.md.

Also satisfied by: workflow-complete, workflow-gate, workflow-list, workflow-next, workflow-start.

The skill declares no I/O contract (schemas/skills/process-state/{input,output}.schema.json).

How it is deployed and reached

  • MCP. Served as workflow_* by sage (cat-harness-tools/scripts/sage-mcp.sh), google-drive (cat-harness-tools/scripts/google-drive-mcp.sh), folio-assistant (bun run cat-harness-tools/src/index.ts --stdio --repo .), the servers .mcp.json declares.
  • In process. src/tools/workflow.ts, registered by registerWorkflowTools — loaded by the harness directly, with no server.
  • GitHub Actions. No workflow in this checkout runs its command.

when to choose it
whenWork follows a declared process and its order must be enforced and recorded: a step done out of order should be refused, not just discouraged.
limitsReached over MCP; an agent without the server can walk the generated checklist (bpmn-checklist) by hand, but nothing then refuses a wrong turn.
costOne diagram load per call; state is a small committed file.
