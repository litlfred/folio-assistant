Description

The MERGE QUEUE — what the merge steward DECIDED about each open pull request, and nothing GitHub already knows.

The core rule: decisions are stored, facts are read live

A queue entry records a decision. It never records a fact GitHub owns.

| stored here (a decision) | read live, never stored (GitHub's fact) | |---|---| | priority class, rank or override position | CI status of the head | | the reason, who decided, when | mergeability (clean, dirty, unstable) | | a hold, with its expiry | labels (ready-to-merge, merge-main) | | the train it was assigned to | the head SHA | | an ejection from a train, with its evidence link | the PR's own CI verdict, and whether CI saw the head | | links to beans and epics | the changed-file list, and what it touches |

A stored GitHub fact goes stale the moment anybody pushes. The steward computes the right-hand column at decision time (scripts/merge-queue.ts deriveFacts), and the queue tile joins it in the reader's browser at view time; neither writes it back.

MergeQueueEntrySchema enforces it structurally: the object is strict, and the keys a well-meaning writer would reach for first (FORBIDDEN_FACT_KEYS) are refused by name with this rule as the message.

Where a fact MAY be written down: as a dated evidence snapshot on a FINISHED train run — a workflow instance of Process_MergeTrain under beans/workflows/ — recording what the steward saw when it acted (TrainMemberEvidenceSchema).

Where the fields come from

  • ejection — eject a failing member and re-run the rest (SQ19 §2.2: a failed batch is split and retried without the faulty change; §3.2: a refused change returns to its author with the reason). evidenceUrl is that reason's evidence.
  • MemberFactsSchema.authoredPaths / .touchesShared — predict which PRs conflict, cheap form (SQ19 §5.2: decide independence from the build graph); generated paths are excluded, or every pair predicts as conflicting. COMPUTED live from the PR's file list, never stored.
  • MemberFactsSchema.ownCi / .headShaMatchesCi — attribute a red train from each member's own CI before bisecting. GitHub facts: read live, or snapshotted on a finished run only.

SQ19 = Ananthanarayanan et al., Keeping Master Green at Scale, EuroSys '19.

What it is not

Not GitHub's merge queue — that is unavailable on a personal-account repository. Not the order itself: the order is COMPUTED, by processes/decisions/merge-priority.dmn over live facts, and an entry records the outcome the steward acted on, or an owner override with its reason. Not the merge SOP (merge-manager) nor the gates: those say how a merge is done and what it must prove; this says which PR goes next and why.
