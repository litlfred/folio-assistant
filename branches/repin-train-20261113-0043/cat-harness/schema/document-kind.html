Description

A document KIND — a named structure of sections that a document authored with a harness follows.

Not a content profile

A profile (CONTENT_PROFILES in block-kinds.ts) says which BLOCK KINDS a folio may contain, and is a compile-time union in core. A document kind says what a publication's STRUCTURE is: which sections it has, which are required, and what each is derived from. Only a document kind can be contributed by a harness as DATA, without core naming it.

Core knows that document kinds exist; it never knows which. A harness declares its kinds in a document-kinds directory of its <instance>.json, one JSON file per kind.

Two rules the schema enforces

  • A structure is never invented. Every kind names its sources, and every section may name its own — a kind whose sections come from several publications says which section came from which.
  • "Computed from" is a claim to check. A section's computedFrom names DECLARED graph ids (e.g. library), so a reader can check the graph exists. modelledBy names what kind of thing the section holds, in a pinned external model.
