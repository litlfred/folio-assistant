Description

WHERE A DECLARED SUBGRAPH GETS ITS CONTENT — one concept, several kinds.

A declared subgraph says where it gets its content, and the layer config may override that. Directory, branch and remote subgraphs are one thing differing in SOURCE, a discriminated union on kind:

| kind | content comes from | the entry's path is | |---|---|---| | directory (the default) | the checkout, at path | the content itself | | branch | a declared repository branch, keyed by commit or tip | where a mount of it lands | | family | a family of branches, one per key | where a mount of ONE member lands | | remote | another repository's tree, at a pinned 40-character commit | where the remote mount lands | | hydrated | another layer's published index.hydrated.jsonld for one subgraph, at a pinned commit — metadata, no files | where that one file lands |

A new kind (e.g. a graph database) is a new MEMBER of the union, which every switch on kind is then forced by the compiler to answer — never a reinterpretation of an existing field.

The legacy storage field

storage: { branch, keyedBy } is EXACTLY source: { kind: "branch", branch, keyedBy }, kept as the LEGACY spelling: the resolver reads it and reports declaredIn: "storage", the presence checks ask contentIsOffCheckout (which honours both), and an entry carrying both is refused. qa-store.ts and branch-store.ts still read storage directly. The DECLARATION is the only source of a branch's name; a branch no directory declares is a health finding (state:drift), not a resolver failure.

Overridable by the layer config, matched on id

<instance>.config.json → subgraphSources: { "<dir-id>": <source> }. The declaration says what the subgraph IS; the config says how THIS instantiation is set up (an IG folio may mount fsh-guts from a branch while a fresh clone reads it from the checkout). Matched on the entry's id, never its path.

One resolver

resolveSubgraphSource is pure: entry + optional override in, resolved source out. Every consumer — the KG export's Subgraph node, a publisher's container node, branch-store mount/push — asks it, so the precedence (config, then source, then legacy storage, then the directory default) is stated once.
