Description

A GRAPH TYPOLOGY as a node of the knowledge graph, declared by the harness that owns it — no central registry; a typologies/ graph of one node per kind, the way tools/ holds Tool definitions as nodes.

A harness declares a directory of graph typology typologies; each *.json in it is one GraphTypologyNodeSchema. The registry a reader sees is the base layer's own kinds plus every declared node across the layers, loaded lazily by graph-typology-registry.ts on first use, and a name declared by two files is refused, naming both.

The fields are GraphTypologyDef's, one for one, plus kind (the file says what it declares) and avatar (so the kind's mark travels with the kind). A compile-time check below keeps the two in step: a field added to GraphTypologyDef and not here fails to typecheck.

A LEAF: Zod only, so the registry can import it without a cycle.
