version-bump.ts — instance-versioning.md §4: what a version MEANS, and what makes it go up.

A version governs the layer's declared surface: graph typologies, skill ids, tool ids, block kinds, asset roles, declared directories — everything kg-export walks.

| bump | when | |---|---| | major | a consumer must change something — a subject removed or renamed | | minor | something added that a consumer may use | | patch | everything else, prose included |

A diff, not a commit message

A commit message is a claim about a change; an exported-graph diff IS the change. A feat: prefix on a commit that removed a skill id would yield a minor bump under release-please's heuristic; the diff cannot.

Measuring the bump over history must walk the mainline (--first-parent); without it, consecutive entries are not parent→child and the surface appears to churn.

A rename reads as major

The old id is removed and a new one added. That is conservative and honest (a consumer resolving the old id does break), but a major does not imply capability was withdrawn. SurfaceDiff carries added and removed separately so a caller can see a rename for what it is.
