Description

A PUBLISHED SURVEY of a commit window — so the next session reads it instead of re-deriving it.

Several sessions re-orienting against the same window of new commits each spend the time reading the same thing, and nothing else shows it: a survey is not a claimable bean, and nothing is pushed while surveying.

The two edge commits

A published survey is only safe to reuse if staleness is decidable, so it records the window's own endpoints. A later session computes to..origin/main — the delta it is NOT covered for — and surveys only that.

So SessionSurveySchema makes from and to REQUIRED, as full 40-character object names rather than refs: origin/main recorded as the upper edge names a different commit tomorrow. A survey that cannot be checked for staleness is worse than no survey, because siblings trust it INSTEAD of looking.

What it is not

Not a claim on the window and not a division of labour (which would need a live channel between sessions). It is an artefact: one session writes what it found, and a later one decides for itself whether that still covers its question.
