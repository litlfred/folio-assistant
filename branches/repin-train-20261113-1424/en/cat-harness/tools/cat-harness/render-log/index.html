Record what the publish branch served

Append one entry to the render log on the publish branch: what was published or taken down, when, from which commit, and — for a removal or a retention — WHY. The log is the only place a preview that vanished leaves a trace.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

render-logging

Log every render to the publish branch — what was published, removed, restored or deliberately retained — to an append-only log that lives beside what it describes. Use when adding or removing anything on gh-pages, when asking “what happened to this preview”, or before writing a workflow step that deletes a published artefact.

Source: cat-harness/skills/ui/ui-core/render-logging.md.

The skill declares no I/O contract (schemas/skills/render-logging/{input,output}.schema.json).

installnone
runtimebun, jq

when to choose it
whenWhenever something is published to or removed from the publish branch — including a removal that was refused. Called from feature-staging.yml at four points; staging-render-log.bpmn is the process.
limitsIt writes into a directory and does not push, so a caller that forgets to commit the log has written nothing durable. It cannot edit or delete an entry, by design. --summary / --reason / --detail are REFUSED as flags at exit 2 rather than ignored: they go on stdin, and a caller still passing them is told instead of silently logging an entry with no summary.
costOne appended line. No network.
