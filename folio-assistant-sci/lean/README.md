# Lean directories

A directory of graph typology **`lean`** ([`typologies/lean.json`](../typologies/lean.json))
holds Lean 4 sources. In a folio that is its formalisation: Lake packages
(each a `lakefile.toml` or `lakefile.lean` with its modules beneath it), the
modules, and the declarations a block's `lean.ref` points at. In this harness
it is the templates its Lean tooling fills — this directory holds one,
`formal-edges.lean.tmpl`, which `pipeline/formal-edges.ts` writes into
a folio's own `.lake/` and runs there. It is a `.tmpl`, not a `.lean`, because
the platform tracks no Lean content
(`scripts/tests/lean-decl-starts-are-shared.test.ts`).

## What renders it

**doc-gen4**, wrapped in the harness navbar and rail. Two Tools, in order,
under the process [`lean-docs-publish`](../processes/content/lean-docs-publish.bpmn)
and the skill [`lean-html-docs`](../skills/lean/lean-html-docs.md):

| Tool | script | does |
|---|---|---|
| `lean-html-docs` | [`lean-docs-build.sh`](../adapters/paper/lean/lean-docs-build.sh) | `lake -R -Kenv=dev build <Lib>:docs`, refusing a shared or untraced `.lake/` |
| `lean-render-publish` | [`lean-render.ts`](../adapters/paper/lean/lean-render.ts) | stages the render under the folio's site and runs `rail-standalone-pages.ts --foreign-site` |

The render is built at publish and never committed — it is derived, gigabytes
for a Mathlib package, and its input (the olean cache) lives on a branch. So a
folio declares it as a `coverage.visualiser` with a `writer` naming the two
scripts; the skill carries the exact declaration.

This directory has no render of its own: it holds a template, not a Lake
package, so its declaration waives the visualiser and says why.

## Declaring one in a folio

```json
{
  "id": "lean",
  "path": "folio/quantum-observable-universe/lean/",
  "graphTypologies": ["lean"],
  "coverage": {
    "process": "lean-docs-publish",
    "visualiser": [{
      "ref": "_site/lean/index.html",
      "title": "Lean",
      "writer": [
        "folio-assistant/folio-assistant-sci/adapters/paper/lean/lean-docs-build.sh",
        "folio-assistant/folio-assistant-sci/adapters/paper/lean/lean-render.ts"
      ]
    }]
  }
}
```

The folio's dependency on folio-assistant-sci must be pinned at or after the
commit that adds `typologies/lean.json`: a declaration naming an unknown graph
typology fails to parse as a whole.

# sci-lean

The Lean templates this harness's tooling fills: today `formal-edges.lean.tmpl`, which pipeline/formal-edges.ts writes into a folio's own `.lake/` and elaborates there. Declared with graph typology `lean`, the kind this instance owns for Lean sources (typologies/lean.json). The Tools (`lean-html-docs`, `lean-render-publish`), the process (`lean-docs-publish`) and the skill (`lean-html-docs`) are what a FOLIO's `lean` directory gets: its doc-gen4 render, published under the folio's site in the harness rail. `.tmpl`, never `.lean`: the platform tracks no Lean content, and lean-decl-starts-are-shared.test.ts holds it to that.

Part of [folio-assistant-sci](../README.md) 0.1.0, declared as `sci-lean`, holding `lean`.
