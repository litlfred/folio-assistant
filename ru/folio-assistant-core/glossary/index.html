Авторские термины

Bootstrap terms

терминальтернативные обозначенияопределение
Узел—Файл или часть файла, адресуемая фрагментом IRI, названные с помощью IRI.
Ссылка—Указание одним Узлом на другой Узел по его IRI.
Схема узла—Схема, по которой можно проверить Узел: JSON Schema или опубликованная внешняя схема, например схема BPMN.
Вид узла—Имя, сопоставленное со Схемой узла.
Подвид—Вид узла, Схема узла которого требует всего, что требует схема другого Вида узла, так что любой Узел, удовлетворяющий ей, удовлетворяет и другой.
Экземпляр узла—Узел, указывающий свой Вид узла в $schema или во вводном блоке и удовлетворяющий Схеме узла этого вида.
Вид графа—Именованный набор Видов узлов.
Декларация—Документ JSON, <name>.json, задающий имя и перечисляющий записи каталогов и записи файлов.
Расширение—Поле Декларации или одной из её записей, которое здесь не определено. Читатель, не распознающий поле, пропускает его, а остальная Декларация сохраняет своё значение.
Подграф—Запись каталога в Декларации: id, каталог и Виды графов, к которым относятся виды его Экземпляров узла.
Ресурс—Запись файла в Декларации: один файл о самом репозитории, поле role которого говорит, для чего он нужен.
Граф знаний—Схемы узлов, Экземпляры узлов и Ресурсы, перечисленные в одной Декларации, на одну версию репозитория. При публикации в JSON-LD утверждения Экземпляров узла каждого Подграфа образуют один именованный граф.
Зависимость—Запись needs Декларации, называющая другой Граф знаний. Ссылки могут вести от Экземпляров узла этого графа к названному, но никогда обратно.
Содержимое—Экземпляры узла, описывающие предмет Графа знаний, — записи, документы, каталоги и их термины, — а не то, как с ним работать.
Задача—Единица работы, описанная тем, что ей нужно для начала, и тем, что она производит.
Актор—Человек, агент или программа, способные выполнять Задачи.
Навык—A Node Instance stating a responsibility an Actor carries out to complete a Task: as natural-language instructions to follow, as a contract to be tested against, or both. (не переведено)
Роль—Экземпляр узла, называющий роль, которую Актор принимает на себя для выполнения Задач, и перечисляющий Навыки, необходимые для этой роли.
Узел процесса—Узел потока BPMN: действие (задача или вызывающее действие), шлюз или событие.
Поток последовательности—Направленная связь в процессе BPMN от одного Узла процесса к следующему.
Процесс—Экземпляр узла, содержащий процесс BPMN, который координирует Задачи: его Узлы процесса, соединённые Потоками последовательности, расположены на дорожках, каждая из которых называет Роль.
Обвязка—Граф знаний, Подграфы которого содержат Навыки, Роли или Процессы: то, чем Актор пользуется для работы с Графом знаний, включая сам этот граф.

Folio Assistant platform terms (cat-harness)

терминальтернативные обозначенияопределение
связанная обвязка—Обвязка, которую данная знает по имени, сайту и репозиторию и никогда не загружает, не собирает и не копирует. Четвёртое отношение наряду с «зависит» (needs), «ссылается» (remoteGraphs) и «использует» (dependencies).
политика—Какой Актор может выполнять какое действие и где — в виде правил разрешения и запрета W3C ODRL 2.2, ограниченных Процессом, Задачей и Ролью.
разрешение—Одно правило ODRL, разрешающее получателю действие, при необходимости над объектом и в определённых ограничениях. Разрешение на более широкое действие разрешает и все входящие в него действия.
выполнение задачи—Одно выполнение задачи BPMN Актором в Роли в рамках политики, записанное как действие W3C PROV-O, планом которого является задача.
актор—Конкретный участник — человек, агент или механизм, — существующий во всех процессах и принимающий на себя роли. Какая учётная запись какому актору соответствует, известно хранилищу данных.
роль—Дорожка: образ, который актор принимает на себя из-за дорожки, в которой действует, и который несёт навыки, нужные действиям этой дорожки.
user story (не переведено)—What a reader acting in a Role is trying to do, told as that role: as a , I want , so that . The story points at its role; the role names no story. _(не переведено)_
test run (не переведено)—One measurement of a Skill: which skill it tests, the cases it exercised, and a hash of the data and a hash of the process that produced the result, so a third party can redo it. Its cases are checked against the skill’s input and output contracts. (не переведено)
voice (не переведено)—A named set of writing rules for prose, active in the roles and processes it names. The voice points at the role it is written for; the role names no voice. (не переведено)
external schema (не переведено)—A record of a specification the platform depends on but does not hold: which authority publishes it, which version is conformed to, and the operative terms used from it. (не переведено)
KG QA report (не переведено)—A committed QA sidecar recording, for one knowledge-graph subject such as a process, role or skill, which of its references fail to resolve under each audit criterion. (не переведено)
todo (не переведено)—One person’s outstanding work, as a content node the folio owns, tagged with the roles, processes and tasks it concerns. Not the agent work plan, which is beans. (не переведено)
bean (не переведено)—One item of the agent work plan, held by the beans CLI in the committed beans/ store, with a status, a parent and the beans it blocks. (не переведено)
JSON Schema (не переведено)—A JSON document that describes the shape of other JSON documents. In the platform, a node schema and a skill’s input and output contracts are each a JSON Schema file. (не переведено)
