# uploads

The incoming queue of the document-ingestion pipeline for THIS checkout — raw files as dropped, before ingestion. Distinct from `cat-harness/uploads/`, which is the harness layer's own queue: the two are different instances' directories that happen to share an id, not one directory declared twice. NOT L1 and NOT greppable as corpus; a source sitting here reads as absent to every consumer while the file is on disk.

Part of [Folio Assistant](../README.md) 0.1.0, declared as `uploads`, holding `uploads`.

## Governing process — Document ingestion — uploads/ to the L1 source knowledge graph

This directory declares `document-ingestion` as the process that governs it. The link is **declared** in `coverage.process`, not inferred from the diagram's wording.

![Document ingestion — uploads/ to the L1 source knowledge graph](../cat-harness/docs/assets/img/workflows/document-ingestion.svg)

The diagram is the source of truth: [`document-ingestion.bpmn`](../cat-harness/processes/document-ingestion.bpmn). The SVG is generated by `bun run render:bpmn` — never hand-edited.

It begins at the start **event** “A contributor has a file for the folio”. An event is something that has already happened, so whatever brings the process to that point is **outside** this diagram.

It is a high-level process: 5 of its steps are **call activities**, each handing off to its own diagram.

## What the process does not cover — how a file gets here

Authored, outside the `kg:subgraph` markers above: the platform owns the
markers, the folio owns the file.

`document-ingestion` opens on an **event**, not a task — *"A file lands in
`uploads/`"* — so the diagram begins **after** arrival and models nothing about
**how** the file arrived. At least three routes reach this directory today: a
git commit on a branch, a file handed to an agent in a chat session, and the
GitHub web UI's *Add files via upload*. **None of the three is governed by any
process or skill.** That is a real gap rather than a hypothetical one: a web-UI
commit on 2026-09-29 (`c8349950fa5`, straight to `main`, no PR) added three PDFs
here and turned the blocking `readme:subgraphs:check` red, because a commit made
in the web UI runs no generator. The gap is recorded and awaits the owner; no
procedure for the three routes is stated here, because none has been decided,
and a page asserting a procedure nothing governs is worse than a page admitting
a gap.
