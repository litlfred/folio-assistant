Folio Assistant Core

folio-assistant

Un cadre de compétences d’agent indépendant du contenu pour la rédaction de contenus rigoureux avec un grand modèle de langage — articles scientifiques et livres, Lignes directrices SMART de l’OMS, et Guides d’implémentation FHIR — appuyé par un serveur MCP, un contrôle d’accès basé sur les rôles, et un modèle d’objets de contenu typé.

Quatre choses, dans l’ordre

1. Le plan de travail est l’endroit où vous dites ce que vous faites. Pas un message de discussion, pas un commentaire — des beans, un dépôt versionné que toute session ou tout agent peut lire. Réservez avant de travailler, pour qu’une session voisine ne prenne pas le même élément ; un bean qui s’avère inutile est marqué scrapped, avec ses raisons, jamais supprimé.

cat-harness-tools/scripts/install-beans.sh && export PATH="$HOME/.local/bin:$PATH"
beans list                          # ce qui est ouvert
beans create "<title>"              # …après avoir vérifié que le titre n'existe pas
beans <id> --status in-progress     # le réserver, visiblement

2. Créez votre premier folio. Ce dépôt est la plateforme ; votre contenu vit dans le sien. Une seule commande le prépare — les manifestes, la déclaration, les fichiers d’agent et le lien vers ici :

bun run cat init-folio --help

Ensuite, Démarrer accompagne le premier bloc à travers la validation, le rendu et la relecture.

3. Sachez quel genre de chose vous écrivez. Un document est de la prose structurée ; un article (paper) est cela, plus les types de blocs dont l’assertion est une affirmation formelle, appuyée par Lean et composée avec LaTeX. Ce choix décide quels blocs sont permis et quels contrôles s’exécutent : Types de contenu.

4. La documentation que vous ne lirez jamais. Toute la documentation — les guides de rédaction, l’architecture, le flux de publication, la référence générée des schémas et des compétences. Elle est là, elle est complète, et l’attente honnête est que vous y arriverez depuis un moteur de recherche au moment exact où quelque chose casse. C’est une bonne façon de s’en servir. Les trois étapes ci-dessus sont celles qui valent d’être lues maintenant.

Quand c’est la machinerie qui vous déroute plutôt que la rédaction — qui fait quoi, dans quel processus, avec quelle compétence — commencez par La plateforme. Une seule phrase y porte tout le modèle, et chacun de ses mots est un objet déclaré séparément.

Qu’est-ce que folio-assistant ?

folio-assistant est la plateforme — elle ne contient pas de contenu. Elle fournit les compétences, les schémas, les outils et un serveur MCP (Model Context Protocol) qu’un agent piloté par un LLM utilise pour planifier, rédiger, valider, réviser, tester et publier un folio de contenu qui réside dans un dépôt séparé.

Séparation des préoccupations. Cette documentation décrit le formalisme du cadre et comment utiliser folio-assistant — délibérément maintenue séparée de tout contenu spécifique. Lorsque du contenu apparaît dans ces pages, il est purement illustratif (un exemple), jamais l’artefact canonique.

Types de contenu pris en charge

folio-assistant est extensible — chaque type de contenu est géré par un adaptateur de contenu et un ensemble de compétences correspondant. Les types actuellement pris en charge :

Type de contenuArtefactsEnsemble de compétences
Articles scientifiques et livresFormalisation Lean 4 + LaTeX/Markdownauthoring-math
Kits d’adaptation numérique (DAK) des Lignes directrices SMART de l’OMSArtefacts L2 — BPMN, DMN, dictionnaires de données Excel, personasauthoring-who-smart-guidelines
Guides d’implémentation SMART de l’OMSRessources FHIR L3, FSH, sortie de l’éditeur d’IGauthoring-who-smart-guidelines
AutresExtensible — ajoutez un nouvel adaptateur + ensemble de compétencesAjouter un type de contenu

Le cycle transversal content-lifecycle (planifier → rédiger → valider → réviser → tester → publier → retour → retirer) s’applique à chaque type de contenu. Le flux de publication le modélise correctement — en diagrammes BPMN à couloirs, avec les rôles, la porte de validation IHM, et le plan de travail partagé.

Où aller ensuite

  • Installation — prérequis, clonage, bun install, vérification des capacités.
  • Démarrage — connectez le serveur MCP à votre LLM et exécutez votre première compétence.
  • Tutoriel : Rédiger un article avec folio-assistant — un guide complet piloté par LLM avec une session de chat simulée.
  • Types de contenu — le formalisme de chaque domaine de rédaction.
  • Flux de publication — diagrammes BPMN à couloirs des processus d’édition et de publication : la porte de validation IHM, qui révise quoi, et le plan de travail partagé.
  • Intégration de l’agent — orientation pour un agent LLM intégré dans un folio : premières étapes, recherche de compétences, modèle d’objets de contenu, side-cars d’assurance qualité.
  • Compétences et rôles — chaque compétence et rôle, et comment ils fonctionnent ensemble avec le LLM.
  • Référence du schéma de compétences — contrats d’entrée/sortie générés pour chaque compétence.
  • Référence de l’API TypeScript — le modèle d’objets de contenu (Block, Chapter, Paper, builders, contraintes Zod).
  • Architecture — adaptateurs, serveur MCP, RBAC, le modèle de blocs.
  • Le graphe de connaissances — la taxonomie des sous-graphes, le sens dans lequel les références s’exécutent, et la manière dont les dépôts répartissent le travail.
  • Le Harness — instanciation, le parcours des dépendances, et ce à quoi oblige le harnachement d’un répertoire.

Deux compétences méritent d’être lues avant les pages ci-dessus, car tout le reste les présuppose : getting-started oriente ce que vous essayez réellement de faire, et placement détermine où doit se situer un nouveau nœud avant que vous n’en créiez un.
