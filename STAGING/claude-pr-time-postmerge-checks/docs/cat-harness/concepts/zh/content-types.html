folio-assistant 是与内容无关的：该平台对任何特定的论文或指南一无所知。每一种（kind）内容都由一个内容适配器（content adapter，懂得如何验证/构建/渲染该种内容的代码）和一个技能包（skill package，创作形式化体系——作者与大语言模型所做的工作）提供支持。

本页面描述了每种内容类型的形式化体系（formalism）。它特意与任何具体内容保持独立；具体的制品存放在它们各自的内容仓库中。

内容生命周期

✎ Edit TR

每种内容类型都遵循相同的生命周期，该生命周期由通用的 content-lifecycle 技能包提供：

阶段技能发生的操作
plancontent-plan确定工作范围，识别制品与参与者
authorcontent-author从源材料创建结构化制品
validatecontent-validate对照模式（schema）与约束进行检查
reviewcontent-review人工 / 领域专家（SME）对照标准进行审阅
testcontent-test自动化 QA、构建通过（green）、证明/验证器通过
publishcontent-publish渲染并部署已发布形式

retirecontent-retire弃用或归档制品

无论内容类型为何，生命周期阶段都是相同的——不同之处在于每种类型所产生的创作（authoring）技能和制品（artifacts）。有关技能的完整列表以及驱动它们的角色，请参阅技能与角色。

八个阶段名称隐藏了两件事，而流程图将其清晰呈现：author（创作）与 validate（验证）并非先后继起的阶段，而是一个循环——每次提议的变更都会运行人机交互（HCI）验证关卡，编辑器在提交任何内容之前都会看到发现的问题——并且 review（审阅）会发生两次，一次针对每次变更，另一次针对组装后的草稿。这两者都在发布工作流页面上展开为各自独立的图表。

文档与政策指南

✎ Edit

技能包： folio-document-adapter · 适配器： document · 指南： 编写文档

结构化散文：卫生政策指南（比如 L1 指南）、标准、报告、手册、书籍章节。论文所具备的一切它都有，唯独缺少形式化层——因而也去掉了服务于形式化层的两条工具链。

  • 源模型（Source model）——与论文相同的类型化块（blocks）构成的树，仅限于内容为散文而非形式化主张的类型：prose、example、remark、algorithm、simulator、equation、diagram、table。
  • 渲染（Rendering）——document_render_md 将 folio 组装为一个 Markdown 文件；document_render_html 与 document_render_pdf 则通过 pandoc 进行处理。PDF 路径使用 HTML 引擎（weasyprint、prince、wkhtmltopdf），并且绝不回退到 latexmk，因此“无需安装 TeX”始终名副其实，而不是变成“直到某人安装了 TeX 为止才名副其实”。
  • 强制约束（Enforcement）——content_profile_check 会拒绝数学类型、lean 字段或同级的 .lean 文件，并在每次 content_validate 时运行。

相关的技能模式： document-authoring、 document-structure、 normative-statements、 document-publishing。

承载规范性陈述

✎ Edit TR

建议、要求或规则是读者所引述、实施者所追踪的块。它需要标签、稳定的标识以及在依赖图中的位置——theorem（定理）所拥有的一切——但它断然不是定理，因为没有任何东西去证明它。

目前不存在作为一等公民的 recommendation 块类型。目前它的载体是一个带有标签和标题的 prose 块；normative-statements 技能阐明了该约定及其限制。早期在 document-intake 中的指导意见将指南建议映射到 definition 上——这早于当前这种内容类型，并且对文档 folio 而言是错误的，因为在文档 folio 中 definition 属于数学类型，且其 lean 字段是必填项。

科学论文与专著

✎ Edit TR

技能包： authoring-math · 适配器： paper · 指南： 编写论文

严谨的科学论文与专著，其中的散文和数学内容均有机器校验的 Lean 4 形式化作为后盾，并通过 LaTeX 进行排版渲染。

论文就是文档加上包含 Lean 的块。 上一节中的所有内容在此同样适用：相同的块树、相同的编辑 uses[] 图、相同的 QA sidecar、相同的生命周期——以及 Markdown 渲染路径（在未安装 TeX 的机器上起草时即可工作）。正因如此，paper 适配器在代码上继承扩展了 document 适配器。论文所增加的是下方的七种断言为形式化主张的块类型，以及用于检查和排版它们的两个工具链。

  • 源模型（Source model）——内容是由类型化块（definition、theorem、lemma、proof、equation、prose 等）构成的树。有关 Block、Chapter 和 Paper，请参阅 TypeScript API 参考。
  • 形式化（Formalization）——lean-formalization 和 proof-verification 技能驱动 Lean；每个类定理（theorem-like）块都可以对照其 Lean 对应项进行追踪，且每一个 sorry 均可审计。
  • 渲染（Rendering）——latex-authoring 加上论文适配器的 paper_render_pdf / paper_render_html 工具。

文档 folio 无法获得的七种类型，以及它共享的八种类型：

块类型标签前缀是否包含 Lean？配置文件
definitiondef:必需仅限论文 (paper only)
theorem / lemma / proposition / corollarythm: / lem: / …预期包含仅限论文 (paper only)
conjectureconj:可选仅限论文 (paper only)
proofprf:可选仅限论文 (paper only)
example / remarkex: / rem:可选共享 (shared)
algorithm / simulatoralg: / sim:可选共享 (shared)
prose / equation / diagram / tableprose: / eq: / fig: / tbl:不适用共享 (shared)

四个“仅限论文”（paper only）行是 schemas/block-kinds.ts 中的 MATH_BLOCK_KINDS；而“共享”（shared）行则是 DOCUMENT_BLOCK_KINDS，作为补集推导得出，以便后续添加的类型不会未经分类。

其中有两行值得进一步审视。definition 是整个划分中最明确的分水岭——它是唯一一个其 lean 字段为必需而非可选的类型，因此即便配置文件允许，文档 folio 也无法容纳它。而“共享”（shared）类型仍然声明了一个可选的 lean：类型系统允许了配置文件所禁止的内容，这正是为什么 content_profile_check 在“该类型是否被允许”之外还有第二条规则。

相关的技能模式： latex-authoring、 lean-formalization、 proof-verification。

WHO SMART 指南 DAK（L2）

✎ Edit TR

技能包： authoring-who-smart-guidelines · 指南： 创作 WHO SMART DAK

数字适应套件（Digital Adaptation Kit，简称 DAK）是 WHO 指南的 L2（机器可读，但独立于具体实现）表示。folio-assistant 负责创作以下 L2 制品：

  • 业务流程——BPMN 2.0 工作流（bpmn-authoring）
  • 决策逻辑——DMN 决策表（dmn-authoring）
  • 数据字典 / 核心数据元素——Excel / 结构化表格
  • 术语——代码系统与值集（terminology-management）
  • 人物画像、场景、指标、需求

相关的技能模式： l2-dak-authoring、 bpmn-authoring、 dmn-authoring、 terminology-management。

WHO SMART 实施指南（L3）

✎ Edit TR

技能包： authoring-who-smart-guidelines · 指南： 创作 WHO SMART IG

L3 层将 L2 DAK 转换为可计算的 FHIR 实施指南（Implementation Guide）：

  • FHIR 资源——以 FSH（FHIR Shorthand）编写并使用 SUSHI 进行编译（l3-fhir-authoring）
  • 验证——对照 FHIR Profile 进行验证（fhir-validation）
  • 发布——使用 HL7 FHIR IG Publisher 发布（ig-publication）
  • 质量控制——质控关卡（quality-control）

相关的技能模式： l3-fhir-authoring、 fhir-validation、 ig-publication、 quality-control。
