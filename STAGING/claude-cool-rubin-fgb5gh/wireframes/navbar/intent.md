I could not build the site. There is no local just-the-docs, and the proxy refuses `litlfred.github.io`. So this is drawn from the templates, JS, CSS and generated data. Where a behaviour comes from reading the CSS rather than a render, the text says so.

## Who it is for, and what they need to do

The template comments quote the owner:
- the dividers are *"like a giant tabbed folio"*: *"a thing you REACH FOR"*, not a dashboard
- *"harnesses should be collapsible"*
- closed means a strip *"icon width thick"*, not gone
- home stays at the bottom

The declared interaction profile is low-dexterity, which is why the tab bodies are large targets.

- **Reader:** anyone on any docs page, including a low-dexterity or touch reader.
- **Tasks:**
  - know which instance they are in
  - jump to a harness and to its graphs (library, docs, processes …)
  - reach the harness actions (todos, beans, processes, KG)
  - see the current page's sections
  - get home
  - reach settings, language, QR and search

## What it must show (read off the sources)

- **Top:** the instance mark and title, the scheme / language / actions controls, and the icon row. The icon row comes from `navbar.icons`: close, todos, beans, processes, kg, launcher.
- **Middle:** "On this page", when the page has at least 2 h2/h3 headings. Then "Folders", 24 entries for cat-harness, with no-viewer kinds rendered as unlinked text. Then the theme's page list.
- **Bottom:** "Harnesses (5)", the instantiated ones: smart-trust, WHO IRIS, Folio Assistant, C@T Harness, and Bootstrap as the floor. Each carries its mark or initial, its label, and its graph links. Unlinked kinds carry a note ("no viewer yet" or "no viewer by design"). ⌂ home comes last.
- **Landing:**
  - Stickies (5), collapsed
  - title, lede, and Get started / Install / View on GitHub
  - one section per harness: description, three stats, viewer links, and "Gaps in this instance's declaration (n)"
  - then the authored guide

## Findings

1. **At rest the strip is marks with no labels.** Four of the five dividers are single initials (S, W, F, B), and there are five unlabelled glyphs (▤ ◍ ⇶ ⌘ ▦). The accessible names exist (`aria-label` or `title`), but a sighted mouse reader has to hover each one. A touch reader on a tablet at 800 px or wider cannot hover, and has to use ☰ first. The CSS comment says the same.
2. **Two dividers open the same page.** Folio Assistant and C@T Harness both have `href: "/"`, which is the landing page the reader is already on. The difference only shows as two sections further down that page.
3. **The harness descriptions leak authoring notes and formatting into the landing page.**
   - Folio Assistant's description is a naming rationale: *"NAMED `folio-assistant-checkout` rather than `folio-assistant`…"*, with literal backticks.
   - C@T Harness's description is five newline-separated alternative spellings ("caaat-harness ca&at-harness .c&at-harness c@t-harness"), which run together as one line.
4. **Each harness's navigation appears in three places.** The graph kinds appear as the divider's links in the sidebar, as "Folders (24)" for cat-harness, and as "visualisations you can open" on the landing. They are generated from one accessor, so they agree, but the open sidebar lists cat-harness's 24 kinds twice, in Folders and under the C@T Harness divider.
5. **The open sidebar is long even with its caps.** "On this page" (11), the 27-page nav, and five dividers with up to 24 graph links each are stacked. The CSS comment records that the middle region can shrink to an 8rem floor. The page list, which is the theme's main navigation, is the region that gets squeezed.
6. **Mobile: the sidebar's own × / ☰ labels are unstyled below 800 px.** This is read off `docs-ui.css`: every `.fa-nav-toggle` / `.fa-nav-close` rule, and every `:has(.fa-nav-open:checked)` rule, is inside `@media (min-width: 50rem)`. Only print hides them. So in the theme's opened menu they render as bare "×" and "☰" glyphs beside the theme's own Menu button, and no rule reads the checkbox they toggle at that width. I have not seen a render, so whether the theme's own mobile CSS hides the sidebar footer they sit in is unconfirmed.
7. **The "▾ Folio" handle is fixed at top centre on every page** (`z-index: 91`, `min-height: 3.25rem`). At 390 px it sits over the middle of the theme's top bar, where the title is.
