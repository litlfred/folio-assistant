# Skills index visualiser — as-is intent

**Covers:** `cat-harness/docs/cat-harness/docs-auto/index/skills/cat-harness/index.html`. The same template renders `cat-harness/docs/cat-harness/docs-auto/index/skills/bootstrap-render/index.html`, `cat-harness/docs/cat-harness/docs-auto/index/skills/kg-navigation/index.html`, `cat-harness/docs/cat-harness/docs-auto/index/skills/large-datasets-skills/index.html` and `cat-harness/docs/cat-harness/docs-auto/index/skills/who-iris-skills/index.html`, and this wireframe covers those as well. Generated by `cat-harness/scripts/gen-docs-auto.ts` (`bun run docs:auto`) using `autoDocPage()`, the type `index/skills`.

**Who it is for:** an agent or person choosing a skill, and the author of a harness's docs who has to summarise what the index lists (the `docs-auto` skill obligation quoted in the generator).

**What they need to do:** see every skill markdown file in a sub-graph with the description its front matter declares, move between the five skill sub-graphs, and open a skill's source on GitHub.

**What it must show** (read off the page and the generator): the title and scope tag; the lede ("every skill markdown file, with the description it declares in its own front matter"); the "index, not the documentation" note; a sibling list with counts; and a two-column table of name (link), path and description, or *no description in the artefact*.

## Findings

1. **Horizontal scroll at phone width.** At 390 px the document is 421 px wide (`scrollWidth` 421). Descriptions containing long unbreakable tokens (for example `gh-pages/STAGING/<branch-slug>/` and `` `<Paper>/MathlibExt.lean` ``) push the table past the viewport, so the right edge of every description is cut until the reader pans.
2. **One very long flat list.** 238 rows run to 20,003 px at 1280 and 40,314 px at 390. The page has no folder headings (the folder is visible only inside each path), no search and no filter. Finding `wireframe-design-review` among 135 folio-core skills means scrolling or using the browser's find.
3. **50 of 238 skills say *no description in the artefact***, among them `latex-authoring`, `fhir-validation`, all nine content-lifecycle skills and `dmn-authoring`.
4. **Markdown shows through.** 22 descriptions have literal backticks, for example "Taking a file from \`uploads/\` to \`library/<bib-slug>/\`".
5. **The phone layout favours the path.** At 390 px the first column holds the name and a path that breaks mid-token (`…/authoring-who-smart-g / uidelines/…`), which leaves a narrow description column, and that column is then clipped (finding 1).
6. **The small siblings get the same heavy page shell.** `kg-navigation` and `who-iris-skills` have one row each, but they repeat the full lede, note and five-row sibling list above it.
