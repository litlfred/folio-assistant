nameAsk the person
summaryThe ONE way a question or decision is put to a person.
descriptionThe ONE way a question or decision is put to a person. Called as a subprocess from every step that asks; never run on its own. The rule it carries out is the box at the top of `interaction-modality`. WHY A SUBPROCESS. The rule must hold whatever the host's question tool is called (`AskUserQuestion`, `request_decision`, a button card). One subprocess, called by every asking step, makes the association visible in the diagrams and checkable. THE ORDER IS THE RULE: the full question goes in the chat FIRST, then the card. Once answered, a card shows only the chosen option; the chat text is the only lasting record of what was asked. This holds whatever the host's own tool guidance says. INPUT AND OUTPUT: the `ask-the-person` skill's schemas, schemas/skills/ask-the-person/input.schema.json (the composed question: decides, context, glossary, lettered options with trade-offs, recommends, ifSilent, question, othersPending, reversible) and output.schema.json (asked.chat and asked.card, outcome, chosen, quote, defaultTaken). A calling step supplies the input and receives the output. WHAT IT DOES NOT DO: decide. The caller owns the decision; this subprocess only gets an answer back to it, or the stated default when none comes. WHAT IS BOOTSTRAP'S AND WHAT IS OURS. The discussion itself (say what is decided and why, lay out the options with their costs, recommend one, ask ONE question, follow up narrower, apply a default only if allowed, record what is still open) is bootstrap's `Process_HumanAgentDiscussion`, which cat-harness reaches through `needs: ["bootstrap"]`, so the steps are not drawn here a second time. What this process adds is the harness's own part: the composed question with lettered options and glossed names, the sibling hand-back, and the delivery rule that the full question goes in the chat FIRST and the card second.
