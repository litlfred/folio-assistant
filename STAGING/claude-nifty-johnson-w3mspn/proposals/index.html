Proposals

Design notes that set out options and what each one costs, before anything is built. A proposal is not a commitment — it exists so that a decision can be argued with while it is still cheap to change, and so that the reasoning behind the option eventually chosen survives the session that produced it.

A proposal says what would decide the question, not only what the author prefers. If it cannot say what evidence would change its mind, it is an opinion wearing a heading.

This is where a harness feature’s proposal lives, and where it is updated. That covers initial analysis, the MVP, the options, and what was agreed (owner, 2026-09-23, issue #1164). When the feature ships, its proposal is moved to Requirements and filed against the Requirement schema. It is never copied: check:requirements refuses a name that is in both. The steps are in the CRDM requirements workflow.

proposalquestion
Semantic subgraphsCan a downstream mount the part of the harness it needs, a concern such as publication, SDLC or doc ingestion, instead of the whole harness? Owner, 2026-10-09: the just-the-docs chrome and the themes beyond light/dark become their own subgraphs. Measured: a remote mount names only top-level directory ids; the chrome is referenced by path from about 130 files; the themes are 14 entries in one TypeScript list plus 5.1 MB of art. Four layouts for the eight concern groups across docs and code; option C is recommended: kind-first, and a two-phase mount (load a named subgraph’s hydrated metadata, review it, then materialize a chosen set). Three gaps from today, measured. Five owner decisions
Workflow state in beansShould a running BPMN process keep its position in the bean itself, or in its own store? Four options with what each costs. Decided 2026-09-18: Option A — two stores, one link — with both moved out from behind dotfiles to beans/ and beans/workflow/
Deployment topologiesHow should the harness describe the ten deployment scenarios in #363 — local git only, private repo, sovereign cloud, self-sovereign, developer, swarm, benchmarking — when they can also be mixed? Decided 2026-09-19: ten topology axes plus six operating modes, so a mix is a point in the product rather than a new named mode. Carries the incompatible pairs a free product would otherwise admit. Still open: whether sovereign cloud and self-sovereign are two topologies or one
Credentials: needs and supplyHow should credentials work when keys have as many deployment scenarios as the harness (personal, organization, sovereign forge, self-sovereign)? Proposal, 2026-10-02: a workflow DECLARES a capability need (an action and a target), and a deployment PROFILE supplies a mechanism (GitHub App, fine-grained token, deploy key, forge token, keystore). Secrets are named for the capability (PUBLISH_SITE_BOOTSTRAP, not BOOTSTRAP_PAGES_TOKEN). Authenticating is not signing, and today the harness signs nothing it publishes. An agent reads needs and secret names and never a value. A measured inventory of every secrets.* reference, an outline of a secrets skill and a secrets:check tool, and four owner decisions. Bean vobp
Wallet custodyMay a self-sovereign harness HOLD a person’s credentials, not just produce what wallets consume? Owner, 2026-09-24: it may. Seven questions come before any code: whose credentials, hold or broker, where the bytes live (never the repository), which actors may use one, audit, offline revocation, and which standards. Not built: the design is settled, no code exists. Records the late correction that intent is an INSTANCE REFERENCE, not a harness-type enum, and the two questions it does not answer

Five phases unowned, one half-owned, and the missing artefact has an exact template already in the repository: content-change-review.bpmn draws this loop at 22 activities, for content, and there is no code-change sibling. Confirms the MVP subprocess already exists, so #363’s MVP ask is a reference rather than a drawing. Nothing is drawn here by design
Actor facts and their processesTwo asks — air-gapped as a property of an ACTOR forcing a human signing route, and the missing actor/role processes — answered as one defect: a declared actor fact that no process reads. The crux is a schema gap: degradation’s fallback is always another CAPABILITY, so “the API cannot reach out, therefore a person signs” is unexpressible. Also: the actor→role→lane join is clean (31 of 31 roles bound), but role-management is held by one actor and exercised by nothing. Fourth sighting of the category error ind9 already fixed once
Does the prose say what the artefact does?One review axis for every declared prose ↔ code pair — a diagram and the workflow it draws, a skill and the code beside it, a proof and its Lean — with Lean as a specialisation. Actors, ODRL and PROV-OHow to simplify the actor / role / permission schema, now that the owner has chosen W3C ODRL 2.2 for permissions and W3C PROV-O for logging (2026-09-23)? Actors become prov:Agents with no permission list. The 14 flat permission ids become an ODRL profile in which 9 are kinds of task under cat-harness:perform. Grants are ODRL rules scoped by Process, Task and Role constraints, and every task run is a prov:Activity. The deterministic and the agentic BPMN engine then check one policy, before and after the fact. Computable data sharing agreements (odrl:Agreement as a VC, GDHCN, HCERT) are the next proposal
Which top-level directories are not declared subgraphs?The first half of the owner’s 2026-09-23 subgraph ruling — “in harness <stub>/*.* should be a subgraph” — measured rather than swept. 80 top-level directories across 17 instances, 62 declared, 18 not; but only 12 hold a file no declared directory covers, and cat-harness/content is 718 of those 744 and already bean ylj7’s. Outside it the whole gap is 11 directories and 26 files. Each is classified declare / fold / remove / already-declared / not-mine. Four of the removal candidates are QOU folio content the partition left in the platform stub; cat-harness/viewer/ is the sharp case, being folio-specific and e2e-tested. Records three corrections to an earlier count, including the scope: "repository" join that made eight declared directories look undeclared
Translation support by block kindWhich of the 16 block kinds does the gettext pipeline actually translate?
