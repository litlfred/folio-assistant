        • OptionalcontentTypes?: Record<string, Record<string, unknown>>

          Sections that registered CONTENT TYPES declare about this repository, keyed by the type's id: "contentTypes": { "dak": { ... } }.

          The platform knows only that each value is an object. What goes inside is the business of the layer that registered the type, which reads and validates its own section (owner, 2026-10-24: a DAK's metadata moves into index.config.json and WHO adopts the file). A section's PRESENCE is the marker, the same assertion a marker file makes: see IndexSectionMarker in content-type.ts. It sits on the index for the reason site.agentRun does: an IG repository may declare no instance of its own, so its index is all it has.

          • OptionalagentRun?: boolean

            This repository is AGENT-RUN: an agent builds and publishes its site (stage-local.ts), and its publish workflows keep only workflow_dispatch, as documentation of what the agent path must match rather than something to dispatch (owner, 2026-10-10, bean n3h9; the feature-staging skill, "Agent-run repositories").

            The repository declares it itself: the owner ruled on 2026-10-14 (Q7 of the folio-assistant#2529 reference-direction review, "Yes, declare it") that agent-run is a declaration, not a list the platform keeps of the repositories it applies to. It sits on the INDEX's site, beside landing, and not on an instance declaration, for the reason landing is on a config: it is a fact about how THIS checkout publishes. A declaration travels into every checkout that mounts the instance, and an IG repository may declare no instance of its own at all, so its index.config.json is all it has.

            Absent means not declared. That is not the same as "a runner publishes it", so a reader says which one it found rather than assuming.

          • Optionallanding?: string

            An instance name, or HUB_LANDING. Must name an instance this file lists.

          • Optionalworkflows?: { publish?: string; stage?: string }

            The workflow files that publish this repository's site and stage a preview of it, by file name under .github/workflows/. The pages-publish and feature-staging Tools run them through bun run cat site:workflow publish|stage, so a Tool names no repository's file (owner, 2026-10-30, "Make them generic"). An agent-run repository declares none: stage-local.ts is its path. check:tools fails when a file named here does not exist.

        • Optionaltitle?: string

          What this CHECKOUT is called. The index declares no instance of its own (owner, 2026-10-08), so nothing else names it; index:render titles the root README.md and AGENTS.md with it (owner, 2026-10-09: those two are rendered files). Absent, they are titled generically.
