Bootstrap terms

términoetiquetas alternativasdefinición
Nodo—Un archivo, o una parte de un archivo direccionable mediante un fragmento de IRI, nombrado por un IRI.
Referencia—La designación que un Nodo hace de otro Nodo por su IRI.
Esquema de nodo—Un esquema contra el que se puede validar un Nodo: un JSON Schema, o un esquema externo publicado como el de BPMN.
Tipo de nodo—Un nombre emparejado con un Esquema de nodo.
Subtipo—Un Tipo de nodo cuyo Esquema de nodo exige todo lo que exige el de otro Tipo de nodo, de modo que todo Nodo que lo satisface satisface también el otro.
Instancia de nodo—Un Nodo que nombra su Tipo de nodo, en $schema o en el preámbulo, y satisface el Esquema de nodo de ese tipo.
Tipo de grafo—Un conjunto con nombre de Tipos de nodo.
Declaración—Un documento JSON, <name>.json, que da un nombre y enumera entradas de directorio y entradas de archivo.
Extensión—Un campo de una Declaración, o de una de sus entradas, que no se define aquí. Un lector que no reconoce el campo lo ignora, y el resto de la Declaración conserva su significado.
Subgrafo—Una entrada de directorio de una Declaración: un id, un directorio y los Tipos de grafo a los que pertenecen los tipos de sus Instancias de nodo.
Recurso—Una entrada de archivo de una Declaración: un archivo sobre el propio repositorio, cuyo campo role indica para qué sirve.
Grafo de conocimiento—Los Esquemas de nodo, las Instancias de nodo y los Recursos que enumera una Declaración, en una versión dada del repositorio. Publicadas como JSON-LD, las afirmaciones de las Instancias de nodo de cada Subgrafo forman un grafo con nombre.
Dependencia—Una entrada needs de una Declaración que nombra otro Grafo de conocimiento. Las Referencias pueden apuntar desde las Instancias de nodo de este grafo hacia el nombrado, nunca en sentido inverso.
Contenido—Instancias de nodo que describen el objeto de un Grafo de conocimiento, como registros, documentos, catálogos y sus términos, y no cómo trabajar con él.
Tarea—Una unidad de trabajo, expresada por lo que necesita para comenzar y lo que produce.
Actor—Una persona, un agente o un programa que puede llevar a cabo Tareas.
Habilidad—A Node Instance stating a responsibility an Actor carries out to complete a Task: as natural-language instructions to follow, as a contract to be tested against, or both. (sin traducir)
Rol—Una Instancia de nodo que nombra un papel que un Actor asume para llevar a cabo Tareas y enumera las Habilidades que ese papel necesita.
Nodo de proceso—Un nodo de flujo BPMN: una actividad (una tarea o una actividad de llamada), una compuerta o un evento.
Flujo de secuencia—Una conexión dirigida en un proceso BPMN de un Nodo de proceso al siguiente.
Proceso—Una Instancia de nodo que contiene un proceso BPMN que coordina Tareas: sus Nodos de proceso, unidos por Flujos de secuencia, se sitúan en carriles que nombran cada uno un Rol.
Arnés—Un Grafo de conocimiento cuyos Subgrafos contienen Habilidades, Roles o Procesos: aquello que un Actor usa para trabajar con un Grafo de conocimiento, incluido él mismo.

Folio Assistant platform terms (cat-harness)

términoetiquetas alternativasdefinición
arnés asociado—Un arnés que este conoce por nombre, sitio y repositorio, y que nunca carga, construye ni copia. La cuarta relación junto a depende (needs), referencia (remoteGraphs) y utiliza (dependencies).
política—Qué Actor puede realizar qué acción, y dónde, escrito como reglas de permiso y prohibición de W3C ODRL 2.2 acotadas por Proceso, Tarea y Rol.
permiso—Una regla ODRL que permite a un destinatario una acción, opcionalmente sobre un objetivo y dentro de unas restricciones. Un permiso para una acción más amplia permite todas las acciones incluidas en ella.
ejecución de tarea—Una ejecución de una tarea BPMN por un Actor en un Rol bajo una política, registrada como una actividad W3C PROV-O cuyo plan es la tarea.
actor—Un participante concreto, humano, agéntico o mecánico, que persiste a través de todos los procesos y asume roles. Qué inicio de sesión corresponde a qué actor es algo que sabe el almacén de datos.
rol—El carril: una persona que un actor asume por el carril en el que actúa, y que lleva las habilidades que necesitan las actividades de ese carril.
user story (sin traducir)—What a reader acting in a Role is trying to do, told as that role: as a , I want , so that . The story points at its role; the role names no story. _(sin traducir)_
test run (sin traducir)—One measurement of a Skill: which skill it tests, the cases it exercised, and a hash of the data and a hash of the process that produced the result, so a third party can redo it. Its cases are checked against the skill’s input and output contracts. (sin traducir)
voice (sin traducir)—A named set of writing rules for prose, active in the roles and processes it names. The voice points at the role it is written for; the role names no voice. (sin traducir)
external schema (sin traducir)—A record of a specification the platform depends on but does not hold: which authority publishes it, which version is conformed to, and the operative terms used from it. (sin traducir)
KG QA report (sin traducir)—A committed QA sidecar recording, for one knowledge-graph subject such as a process, role or skill, which of its references fail to resolve under each audit criterion. (sin traducir)
todo (sin traducir)—One person’s outstanding work, as a content node the folio owns, tagged with the roles, processes and tasks it concerns. Not the agent work plan, which is beans. (sin traducir)
bean (sin traducir)—One item of the agent work plan, held by the beans CLI in the committed beans/ store, with a status, a parent and the beans it blocks. (sin traducir)
JSON Schema (sin traducir)—A JSON document that describes the shape of other JSON documents. In the platform, a node schema and a skill’s input and output contracts are each a JSON Schema file. (sin traducir)
