# glossary/ page: as-is intent

**Covers:** `cat-harness/docs/glossary/index.md`, the `coverage.visualiser` of core's `glossary` directory in `folio-assistant-core/folio-assistant-core.json`, and the per-asset-type pages beside it, `cat-harness/docs/glossary/<type>/index.md`. All are generated by `folio-assistant-core/scripts/glossary-page.ts` (`bun run glossary:page`) and gated by `check:glossary`.

**Candidates:** `as-is.html` is the index, and `as-is-type-page.html` is one asset type's page (Schema fields, the largest). Both are checked at web 1280 and mobile 390.

**Who it is for:** anyone who meets a word in a folio and wants to know what it means: a reader, an author choosing a term, or an agent binding a term to an external concept. Owner, 2026-09-23: *"it should be part of general pracice w/ glossary/ page"*.

**What they need to do:** find a term fast, read its definition, see its code, see which external concept it matches, and tell an authored definition from a candidate extracted from a knowledge-graph asset.

**What it must show:**

On the index (`glossary/`):
- the counts by state (authored, candidate extracted, could-not-extract);
- a Pages table: this page and one row per asset type (skills, Tools, BPMN activities, DMN decisions, schema fields), each linked, with its term count and size;
- the index's own size and its budget (64 KB), and the per-type budget (1 MB);
- the authored terms, with a filter box and live count, and an A–Z letter bar;
- per term: the label, the code (`notation`) when the label and source do not already say it, a status badge when not `authored`, the definition, the scheme, the term IRI for an authored term, the source as a link to the asset, and the external matches as links;
- a Sources list: each scheme with its SKOS JSON-LD link, the swimlane ledgers (linked, never copied), and the external schemes referenced through `remoteGraphs`;
- a table of the extracted schemes, instance by asset type, each column heading linked to that type's page and each count linked to its SKOS;
- schema.org `DefinedTermSet` JSON-LD for search engines, carrying the authored terms only.

On each asset type's page (`glossary/<type>/`):
- a link back to the index, and a sentence on what the terms are read from;
- which instances contribute, each with its count and SKOS link;
- the page's size and its budget;
- the filter box with a live count, the A–Z bar, and every term with the "candidate, extracted" badge.

Every term is on exactly one page: authored on the index, extracted on its type's.

## What it answers from the earlier glossary wireframe (`glossary/`, bean `n5be`)

That page's first finding was *"There is no way to find a term except scrolling or the browser's find."* This page has a filter box, an A–Z bar, and terms sorted alphabetically. The swimlane index stays where it is and is linked as a source, so the 46 role terms are not rendered a second time.

## Observed after piece 1 as posed (bean `lqo9`, 2026-09-24)

2428 terms: 7 authored, 2421 extracted as candidates from skills (269), Tools (98), BPMN activities (530), DMN decisions (9) and documented schema fields (1515). The page is 1.4 MB before compression, so it keeps the A–Z bar and the filter, adds the "Show" choice, and says its size near the top. No search engine is added: bean `4pm8` admits Pagefind only in the large-datasets sub-graph. An extracted term's IRI is left to its scheme's SKOS rather than printed on every row; that was the largest cost per row.

## Split per asset type (owner, 2026-09-24)

The owner chose *"Split per asset type"* over keeping one 1.4 MB page. Measured before the split: one page of 2439 terms, 1.5 MB (1,522,496 bytes). After: index 16 KB (7 terms); Skills 192 KB (271); Tools 63 KB (98); BPMN activities 403 KB (531); DMN decisions 7 KB (9); Schema fields 823 KB (1523). The "Show" choice (all, authored only, extracted only) is gone: each page now holds one state, so it had nothing left to choose between. The SKOS files did not change. `glossary.test.ts` pins that every term appears once across the pages, that each page is under its budget, and that the index links every type's page; `check:glossary` fails a page over its budget.

## Terms minted by the instance that owns their source (owner, 2026-09-24)
