    Module schemas/kg/opt-in-subgraphs

    Opt-in named sub-graphs: which are switched on for a folio, and whether a directory sits inside one that is switched off.

    Graph Node

    none — a reader and predicates over declared opt-in sub-graphs; it defines no schema

    The rule

    A directory entry marked optIn: true is an opt-in sub-graph (e.g. cat-harness's sdlc and work-plan). It is off in EVERY layer — including the one that declares it — unless that layer lists it, qualified <instance>.<directory id>, in its own enableSubgraphs.

    The folio root decides, and nothing is inherited. A layer's list enables the sub-graphs for ITSELF. So every reader asks enabledSubgraphs of the root it is resolving FOR — the folio, the downstream of a mount, the instance whose own resolution it is — never of the layer that declared the sub-graph.

    A development override. CAT_SUBGRAPHS (+cat-harness.sdlc,-x.y) adjusts the root's list, so a dev session in any checkout can turn one on without editing a declaration. Unset in CI, and in every agent test context.

    Switched off is invisible, not deleted. A switched-off sub-graph — and everything declared from within it, in any member instance — is left out of what the agent is given: the resolved directories, the skill overlay, the served Tool groups and a mount's default directory list. An explicit mount override naming it still mounts it, and the harness's own machinery may still use it.

    An enableSubgraphs id that names nothing opt-in is refused by check:declaration-resolution (enableSubgraphsProblems), never ignored.
