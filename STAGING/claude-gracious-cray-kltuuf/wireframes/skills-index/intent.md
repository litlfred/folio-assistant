# Skills index visualiser — as-is intent

**Covers:** `cat-harness/docs/cat-harness/docs-auto/index/skills/cat-harness/index.html`. The same template renders `cat-harness/docs/cat-harness/docs-auto/index/skills/large-datasets-skills/index.html` and `cat-harness/docs/cat-harness/docs-auto/index/skills/who-iris-skills/index.html`, and this wireframe covers those as well. Generated by `cat-harness/scripts/gen-docs-auto.ts` (`bun run docs:auto`) using `autoDocPage()`, the type `index/skills`. The `bootstrap-render` sub-graph page is no longer declared or generated, and it has left the sibling list.

**Since 2026-09-23 (bean `byql`)** `kg-navigation` is a package under `cat-harness/skills/` rather than its own sub-graph, so it has no page of its own and appears in the `cat-harness` list. The sibling counts below predate that and are kept as the as-is record they were.

**Who it is for:** an agent or person choosing a skill, and the author of a harness's docs who has to summarise what the index lists (the `docs-auto` skill obligation quoted in the generator).

**What they need to do:** see every skill markdown file in a sub-graph with the description its front matter declares, move between the four skill sub-graphs, and open a skill's source on GitHub (each name links to `github.com/litlfred/folio-assistant/blob/main/<path>`).

**What it must show** (read off the page and the generator): the title and scope tag; the lede ("every skill markdown file, with the description it declares in its own front matter"); the "index, not the documentation" note; a sibling list with counts; and a two-column table of name (link), path and description, or *no description in the artefact*.

## Findings

1. **Horizontal scroll at phone width.** At 390 px the `cat-harness` page is still 421 px wide (`scrollWidth` 421, table 402 px). The description column's text runs past the viewport from the very first rows ("no description in the artefact" is cut to "…artefac"), so the right edge of every description is cut until the reader pans. The three one- and two-row siblings do not overflow.
2. **One very long flat list.** 240 rows run to 20,126 px at 1280 and 40,578 px at 390. The page has no folder headings (the folder is visible only inside each path), no search and no filter. Finding `wireframe-design-review` among 137 folio-core skills means scrolling or using the browser's find.
3. **50 of 240 skills say *no description in the artefact***, among them `latex-authoring`, `fhir-validation`, all nine content-lifecycle skills, all four new folio-document-adapter skills and `dmn-authoring`.
4. **Long descriptions are cut at 220 characters, with no way to read the rest here.** 31 descriptions end in "…", for example `wireframe-design-review` ("…mechanical checks at both vie…"). Only the GitHub source has the full text.
5. **Markdown shows through.** 22 descriptions have literal backticks, for example "Pointer to the bean-based session work-plan system (the \`beans\` CLI flat-file issue tracker, data under \`beans/\`)".
6. **The phone layout favours the path.** At 390 px the name and path column takes 147 px on `cat-harness` and the path breaks at any character (`cat-harness/skil / ls/authoring-mat / h/latex-authorin / g.md`). On the one-row siblings it is worse: the path column takes 260 px and the description column is 92 px, so "How a cold agent finds and loads the skill that governs its task." wraps to one or two words a line.
7. **The small siblings get the same heavy page shell.** `kg-navigation` and `who-iris-skills` have one row each, but they repeat the full lede, note and four-row sibling list above it. At 390 px their only row starts at y ≈ 655.
