L2 DAK authoring

Process_L2Dak · advisory · 11 step(s)

How a WHO SMART Guidelines L2 Digital Adaptation Kit is authored by a business analyst, a terminologist and a clinical SME under a programme manager. folio-assistant — authoring a WHO SMART Guidelines L2 Digital Adaptation Kit. Source of truth: this file. Open it in bpmn.io, Camunda Modeler, or any other BPMN 2.0 tool. The SVG under docs/assets/img/workflows/ is generated from it by bun run cat render:bpmn — never hand-edit the SVG. The extension on an activity names the folio-assistant skill that implements it; marks a step that reads or writes the shared work plan in beans/. Each of the six authoring tracks is a call into l2-component-edit-review.bpmn (Process_L2ComponentEditReview): the agent edits the component, checks, renders and stages it, and hands it on, while a person in the component's reviewing role reviews it alongside, never as a gate. The track's renderer, checker and reviewer are tabled in the skill l2-component-edit-review.

Business analystbusiness-analystOpens the parallel fork into six authoring tracks — five landing here, the sixth (terminology) crossing into a separate lane — and re-enters that same fork whenever clinical validation sends work back, so a fix after Gateway_Accurate revisits every track it is entangled with rather than patching only the one SME flagged. Performs the assemble-and-validate in parallel with clinical validation, not after it (owner, 2026-10-14: adjudication is QA, not a gate), and again after any rework. TerminologistterminologistOne parallel branch of the fork, producing bindings the other five tracks cite rather than author themselves, and calling the same edit-and-review subprocess as they do, with a different terminologist as its reviewer. Kept a separate lane rather than folded into the analyst’s because governance of a code binding is deliberately independent of the artefact that cites it.
Clinical SMEclinical-smeClinical validation runs beside assembly, not before it: it is QA, not a gate (owner, 2026-10-14). A “no” here does not return to the specific task that erred but loops back through Gateway_AuthorMerge into the fork itself, so this lane’s judgement — not the analyst’s — decides whether personas, BPMN, DMN, data dictionary and indicators all get revisited together.

Scope the DAK
Task_ScopeDak		Programme manager / technical officercontent-planEnumerate the processes, decisions and data elements the guideline implies; identify the actors.
Build the L1 library from Component 1
Task_L1Library		Business analystdak-l1-libraryIngest the DAK into the library; it is L2, so it gets no L1 graph. Read Component 1 §1.2 for the sources it draws on (extract-dak-l1-references.ts –context-only), then fetch each L1 source on its own — fetch-dspace-item.ts for an IRIS handle, fetch-who-publication.ts for a who.int item page — and ingest it. Record whether each is L1 on its intake (declared > context > inferred; –record-context writes §1.2’s context). For each L1 source, run l1-specialise.ts: its publication, sections and elements as specialisations of its library nodes, since the library is upstream of L1. Validate with the smart-base Zod validator. Fidelity — does each citation name the source it resolves to — and a cited edition older than the one fetched are left to a person, never passed automatically.
