    Module schemas/prov

    W3C PROV-O: the record of a task or decision being performed. Issue #1180, extended for computable Data Sharing Agreements (DSA B4, bean 3z44, issue #2702).

    Owner, 2026-09-23: "W3C ODRL 2.2 and W3C PROV-O for logging". The deterministic BPMN engine checks a policy BEFORE a task and refuses; the agentic swarm acts, and a QA/QC report checks the policy AFTER, from this log (docs/agentic-harness.html#bpmn-execution). Both need the same record, so it is PROV-O's, not ours.

    One prov:Activity per task run or decision:

    PROV-O / extensionmeans here
    prov:qualifiedAssociation.prov:agentthe Actor that performed it
    prov:qualifiedAssociation.prov:hadRolethe Role it acted in (the lane's)
    prov:qualifiedAssociation.prov:hadPlanthe BPMN task: <process>#<task id>
    prov:actedOnBehalfOfthe person an agent worked for
    prov:used / prov:generatedthe graph nodes read and written
    prov:wasInformedBythe activity this one was part of: a Tool activity names its workflow step's
    prov:used → dcat:Distribution + spdx:checksumthe DSA agreement text the decision was made under (DCAT 3)
    prov:used → cred:VerifiableCredentialthe grant, by its W3C VC Data Model 2.0 credential id (DSA B5)
    cat-harness:underPolicythe ODRL policy (or policies) it acted under
    cat-harness:previousHashlocal extension: SHA-256 hex digest of the preceding record in the chain (null at genesis)
    cat-harness:recordHashlocal extension: SHA-256 hex digest of this record's canonical JSON

    hadPlan is PROV-O's own term for "the plan an agent followed". A BPMN task is exactly that, so no new term is minted for it.

    The agreement and the grant are cited with existing open terms, not ours (owner card 2026-10-30 19:16Z, bean yy40). A decision record names the agreement as a prov:used entity whose @id is the DCAT 3 dcat:Distribution of the agreement's legal text, carrying that text's spdx:checksum (spdx:algorithm + spdx:checksumValue, the property DCAT 3 gives dcat:Distribution). The grant is a further prov:used entity whose @id is the W3C VC Data Model 2.0 credential id. No agreement or grant fields of our own remain.

    The hash chain is a local extension. No open standard defines a hash-chained PROV log, so cat-harness:previousHash and cat-harness:recordHash stay in the cat-harness: namespace and are described as such (PROV_LOCAL_EXTENSION_TERMS), in this module, in the PROV-JSONLD emitted by prov-jsonld.ts, and nowhere passed off as PROV.
