      SEEDING writes consent; it is not left for hand editing (task #10, gap c). Whatever creates or re-pins a remote instance in index.config.json passes the person's grant here, and the mount comes back carrying trust.consent {by, on, ref, evidence} with ref taken from the mount itself — so the consent is for exactly the pin being written, and mountTrust accepts it.

      A consent ALREADY recorded for this same pin is kept as it is: it is that person's record, and a second grant does not rewrite who said yes first. A consent for a DIFFERENT pin is replaced — a moved pin asks again, and the grant passed here is the asking. A signature, if any, is kept beside it. The grant is validated with MountConsentSchema, so an empty by or evidence throws rather than writing consent nobody can read.
