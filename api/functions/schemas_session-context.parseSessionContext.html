      Parse a session record, or throw naming what is wrong.

      A session record is written by a machine that may be an LLM playing the part (3nfv), so the shape cannot be assumed from the writer's care. Parsing at the boundary is what makes a non-deterministic writer safe to read from.

      • $schema: "folio-session-context/v1"
      • actor: { declared: boolean; id: string }

        WHO is acting. See the module note — this is the field the record is for.

        • declared: boolean

          Does id resolve to a node under the actors graph?

          Required, and not inferred at read time: a reader resolving it themselves gets a DIFFERENT answer than the writer did if the node was added or removed in between, and the record is supposed to say what was true when the session acted.

        • id: string

          The actor's id, or the best name available when none is declared.

      • claimed: string[]

        Beans this session has claimed.

        By reference, never copied. A claim ANNOUNCES rather than reserves until a PR exists (bean-coordination), so the bean is the authority on its own status and a status duplicated here would be free to contradict it.

      • id: string

        Stable for the life of the session.

      • open: { atNode?: string; instance: string; process: string }[]

        Instances this session has open. EMPTY IS THE NORMAL STATE, not a gap: an agent answering a question, reading, or deciding what to do next is in no process at all, and process-state calls that idle rather than broken.

      • startedAt: string

        When the session began, as an ISO-8601 UTC instant.

      • updatedAt: string

        When this record was last written.

      • OptionalwaitingOn?: { since: string; what: string }

        What the session is waiting on, if anything.

        Free text on purpose: what a session waits for is a human answer, a CI run, a sibling's PR — an open set no enum would survive. since is separate and required alongside, because a wait with no start cannot be told from an abandoned one, which is the argument bean-blocking makes for an expiry.
