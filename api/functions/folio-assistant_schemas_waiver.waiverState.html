      Is this waiver still in force at now?

      Returns a THREE-state answer, not a boolean, and the third is the one that gets skipped: a clock or a timestamp that cannot be read is not "expired" and not "in force" — it is unknown, and an unknown waiver has not waived anything. The gate asks.

        • $schema: "folio-waiver/v1"

          Tag identifying the file's contract, per the directory conventions.

        • bounds: string

          Anything the grant carried that the gate needs to check against — a swarm's agent count and model level, the issues an issue-close waiver names, the artefact class a deletion waiver is limited to.

          Required, and an empty string is a legitimate value meaning the gate class alone bounds it. Optional would let the narrowing be forgotten, which is the one direction a waiver must never drift.

        • expires: string

          When it stops applying (ISO 8601). Required — see the module note.

        • gate:
              | "merge-to-main"
              | "bean-close"
              | "deletion"
              | "swarm-spawn"
              | "process-reentry"
              | "issue-close"

          Which gate is waived. Never "everything" — see WAIVABLE_GATES.

        • grantedAt: string

          When it was granted (ISO 8601).

        • grantedBy: string

          The person granting it, by the identity this repository already knows them by.

        • id: string

          Node id — the file's basename.

        • quote: string

          The grantor's own words, verbatim.

          Not a summary. The agent's paraphrase is the thing under suspicion here: a reader auditing the grant has only this string to check the scope against, and a tidied one can be wider than what was said.

        • scope: string

          How far it reaches.

      • now: Date

      Returns "unknown" | "in-force" | "expired"
