      Every block kind, as a RUNTIME value — DISCOVERED, not listed.

      Owner, 2026-10-04: "kinds need to be discoverable … not centrally managed" (bean riit, step 2; sod4 finding #1). Each kind is a folio-block-kind/v1 node in a block-kinds/ graph its OWNING harness declares — document kinds in the content core, the math kinds in the science layer — and this module scans every instance's declaration for them. Adding a kind is adding a node; nothing here changes.

      Why a runtime list matters at all: Block is a type and is erased, so anything that recognises a block by reading its source needs a list it can iterate. Seven such lists existed, hand-maintained and independent, and every one was short — on the qou corpus 461 blocks (445 table, 16 algorithm) were never yielded, swept or audited, excluded by a stale regex rather than by any decision. Seven tables kept in step by hand were the same defect in a wider form, which is what one node per kind removes.

      Sorted by kind, so the order is a property of the set and not of which instance was scanned first.

        The builder function a block manifest calls. Defaults to kind.

        The kind's own RDF class.

      • Optionalheading?: string

        The English heading, singular — the translation graph's source string. Empty for a kind shown without one (prose).

      • OptionalheadingPlural?: string

        The English heading, plural, for an index that groups by kind.

      • OptionalindexRank?: number

        Where the definition index lists this kind's section, lowest first; absent for a kind the index omits. A reading order (definitions before the theorems that use them), so it is authored, not sorted.

      • kind: string

        The kind string a block's kind field carries.

      • labelPrefix: string

        The label prefix, without its colon (def, not def:). Two kinds may share one (fig).

      • prefixEnforced: boolean

        Whether a block's label MUST start with the prefix. false only where the label rule never applied (prose), so moving the table onto nodes did not tighten validation of a corpus nobody re-checked.

      • Optionalprofile?: "document" | "paper"

        The NARROWEST content profile that admits the kind (paper-adapter kinds only; a contributed adapter's kind is in no profile). Profiles nest (document ⊂ paper), so document means both and paper means the paper profile only — a formal mathematical claim.

      • provable: boolean

        Whether a label of this kind names an upstream provable, which an algorithm must cite.
