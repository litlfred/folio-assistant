    Module schemas/kg/discovered-vocabulary

    An enum whose members are DISCOVERED from the instances mounted beside this layer, rather than written in code — marked, so a reader that publishes the schema knows its members are the composition's and not the schema's.

    Graph Node

    none — a marker registry over Zod schemas; it defines no node shape

    Why a mark is needed

    BLOCK_KINDS is read at import from every mounted instance's block-kinds/ graph (bean riit): the content core declares the document kinds, the science layer the math kinds, the harness none. So z.enum(BLOCK_KINDS) is right at runtime in whatever composition runs it, and it is a different enum in each one. A JSON Schema written from it says which repositories happened to be mounted when the generator ran: with the harness alone it is { "not": {} }, which rejects every value, and in a full mount it lists the core's and the science layer's kinds, which a harness file may not name (bean 8lcl, folio-assistant#2812).

    The vocabulary is OPEN by design — a higher layer adds a kind by adding a node — so the only schema a lower layer can publish for it is the open type. gen-kind-json-schemas.ts reads this registry and writes { "type": "string" } for every schema in it. The Zod stays the closed enum, because at runtime the composition IS known.
