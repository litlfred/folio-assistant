    Module schemas/block-qa

    Per-content-block QA report schema.

    Each content block (a .ts + .md + optional .lean triple under content/) may have a sibling <block>.qa.json audit-report file. The report records, per QA criterion, the result of an audit pass along with the source-file hashes at audit time so staleness can be detected when a sibling file is later edited.

    Multiple reviewer entries per criterion are allowed (script + agent + human adjudication). The first entry whose field_hash still matches the current source files is the "fresh" entry for that criterion.

    Authoritative reference for the architecture: the integration- watcher skill family — see .claude/skills/local/one-voice-integration-watcher.md.
