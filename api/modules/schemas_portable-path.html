    Module schemas/portable-path

    Path segments a checkout can actually create — on every filesystem, not only the one that wrote them.

    A repository is portable only if every path in its tree can be CREATED on the filesystems people clone it onto. NTFS reserves : inside a path component, so one file named req:<slug> makes Git abort the whole checkout on Windows — while the author's machine and Linux CI see nothing wrong.

    ENCODE rather than substitute

    kgQaSidecarPath promises collision-freedom, and substitution (: → -) breaks it: req:agent-workflow and req-agent-workflow would share a sidecar. Percent-encoding is reversible (% is itself encoded), so req:agent-workflow becomes req%3Aagent-workflow — legible, and decodable back to the id.

    The encoder is not the gate, and the gate does not cover everything

    A hand-authored file bypasses the encoder, so unportableSegment is also the predicate a repository-wide gate runs (scripts/check-portable-paths.ts), failing a clone-breaking name when it is committed.

    That gate reads git ls-files, so it sees TRACKED paths only. Output a generator writes into an ignored build directory is outside it; the cover for those writers is encoding at the composer, which is why id-to-filename call sites route through portableSegment.

    Encoding is not always the right tool

    Where a segment is also a PUBLIC ROUTE — scripts/state-visualizer.ts builds a site directory from a declared graph id — encoding would silently publish /req%3Ax/. There the id is refused with a message naming the remedy, as a reserved device name is (aux has nothing to encode).

    Graph Node

    none — a predicate and an encoder over path strings, not a schema
