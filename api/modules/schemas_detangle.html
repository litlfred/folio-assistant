    Module schemas/detangle

    Detangling — is this candidate subgraph really a subgraph?

    Graph Node

    schema

    The criterion

    A candidate subgraph is a large collection of thematically related content that the rest of the graph references while it references little outside itself: a near-sink, arrows mostly one way. That is not a small cut: ten edges in and ten out cannot be lifted, fifty in and zero out lifts cleanly. A near-sink is a node set with no wrong-direction edges out of it.

    Four numbers

    • size — |S|. A two-node candidate is a file move and does not need a declaration.
    • cohesion — internal / (internal + boundary): the evidence for "thematically related". A directory whose files never reference each other is a folder, not a subgraph.
    • inbound — edges from the rest into S. High is GOOD.
    • outbound — edges from S to the rest. This is the one that must be near zero, and every outbound edge is an item on the detangling worklist.

    oneWayness = inbound / (inbound + outbound) is reported ALONGSIDE the counts, never instead: 1.0 from 5/(5+0) and from 500/(500+0) are very different facts.

    The cut classification

    Every outbound edge is a module that must move, a dependency that must invert, or a documented exception — only the first is free. An edge whose kind cannot be determined is unclassified and counted separately, never quietly called essential.

    Nothing here decides — judgement is a declared step

    This module is a mechanical reviewer (the severity/weight split of schemas/sdlc/qa-review.ts). It emits DetangleFinding with a script reviewer and a severity, and has no opinion about whether to carve. The carve is a Decision by a human or agentic adjudicator, which may overrule any finding; the numbers make that decision reviewable ("carved anyway, cohesion 0.31, because X").

    So a failing clause is never a refusal: failingClauses returns the clauses, not a boolean, so the adjudicator can answer them one at a time.
