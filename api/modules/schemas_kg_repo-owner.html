    Module schemas/kg/repo-owner

    Who owns a checkout on GitHub, and how a SAME-OWNER repository name resolves.

    Graph Node

    none — repository naming helpers, not a schema

    WHO migration, plan step T3 (owner decision Q-WP-1 = A, 2026-11-15; cat-harness-tools#2337). The content layers move from one GitHub owner to another by PRs from the forks, and the same commit must build correctly in both places. So a content layer's pin on ANOTHER content layer does not name an owner:

    { "name": "base", "source": { "remote": { "repository": "base", "ref": "<sha>" } } }

    A repository written without an owner is a SAME-OWNER name: it resolves to <owner of the checkout that holds the file>/<name>. A fork resolves to the fork and WHO resolves to WHO, at the same commit, because WHO merges with merge commits (plan rule M1). { "repository": "base", "sameOwner": true } is read the same way.

    The owner of a checkout is never declared (checkoutOwner).

    Harness layers (HARNESS_REPOSITORIES) stay absolute under HARNESS_OWNER: that constant (and the two workflow env lines that mirror it) is what changes when the harness moves to its own org.

    A repository that must name another owner on purpose keeps the absolute form: a content repository that stays behind while the layers it pins move names their new owner in each of those pins.
