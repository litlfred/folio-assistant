    Module cat-harness/schemas/source-descriptor

    How to enumerate a corpus you will never hold, and how to ask it for a subset.

    Graph Node

    schema

    materialize-remote answers "may we take this, and what does holding it cost". A descriptor answers the question before that: how do you enumerate a corpus, and how do you ask it for a part? Every source answers differently, so the answer is written down here rather than told to an agent each time.

    The last row is why SubsetStrategy carries closure: a mathlib declaration without its closure does not compile.

    Cost is declared

    Enumerating a large corpus over a paged, rate-limited API may be refused. A descriptor states what enumeration COSTS, so enumerationCost can answer the size gate before anything is fetched.

    Characterising a source decides how it may be REFERENCED

    A reference is a promise that the thing will still be there, and still be the same thing. Three properties decide whether that promise can be kept:

    remotelargevolatilehow it may be referenced
    no––hold it; the question does not arise
    yesnonomaterialise working; a bare reference is honest
    yesyesnoreference the whole, materialise a subset
    yes–yesarchive, or do not cite it

    A reference to a moving target silently resolves to something other than what was cited. So archivalImperative returns required on a volatile source, and the sourceLoss gate can then only be discharged by an archival copy.

    Delegating search is a fallback

    Search over what is NOT materialised may be sent to the source itself, but only when the source is reachable, has a search of its own, and is stable enough that a link composed today still means the same thing. canDelegateSearch answers that from the characterisation.
