    Module schemas/translation

    Translation status, metadata, and node schemas for localized content.

    The translations/ directory

    The top-level translations/ directory contains only .pot templates, .po translated files, and their .ts manifests (TranslationNode). Rendered output (.md), QA sidecars (.qa.json), and status metadata are properties of the TranslationNode manifest, not loose files.

    translations/
      fr/
        index.ts            ← TranslationNode manifest (KG node)
        index.pot           ← POT template (extractable strings)
        index.po            ← PO translated strings
        agent-onboarding.ts
        agent-onboarding.pot
        agent-onboarding.po
        glossary.ts         ← shared glossary PO (no POT — hand-authored)
        glossary.po

    Each .ts file is a TranslationNode that references its .po and .pot siblings. This makes every translation file a node in the knowledge graph — addressable by label, discoverable by the pipeline, and validatable by the same content-object infrastructure that manages content blocks.

    PO source resolution (fallback behavior)

    When a content block does NOT declare poSources[] (the common case), the pipeline resolves PO files by convention:

    1. Block-level: translations/<locale>/<block-stem>.po
    2. Chapter-level: translations/<locale>/<chapter-slug>.po
    3. Folio-level: translations/<locale>/global.po
    4. Dependency walk: harness.config.json dependencies, depth-first

    When poSources[] IS declared on BlockBase, only the listed files are consulted (no fallback). Later entries override earlier for the same msgid.

    Official vs unofficial

    An official translation has received human adjudication / sign-off. An unofficial translation is agentic — generated by an LLM or machine translation tool, possibly from an existing .po file. The distinction is not quality (an unofficial translation may be excellent); it is accountability — official means a named human has reviewed and approved the translation for this source version.

    Staleness

    An official translation whose source content has changed since sign-off is stale. The sourceHash field is the SHA-256 of the source .md at sign-off time. The pipeline computes the current hash and compares; a mismatch sets stale: true. The translation remains visible with a warning — it is not hidden, because a stale official translation is still more trustworthy than no translation.

    Sign-off levels

    A human can sign off at any level of the content hierarchy (block, section, chapter, folio). The level field records this. A lower-level sign-off overrides a higher-level one for that specific node.
