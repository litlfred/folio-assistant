# bootstrap-tools

**The toolchain that describes `bootstrap`, kept outside it so bootstrap
does not have one.**

`bootstrap/README.md` states the invariant this instance exists to
protect:

> An Initiator has **no** harness, no server, no tools and no work plan.
> It is a file you read, not something you run.

Measured: `bootstrap/` holds `.md`, `.json` and `.bpmn`, and **no
executable code of any kind**. That is the design, not an omission — an
Initiator runs before Bun, before Zod, before the harness exists.

So bootstrap's shapes cannot be Zod *in bootstrap*. Owner, 2026-09-20:

> the zod schema should by one special exemption not be bootstrap, but
> bootstrap-tools

and, sharpening it:

> bootstrap should not know zod at all (it is just generated by it in main and
> ghpages rendering pipeline)

## What lives here

`schemas/discussion.ts` — the authoritative Zod source for the two documents
the `discussion` process carries. The JSON Schema in
`bootstrap/skills/discussion.*.schema.json` is **generated from it** by
`bun run bootstrap-tools:schemas`, and bootstrap carries no import, no
dependency and no build step of its own. Read from inside `bootstrap/`,
those two files are just files, exactly as they were.

## Why this is not simply a port

**Zod's `.refine()` exports nothing to JSON Schema.** Measured with
`zod-to-json-schema`: a refined object emits no `allOf`, no `if`/`then`, and
no trace of the constraint. The output schema has two conditionals —

    determinedBy: "assumed"   requires  assumption
    outcome:      "unsettled" requires  stillOpen

— so a naive port would publish a document that **accepts what the current
one rejects**, at an `$id` consumers already follow. A contract weakened
invisibly is the failure this repository works hardest to avoid.

The generator therefore re-applies those conditionals, and
`schemas/discussion.test.ts` proves it the only way that means anything: a
corpus of documents that **must** validate and documents that **must not**,
run against the generated schema. A test that only checked the happy path
would pass against a generator that dropped both constraints.

See [`schema-management`](../cat-harness/skills/folio-core/schema-management.md)
§"`@ref`" for the related case one level down — an edge the reader cannot see
unless it is declared.
