# AGENTS.md — bootstrap-tools

This directory is a **staged instance**, not a repository yet: it is to become
[`litlfred/bootstrap-tools`](https://github.com/litlfred/bootstrap-tools)
(owner, 2026-09-29, bean `81tw`). What binds everywhere is the repository's
[`AGENTS.md`](../AGENTS.md); what this layer *is* is [`README.md`](README.md).

Two rules govern work here, and both are about a boundary that is easy to erase
by accident.

## The arrows point one way, and it is outward from here

This instance **needs `cat-harness`**, and reads and writes `bootstrap`.
Neither of them may know it exists:

- **Nothing under `cat-harness/` imports from here, or names this instance in
  code.** It would be a cycle: this instance imports cat-harness's
  `cat-harness.ts`, `graph.ts`, `requirement.ts` and `model-registry.ts`, which
  is exactly why those four stayed behind when the rest moved.
  `check:partition` fails the import; `check:reference-direction` reports the
  name.
- **Nothing under `bootstrap/` imports from here, or needs a tool at all.**
  bootstrap's README promises a Bootstrapping Agent *no harness, no server, no
  tools and no work plan*. The owner's words: *"bootstrap should not know zod
  at all (it is just generated by it in main and ghpages rendering pipeline)"*.

If a change would put an import, a dependency, a `package.json` or a build step
into either, it is the wrong change.

## What VALIDATES at a published `$id` is a contract

`bootstrap/schemas/*.schema.json` are generated from the Zod here and in the
stay-put `cat-harness/schemas/` modules, by `bun run bootstrap:schemas`, and
their `$id`s are already published. **Changing the Zod changes what a third
party accepts.** Before merging a change to any of it:

1. `bun run bootstrap:schemas` — regenerate (`:check` is a gate).
2. `bun run bootstrap:validate` — bootstrap's own documents still parse.
3. `bun run bootstrap:semver` — the bump the change REQUIRES, computed from the
   diff. MAJOR needs the owner. The rules are
   [`skills/bootstrap-contract-semver.md`](skills/bootstrap-contract-semver.md).

Two ways a Zod change has already moved the contract silently, both caught
rather than shipped: **`.refine()` exports nothing** (the conditionals live in
`JSON_SCHEMA_CONDITIONALS` too, and `schemas/discussion.test.ts` asserts the two
forms agree), and **`z.object()` is strict** (kept deliberately, bean `z634`).
