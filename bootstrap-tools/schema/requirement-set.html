Description

A REQUIREMENT SET — the requirements document: a set of requirement statements at one stage of its life, with the sign-offs that moved it there.

The ask, and its approval, are on litlfred/folio-assistant issue #2405 (FR-010 to FR-013). Not quoted here: a bootstrap schema names no outside concept, not even in a quotation (check:bootstrap-concepts).

Why a set is its own node

A Requirement is a statement somebody must meet, and it outlives the document that proposed it. The document has a different life: it is drafted, proposed, approved, planned, worked, delivered and accepted — or rejected, cancelled or superseded — and each of those moves is a DECISION somebody made. Before this node the stage was implied by which directory a file sat in, and nothing recorded who decided, when, or why.

The set's stage and each member's status are INDEPENDENT

A requirement can be in-force while the set that proposed it is still delivered, and a set can be cancelled without retiring a requirement another set also carries. One link between them is enforced, by the harness's checker because it needs the member files: a set is accepted only when every member it approved is in-force.

A sign-off is an adjudication record

Who decided (kind, id, actor — the same three identity fields a reviewer entry carries in the harness), when (at), about what (scope: the set, or one member), what they decided (outcome, from a closed list), which stage that moves the set to (stage), why (reason) and where the decision can be read (evidence, a link to the comment it was made in).

Which stages need a sign-off

The ADJUDICATED stages — approved, accepted, rejected, cancelled — are reached only through a sign-off that names the stage, with the matching outcome; approved and accepted only through a HUMAN one. The PROGRESS stages — planned, in-progress, delivered — are facts about the work rather than decisions, and are checked as facts: from planned on, the set names its work plan, and every stage past approved presupposes an approving human sign-off. draft and proposed are authoring, not adjudication.

Bootstrap holds no code, so this file is the source and bootstrap/schemas/requirement-set.schema.json is what bootstrap publishes, generated by bun run bootstrap:schemas. The refinement does not survive the conversion; REQUIREMENT_SET_JSON_SCHEMA_CONDITIONALS restates what JSON Schema can say.
