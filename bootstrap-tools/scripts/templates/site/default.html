{%- comment -%} The page layout of a site bootstrap-tools stages (scripts/site.ts), in place of jekyll-theme-primer's own `default.html`. It is that layout with ONE change: the footer. The theme's footer is its `github_edit_link` tag ("Improve this page"), which sends a reader to GitHub's editor for the file at `page.path` on the branch Pages serves. Here that is always wrong (owner, 2026-10-01: "footer should not take them to edit page when bootstrap-tools used"): the branch is `gh-pages`, a staged copy rewritten on every publish; and a generated page is rewritten from its source, so editing it anywhere is pointless. So the footer reads what site.ts declared for the page (`_config.yml`, `defaults:` scoped to each page's path): generated_by the scripts that wrote the whole page → no edit link; a link to each script, and to `source_url` generated_from what it was generated from, in words source_url where that source is, on the instance's own branch edit_url an authored page: the editor for its SOURCE file on the instance's branch, never the gh-pages copy generated_sections the scripts that wrote some regions of an authored page A page none of these name gets no footer link at all: a link that might be wrong is worse than none. {%- endcomment -%} {% seo %}
