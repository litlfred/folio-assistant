## Why

Owner, 2026-11-13: "why are skills/tools buried under .github? the src code should be transparent in the KG and then .github just calls as needed" and "I thought things like `smart-base/schemas/skills/l2-dependency-choice/input.schema.json` were to be migrated into smart-base/L2 subgraph".

The platform already says so: skills and tools are KG content found through declared directories, including subgraph `graph.json` (cat-harness `skills/kg/kg-core/placement.md:66-81`, `directory-conventions.md:462-468`); dot-directories are rejected for nodes (`directory-conventions.md:231`); host skill folders (`.github/skills`, `.claude/skills`, …) are written by cat-harness-tools `scripts/install-skills.ts` with the "edit the source, not this copy" marker. smart-base breaks this twice:

1. `.github/skills/` is a hand-written Python/Docker "DAK Skill Library" (~2,100 lines). No build path calls it; its validators glob a directory that does not exist (`input/business-processes/`) and guess actor file names that do not exist; four swimlane validators overlap.
2. The L1–L4 subgraphs got their skill `.md` files, but the 21 per-skill I/O contracts stayed at `smart-base/schemas/skills/`, and ~35 scripts behind L* tool nodes stayed at `smart-base/scripts/`, because cat-harness-tools resolves contracts only at `<root>/schemas/skills/`.

Analysis: session https://claude.ai/code/session_01EucfRnu5trsK3i7GD1yvkP (2026-11-13), read-only audit of litlfred/smart-base@f369501, WorldHealthOrganization/smart-base@main and the platform layers.
