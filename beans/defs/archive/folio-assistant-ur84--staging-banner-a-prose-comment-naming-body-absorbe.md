Owner, 2026-09-21, with two screenshots of the same preview: *"staging banner
gone from f-a"* — present on `who-iris/`, absent on the folio-assistant
landing page beside it.

## The defect

`injectInto` used `html.replace(/<body([^>]*)>/i, …)` — **non-global**, so one
substitution, spent on the first match anywhere in the file including inside
an HTML comment.

`docs/_includes/head_custom.html` is in the `<head>` of every just-the-docs
page and contains, as PROSE explaining why a `<meta>` is used rather than a
`<div>`:

> A browser hoists a stray `<div>` into `<body>` and the code still works,
> which is exactly what makes the mistake survive review.

That sentence is the first `<body>` in the rendered document. The banner went
inside the comment; the real tag, hundreds of lines later, got nothing.

**A comment about the banner broke the banner**, and its last clause is what
the defect did to itself.

## Why it looked like a `who-iris` feature

`who-iris` pages are generated by `gen-iris-pages.ts` without that include, so
they were fine. Half the preview worked, which is worse than none of it
working: the reviewer sees a banner, concludes the injection runs, and looks
for the cause somewhere else.

## Measured, on the deployed tree rather than inferred

Scanned `origin/gh-pages` at `STAGING/claude-lhs-navbar-harness-folios-cqo9mu`:

| | pages |
|---|---|
| total | **670** |
| banner in the body (correct) | 347 |
| **banner inside a comment** | **323** |
| no banner at all | 0 |
| no `<body>` tag | 0 |

**48 % of the preview**, invisible — and the injector reported all 670 as
injected, because the only question it asked was whether the bytes changed.

## Why it survived the tests

`staging-banner.e2e.ts` and `staging-banner-constant.test.ts` both fed the
injector hand-written fixtures. Every one of them put `<body>` where the
author expected it. The parity gate's own comment already names this class —
*"a matcher proven only against fixtures is proven against its author's idea
of the file"* — and this is the same failure two files over.

## Fixed

- `bodyInsertionPoint()` skips comment ranges and returns the first REAL
  `<body …>`, or `-1`.
- `injectInto` returns **three** outcomes — `injected` / `already` /
  `no-body` — rather than letting a caller infer success from "the bytes
  changed". That inference is what made 323 broken pages look clean.
- `run()` collects the `no-body` pages by name and the CLI **exits 1** with
  the list. A staged page with no banner is indistinguishable from the live
  site, which is the entire reason the banner exists, so it fails the build
  rather than printing a warning inside a green job. Safe today: 0 of 670
  pages lack a `<body>`, measured before making it fatal.
- **THE WITNESS**: a test that reads the real `head_custom.html`, builds a
  page from it the way Jekyll does, and asserts the banner lands after the
  real `<body>`. It also asserts its own premise — that the include still
  contains a commented `<body>` — so the case cannot go vacuous in silence.

## Falsified

Reverting the comment-awareness (one line) fails **4** tests including the
witness; restored, 29 pass. The three new cases each fail for their own
reason rather than all on one assertion.

## Done when

- [x] the banner lands after the real `<body>` on a page whose `<head>`
      mentions one in prose
- [x] a page the injector cannot place a banner in is a REPORTED state, not a
      silent success
- [x] the CLI fails the staging build rather than warning
- [x] a witness test reads the file that actually shipped the defect
- [x] falsified by mutation

## Not done

**The 323 pages already deployed are not rewritten.** The next staging build
of any branch re-injects from scratch, so this repairs itself on the next
push; rewriting the published tree would be editing a build output in place.

**The prose comment in `head_custom.html` is left exactly as it is.** Escaping
it would fix this instance by making the document lie about its own subject,
and would leave the injector still wrong for the next comment that mentions a
tag. The injector was the defect.
