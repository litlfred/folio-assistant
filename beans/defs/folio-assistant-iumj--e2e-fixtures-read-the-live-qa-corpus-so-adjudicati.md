## What happened

`main` went red at `78a399ee5` on `End-to-end + accessibility (hard)` — two
specs in `tests/qa-panel.e2e.ts`. Fixed on `claude/ecstatic-goldberg-eroyaz`
(PR #314); this bean is the general defect that fix does not close.

A composition failure. #317 added the e2e job, green against the corpus as it
then stood. #302 adjudicated all 26 `voice-*` findings to zero — correctly —
and was green because the gate did not exist on its branch. Each right alone.

The specs read the real sidecar
`docs/assets/qa/crdm-methodology/what-is-not-built-yet.block.json` and assert
the panel's first row is `voice-status-leak` / fail / critical. After the
adjudication that sidecar records 48 criteria and no failure, so the first row
became the first alphabetical *passing* one. The panel was correct throughout.

## Why the coupling is the defect, not the assertion

The spec's header argues for reading the corpus so that "nothing here can
drift from what the generator produces". That is a real benefit and worth
keeping: the shape under test stays honest.

But the verdict is not shape. A verdict is content, and content is *supposed*
to change — adjudicating a finding to zero is the QA system working. A gate
that goes red when the corpus gets cleaner punishes the thing it exists to
encourage.

The file had already learned this once, one entry down: `STALE_JSON` carries a
comment recording that it was served from the corpus, that re-running the
sweep cleared the staleness, and that whether the panel renders that state
"must not depend on the corpus happening to hold an out-of-date verdict on the
day the suite runs". The same sentence is true of `fail`. The fix in #314
applies that pattern to the failing row; nothing stops the next spec coupling
itself the same way.

## Measured, 2026-09-19

- 48 criteria in that sidecar, 0 failing (`bun run` + `python3` over the JSON).
- **No criterion anywhere in `docs/assets/qa/**/*.block.json` carries
  `evidence`.** So `expect('.fa-qa-evidence pre')` could not have been
  satisfied from disk at all, by any block — the assertion outlived every
  input that could meet it.

## Done when

A spec that needs a verdict cannot silently inherit one from the corpus.
Options, cheapest first:

1. **A documented derive-from-corpus helper** — one place that reads a real
   sidecar and sets the verdict under test, throwing if the criterion it names
   has left the file. #314 wrote this inline for one fixture; lifting it is
   small and keeps the shape-fidelity benefit.
2. **A committed fixture corpus under `tests/fixtures/qa/`**, regenerated by a
   script with `--check`. Fully decoupled, but adds a staleness gate of its
   own, and a fixture nobody regenerates is how the shape drifts.
3. **Leave it, and rely on the e2e job catching it each time.** The cost is
   real and now measured: a correct adjudication took `main` red, and the
   author pays a round trip to find out the content was fine.

Recommend 1. It is the smallest change, it preserves the property the spec's
header is actually arguing for, and it converts the failure mode from "red CI
on a correct content change" into "a named error saying the fixture's subject
is gone".

If nothing is done, the next adjudication, re-sweep or criterion rename that
touches a block a spec reads takes the default branch red again.

## Resolved, 2026-09-19 — option 1

`tests/support/qa-fixture.ts`. `sidecarWithVerdicts(path, overrides)` reads a
real sidecar, applies the verdicts under test, and **throws** naming the
criterion when an override's subject has left the file. `sidecar(path)` reads
one unchanged, for a spec that really is about shape only.

Option 1 of the three, as recommended: it preserves what the spec header was
actually arguing for (shape comes off disk, so a fixture cannot agree with the
code while the code disagrees with the generator) and converts the failure mode
from "red CI on a correct content change" into a named error.

`counts` moves with the verdict, so the fixture cannot itself introduce the
header-contradicts-rows defect a spec ought to be able to catch. The source
file is never modified.

Unit-tested in `scripts/tests/qa-fixture.test.ts` rather than only through the
e2e suite: the behaviour that matters is the throw, and a throw that fires only
inside a Playwright spec is one nobody sees until CI is already red. Eight
tests, including that the error message says WHY it throws — without that, the
next reader "fixes" it by deleting the override.

The last test asserts the real corpus still holds `voice-status-leak`. That is
the early-warning: it runs in `bun test`, which runs everywhere, so the next
adjudication that would break the e2e fixture reports in the fast job instead
of the browser one.
