## The three

| call site | selector | landed |
|---|---|---|
| `prunableStickies` — `ensure-landing-sticky.ts` | parses as the sticky it writes | merged, the original |
| `prunableDashboards` — `state-visualizer.ts` | an HTML comment, `Generated by scripts/state-visualizer.ts` | [#642](https://github.com/litlfred/folio-assistant/pull/642), open |
| `findOrphans` / `pruneOrphans` — `scripts/viewer-prune.ts` | `folio:generated-viewer: <generator>`, plus the legacy `DATA_HREF`+`SCOPE` pair | this PR |

All three answer one question — *which of these directories did I write?* —
and all three answer it correctly. That is not the problem. The problem is
that only the third is a MODULE: the other two are functions inside the
generator they serve, so a fourth generator has nothing to import and writes
a fifth shape. `y90d` predicted this and named the fix in advance
(*"do not write a fourth"*), then wrote the second because the first was not
importable either.

## Why this was not just done here

`y90d`'s own reason, applied symmetrically: #642 is live on
`state-visualizer.ts` and editing another session's in-flight file collides.
Reported rather than done, and this bean is the report.

## They differ in one substantive way, not only in spelling

`viewer-prune` takes the generator's NAME and composes the marker, so a page
says WHICH tool owns it; the other two match a fixed sentence, which answers
"generated" but not "generated by whom". That distinction only bites when two
generators publish under one root — which is exactly `state-visualizer`'s
situation at the site root, and exactly the case `y90d` spent its second
objection on.

## Done when

- [ ] `viewer-prune.ts` takes the marker as a parameter rather than composing
      only its own form, so a fixed-sentence marker is expressible
- [ ] `prunableDashboards` and `prunableStickies` are call sites of it, with
      their existing tests kept as the falsification (they must still fail on
      directory-selection and on an emptied keep-set)
- [ ] nothing names a fourth shape

## Not in scope

Changing any marker already committed to a published page. A marker is read
off files that exist; changing it strands every page written before the
change, which is the same defect one level up.
