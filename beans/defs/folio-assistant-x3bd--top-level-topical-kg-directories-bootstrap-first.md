TWO PREREQUISITES FOUND BY MEASUREMENT, both blocking this design, measured on 21a1379ce. (1) A SKILL BODY IS NOT REACHABLE FROM THE PUBLISHED GRAPH. A Skill node carries instructions='skills/folio-core/getting-started.md', a REPO-RELATIVE PATH, and hasInstructions=true, a boolean. No field gives a dereferenceable URL. The body IS published, at docs/reference/skill-instructions/<name>.html, and the graph never names that URL. So a consumer holding only the JSON-LD cannot fetch a skill body — which is the whole job of the one skill bootstrap is supposed to contain. Same defect class as the /kg/ literal fixed earlier tonight: a link-shaped value that does not dereference. Contrast inputSchema/outputSchema, which ARE minted as published IRIs by skillIoIri. (2) NEITHER instructions NOR hasInstructions IS IN @context, so a JSON-LD processor DROPS BOTH — they are among the 34 undeclared terms of bean ovkk. In JSON-LD form the path is not merely unfollowable, it is absent. CONSEQUENCE: 'read markdown from the KG in json or jsonld format' cannot work today in JSON-LD at all, and works in plain JSON only with the repository checked out. So before bootstrap/ can exist, the graph must publish a dereferenceable instructions URL (the docs-site page, or the raw .md, decided deliberately) and declare the term in @context as a link. That is a small, self-contained change and it is the real step 3a — ahead of creating the directory, because creating bootstrap/ first would ship a skill whose own premise is false.

_2026-09-19T06:20:54Z_ — OWNER, same exchange: 'the content should be in README.md (so self documenting in github, too). README.md brief!!!!' So the bootstrap skill's self-description lives in bootstrap/README.md, not in a <skill>.md beside it. Three things that buys, and the third is the one that matters. (a) GitHub renders a README in the directory view, so somebody who lands in the repository with no tooling and no checkout sees the core data model, the BPMN flow and the first step immediately — no MCP, no skill_fetch, no JSON-LD processor. (b) It is the same file the docs site and any blob URL already serve, so it needs no new publishing path. (c) It SIDESTEPS prerequisite (1) above for humans entirely: the 'skill body is not reachable from the published graph' defect bites a consumer holding only the JSON-LD, and a README is reachable by every other route. The graph should still NAME it — the term still has to be declared in @context and given a dereferenceable URL — but the content is no longer hostage to that being done first. BRIEF IS A HARD CONSTRAINT, stated emphatically ('README.md brief!!!!'). It is also the constraint most likely to erode: every future session will have a reason to add one more paragraph, and AGENTS.md is itself the worked example of a bootstrap pointer that grew into a reference. Worth a measured budget rather than an intention — kg-audit already has skill-is-brief as a criterion, and pointing it at bootstrap/README.md would make the limit enforced rather than hoped for. NOTE ALSO: the README must be AUTHORED prose, not generated. content/pipeline/readme-sections.ts writes only inside <!-- marker:begin/end --> pairs and touches nothing outside them, so a generated section could be added later without endangering the authored text — but the brief description itself is prose a generator would have to invent, which is exactly the argument AGENTS.md records for deleting scripts/generate-readme.sh.
