Description

What a repository IS — the markers it carries, as a resolvable set.

A repository is a SET, and the marker is the assertion

A repository declares itself an instance of a content type by carrying a file named after that type. The filename is the assertion; the type's IRI is the resolvable reference to what the assertion MEANS. A repository may be several things at once (a DAK and a SUSHI project), so the answer is a set, not a one-file boolean. Each marker stays owned by whoever defined it — sushi-config.yaml is SUSHI's and is not ours to rename; dak.config.json is ours.

So this is a registry, not an enum, and each type declares its own filename (skills/kg/kg-core/directory-conventions.md).

The same shape as GraphTypologyRegistry

Open, seeded with a base table, register refusing a conflicting redefinition and tolerating an identical one (a diamond reaches the same type twice). A layer that owns a type registers it at load time, as folio-graph-typology.ts registers folio.

Reported, never resolved

Two markers may state the same fact differently — both naming a canonicalUrl, say. describeRepository REPORTS the disagreement and resolves nothing; ranking the markers would make one repository's truth depend on which layer happened to load.
