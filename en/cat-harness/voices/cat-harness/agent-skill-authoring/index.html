Agent skill authoring — the base voice, read from two ingested papers

The voice for writing and reviewing agent skills: what a SKILL.md's description must carry to be routed to at all, how much may sit in the body, where references and examples go, and what to do before trusting somebody else's skill. Twelve rules, every one cited to a page of an ingested paper. This is the SHARED BASE — the part the vendors agree on. Anything specific to one vendor's platform belongs in an override under `vendors/`, declaring this voice in its `extends` field.

12 rule(s) · overlay voice-overlay-agent-skill-authoring at major · provenance evidence · derived from Authoring Agent Skills: A Software-Engineering Approach (2026); What Keeps Agent Skills from Being Reusable? Evidence from 138K SKILL.md Files (2026)

rulewhat it askscategory · severitythe passage it was read from
as-description-states-function-and-triggerThe description states BOTH what the skill does and when to use it
A description that names only the function cannot be routed to. State the operations and the triggering situations, in the concrete terms a real request would contain — "Drafts release notes from the pull requests merged between two version tags. Use when cutting a release…" rather than "Handles releases". This is the most prevalent defect in the public corpus and the only one whose harm has been measured end to end: R1.3 (missing trigger guidance) affects 52.3% of 138,133 skills, and R1-clean skills reach 88.5% hit@1 against 82.6% for R1-defective ones. A skill that is never selected has no other quality.		structure · critical
State both what the skill does and when it should be used, and include the concrete terms a relevant task would contain.
arxiv-2607.25032v1#sec-004-writing-the-description, p4-5
as-description-third-personWrite the description in the third person
The description is read by the model as part of its own context, so first or second person degrades matching. "Reviews a diff for…", never "I review…" or "You can use this to…". This is a routing property, not a style preference — the same sentence in the wrong person is a worse trigger.		person · major
Write it in the third person, since it is read by the model as part of its own context, and a first or second person voice can degrade matching.
arxiv-2607.25032v1#sec-004-writing-the-description, p4-5
as-body-under-500-linesKeep the body under about 500 lines
The body enters the context window whole, the moment the skill is selected. Past roughly five hundred lines it starts displacing the conversation and the other context the task needs, so length is a cost paid at every invocation rather than a one-off. Longer material belongs in a reference file, which costs nothing until it is read.		structure · major
The body should stay under about five hundred lines, a few thousand tokens, so that once loaded it does not crowd out the conversation and other context
arxiv-2607.25032v1#sec-003-staged-loading, p4
as-assume-general-knowledgeAdd only what the model does not already know
Explaining what the model already understands is not harmless padding: every sentence competes for context once the body is loaded, so a paragraph restating general knowledge displaces one carrying a project convention. Write the non-obvious procedure, the specific file location, the rule that must hold — and delete the rest.		register · major
Assume the model already holds general knowledge, and add only what it does not have: project conventions, non-obvious procedures, specific file locations, rules that must hold.
arxiv-2607.25032v1#sec-005-anatomy-of-a-well-formed-skill, p5
as-references-one-level-deepReference files are linked ONE level deep, never chained
Link every reference file directly from the body. A file that links onward to another may be reached by a partial read, and the model then acts on incomplete information — a failure that looks like the skill working, because something was read. The depth limit is what makes a partial read safe.		structure · critical
those files should not chain onward to further files, because the model may preview a deeply linked file with a partial read and then act on incomplete information
arxiv-2607.25032v1#sec-005-anatomy-of-a-well-formed-skill, p5
as-reference-toc-over-100-linesA reference file over ~100 lines opens with a table of contents
A partial read of a long reference shows its opening. If that opening is a table of contents, the reader learns the file's full scope even when it never reaches the end; without one it learns only the first section and cannot tell what it missed.		structure · minor
For any reference file longer than about one hundred lines, place a short table of contents at the top so the model can see the full scope even on a partial read
arxiv-2607.25032v1#sec-005-anatomy-of-a-well-formed-skill, p5
as-one-default-name-the-exceptionGive ONE default and name the exception
A body that lists alternatives without ranking them leaves the model choosing on no grounds, which makes its behaviour vary run to run for reasons the author cannot see. State the default, then state the specific condition under which something else applies.		register · major
Offering many alternatives leaves the model to choose without grounds, so give one default and name the exception.
arxiv-2607.25032v1#sec-009-patterns-and-faults, p8
as-state-dependenciesState every dependency the skill assumes
A skill that assumes a package, a binary or a path is present fails on the machine where it is not — and fails at the point of use, having already been selected. Name what must be installed, and prefer a check that reports the gap over a step that dies on it.		methodology · major
Assuming a package is installed fails when it is not, so state dependencies explicitly.
arxiv-2607.25032v1#sec-009-patterns-and-faults, p8
as-evaluations-before-instructionsWrite the evaluations before the skill
Run the model on representative tasks WITHOUT the skill and record where it actually fails. Those failures are the test cases; the skill is the minimum instruction set that passes them. Written the other way round, a skill documents what its author imagined the model could not do, and the two sets overlap less than they appear to.		methodology · major
Write evaluations before writing the skill.
arxiv-2607.25032v1#sec-008-an-evaluation-driven-authoring-process, p8
as-read-third-party-skills-in-fullRead a third-party skill in full before using it
A skill carries instructions and may carry code, both of which the agent can act on. Installing one from outside the project without reading it is running unreviewed content in the agent's own voice, where it is indistinguishable from the project's own guidance.		methodology · critical
a skill from a third party should be read in full before it is used.
arxiv-2607.25032v1#sec-011-summary-of-guidance, p9
as-no-name-as-headingDo not repeat the skill's name as the body's first heading
The name is already in the frontmatter and already in the model's context at level one. Repeating it as the opening heading spends body lines restating what the reader has, and it is the second most common defect in the public corpus at 44.3%. Open with what the reader does not yet have.		structure · minor
The three most prevalent individual defects are all spec violations: R1.3 miss- ing trigger guidance (52.3%), R2.4 name-as-heading dupli- cation (44.3%), and R3.2 too many inline examples (32.1%).
arxiv-2608.08453v1#sec-012-42-rq1-what-reusability-defects-are-prevalent-in, p4
as-examples-move-to-referencesToo many inline examples belong in a reference file
Examples are the easiest thing to add and the most expensive to carry, because they sit in the body and load on every invocation. R3.2 affects 32.1% of public skills. Keep the one example that disambiguates the instruction; move the rest to a reference the body links, where they cost nothing until needed.		structure · minor
The three most prevalent individual defects are all spec violations: R1.3 miss- ing trigger guidance (52.3%), R2.4 name-as-heading dupli- cation (44.3%), and R3.2 too many inline examples (32.1%).
