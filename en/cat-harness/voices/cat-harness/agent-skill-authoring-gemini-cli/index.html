gc-descriptions-do-not-overlapA description is distinct from every other skill's — and from what the model does anyway
Gemini CLI routes on the description alone, so two skills whose descriptions cover the same requests compete for them, and a description that restates a general capability of the model gives the router no reason to load the skill at all. Check a new description against the descriptions already installed, not only against the skill's own body.		structure · major
Avoid overlap: Ensure your skill descriptions are distinct from one another and from the general capabilities of the model.
agent-skill-best-practices---gemini-cli#page-001, p1
gc-context-budget-in-wordsBudget the three loading levels in WORDS: ~100 always loaded, under 5k on trigger
Gemini CLI states its budget per level and in words: the name and description are always in context (~100 words), the SKILL.md body is loaded only when the skill triggers (under 5,000 words), and bundled resources only as needed. The base voice's '~500 lines' comes from a different source and a different unit; on Gemini CLI the word budget is the vendor's own figure. Neither is a hard limit the platform enforces — both are the publisher's guidance.		numbers · minor
1. Metadata (name + description): Always in context (~100 words). 2. SKILL.md body: Loaded only after the skill triggers (<5k words). 3. Bundled resources: Loaded only as needed by the model.
agent-skill-best-practices---gemini-cli#page-001, p1
gc-degrees-of-freedomMatch how prescriptive a step is to how fragile it is
Three levels: text instructions where several approaches are valid, pseudocode or a parameterised script where one pattern is preferred, and a specific script with few parameters where the operation is fragile or the sequence MUST be followed. Writing a fragile step as free prose is the failure this prevents; so is scripting a judgement call.		methodology · major
Degrees of freedom Match the level of instruction specificity to the task’s fragility. High freedom (text-based instructions): Use when multiple approaches are valid or decisions depend heavily on context. Medium freedom (pseudocode or scripts with parameters): Use when a preferred pattern exists but some variation is acceptable. Low freedom (specific scripts, few parameters): Use when operations are fragile and error-prone, or a specific sequence MUST be followed.
agent-skill-best-practices---gemini-cli#page-002, p2
gc-scripts-for-deterministic-tasksA task a script can do is a script in scripts/, not prose
If the step is deterministic — run a linter, fetch from an API — bundle it as a script under scripts/ and have the body call it, rather than describing the commands for the model to reproduce each time.		structure · minor
Use scripts for deterministic tasks: If a task can be automated with a script (for example, running a linter, fetching data from an API), bundle it in the scripts/ folder.
agent-skill-best-practices---gemini-cli#page-002, p2
gc-llm-friendly-script-outputA bundled script's output is written for a model to read
Suppress verbose tracebacks and end with a clear, short success or failure message. The reader of a skill script's stdout is the agent, and a stack trace is context it pays for without learning what to do next.		formatting · minor
Agentic ergonomics: Ensure scripts output LLM-friendly stdout. Suppress verbose tracebacks and provide clear, concise success/failure messages.
agent-skill-best-practices---gemini-cli#page-002, p2
gc-templates-in-assetsBoilerplate the agent must reproduce exactly lives in assets/
Common file headers and boilerplate go in assets/ as templates, so every run produces the same output rather than the model's recollection of it.		structure · minor
Provide templates: Include common file headers or boilerplate code in the assets/ folder to ensure the agent produces consistent output.
agent-skill-best-practices---gemini-cli#page-002, p2
gc-skill-directory-anatomySKILL.md is required; scripts/, references/ and assets/ are the optional sub-folders
Gemini CLI's layout: SKILL.md (core instructions and metadata) is the only required file; executable logic goes in scripts/, documentation loaded on demand in references/, templates and other non-executable resources in assets/. Other vendors name these folders differently — Antigravity documents examples/ and resources/ — which is why this is a vendor rule and not a base one.		structure · minor
my-skill/ ├── SKILL.md (Required) Core instructions and metadata ├── scripts/ (Optional) Executable logic (Node.js, Python, etc.) ├── references/ (Optional) Documentation to be loaded as needed └── assets/ (Optional) Templates and non-executable resources
agent-skill-best-practices---gemini-cli#page-002, p2
gc-reference-material-out-of-the-bodyKeep the body procedural; reference material, schemas and examples go in references/
The body holds the core procedure. Detailed reference material, schemas and examples move to separate files in references/, loaded only when needed — the vendor's own folder name for what the base voice calls a reference file.		structure · minor
Best practice: Keep the SKILL.md body focused on core procedural instructions. Move detailed reference material, schemas, and examples into separate files in a references/ directory.
agent-skill-best-practices---gemini-cli#page-002, p2
gc-no-hardcoded-secretsNo API key or password in a skill's scripts or documentation
A skill is shared and installed by others; a credential written into it is published with it.		methodology · critical
Avoid hardcoded secrets: Never include API keys or passwords in your skill’s scripts or documentation.
agent-skill-best-practices---gemini-cli#page-003, p3
gc-limit-scopeKeep a skill as narrow as it can be
The narrower the skill, the smaller the damage when it is wrong. A skill that does several things fails in several places at once.		structure · minor
Limit scope: Design skills to be as focused as possible to minimize the potential impact of errors.
