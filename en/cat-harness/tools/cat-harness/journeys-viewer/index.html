Journeys viewer

Draw every journey (user-scenario) and workshop (workshop) in the checkout as static pages at the route of the visualiser a layer declares for this Tool, <locale>/<instance>/<id>/: an index of all journeys, grouped by layer (each a sub-graph page), each parent’s parts nested under it in its order with optional and repeating parts marked (an older file’s partOf children after them, ordered along follows), and a plain DAK user scenario with no steps listed as one; one page per journey, its parts in order and the journeys it is a part of, a journey map with a lane and a feeling curve per persona, then each step, linked to the journey it includes, with its BPMN drawing (the step’s flow nodes highlighted), user stories, requirements, FHIR examples, building blocks, the DAK assets it uses (data sets, decision tables and indicators, linked into the IG) and ArchiMate views; and the workshop layer, the questions for the room on each step, a page per workshop and per module, job aids, and printable A3/A4 sheets; and each device screen (device-screen) that shows a step a workshop presents, drawn as a static device mock (phone, tablet, scanner, desktop, kiosk) with its owner beside it, in the workshop’s Device Demo, linked both ways with the walkthrough. A persona’s picture (meta.persona.avatar) is drawn wherever the persona appears. Layers below the declaring one are read through their declarations, so a downstream site shows the journeys of the layers it mounts too.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

journey-maps

Journeys and workshops as knowledge-graph content: a DAK user scenario told as a journey map (user-scenario kind: ordered steps, per person what they do and feel, pain points, enablers, the record’s trust state, and edges to stories, BPMN tasks, requirements, FHIR examples, building blocks and the DAK’s data sets, decision tables and indicators), the building-blocks catalogue its steps use, a workshop that teaches from it (workshop kind: modules, objectives, questions for the room on each step, reference tables, sheets, job aids), the journeys-viewer visualiser that draws them for a layer and the layers it mounts, and the check:journey-refs gate that every reference they name resolves. Read before writing a journey or a workshop, before declaring the viewer, and before building a journey walkthrough app of your own.

Source: cat-harness/skills/ui/ui-core/journey-maps.md.

Also satisfied by: journey-refs.

The skill declares no I/O contract (schemas/skills/journey-maps/{input,output}.schema.json).

Processes and tasks

No process step names a skill this Tool satisfies.

How it is deployed and reached

  • Command line. From the repository root: bun run cat journeys:viz. cat journeys:viz runs bun run cat-harness-tools/scripts/gen-journeys-viz.ts (declared in cat-harness-tools/package.json).
  • GitHub Actions. No workflow in this checkout runs its command.

As an API: its operation in the OpenAPI document and the MCP tool list of its layer.

when to choose it
whenA site build of a layer that declares a journeys-viewer visualiser over its user-scenario, workshop and device-screen directories; run with the other declared writers (visualiser-writers.ts), before the navbar pass.
limitsStatic pages: the stepper, the filter and the remembered assessment ticks are a small dependency-free script, and every page reads complete without it. A FHIR example links to its page only where a layer declares a fhir-artifact-index; an ArchiMate view is drawn only where its layer declares archimate-pages. A device screen is drawn in the one state its node says: a toggle is drawn on or off, a button is a label; a workshop that declares no screen for its steps frames its own app (presentation.deviceDemo) instead.
costMilliseconds per journey; a BPMN drawing is inlined once per step that names it.
