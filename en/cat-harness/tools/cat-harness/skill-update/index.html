Edit a skill

Change one existing local skill’s instruction file through a gate: it must resolve as skill-fetch serves it, be tracked in the working repository, not be generated, be granted skill-update to the actor by a policy, be unchanged since it was read, keep its name and parse, and add only links that resolve. A gate that cannot decide refuses. Writes the working tree; the caller commits.

Skills it satisfies

A skill states the capability; this Tool is one way to exercise it. Each skill’s declared input and output contract follows, where it has one.

skills-and-tools

A skill states a capability generically; a Tool node carries the concrete mechanism. Read before writing or editing any skill, and whenever a skill is about to name a vendor, a CLI, a binary or an API endpoint.

Source: cat-harness/skills/tools/folio-core/skills-and-tools.md.

Also satisfied by: skill-fetch, skill-list.

The skill declares no I/O contract (schemas/skills/skills-and-tools/{input,output}.schema.json).

How it is deployed and reached

  • MCP. Served as skill_update by sage (cat-harness-tools/scripts/sage-mcp.sh), google-drive (cat-harness-tools/scripts/google-drive-mcp.sh), folio-assistant (bun run cat-harness-tools/src/index.ts --stdio --repo .), the servers .mcp.json declares.
  • In process. src/tools/skill-update.ts — loaded by the harness directly, with no server.
  • GitHub Actions. No workflow in this checkout runs its command.
