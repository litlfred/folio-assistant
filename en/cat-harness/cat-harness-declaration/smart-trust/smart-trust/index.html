_builtAtPublish_comment
Owner, 2026-10-14 (B1; schemas/built-at-publish.ts in cat-harness). This instance's JSON-LD @context is generated by `jsonld:contexts` (cat-harness-tools scripts/gen-instance-contexts.ts) from the prefixes and content-context terms its documents use, flattened with the prefix tables of every instance it needs. Those tables are read at the CHECKOUT's pins, not at pins this instance's commit names, so no commit of it can hold the file current: it is built at publish and never committed (bean folio-assistant-63q4). docs/ joined the list on 2026-10-15 (owner, ~10:45Z, B1): its pages are rendered by `smart-trust:pages` (fhir-harness gen-ig-pages over fhir-artifact-index/, with smart-base's themes and chrome), so they are a function of those layers at the checkout's pins: fhir-harness's switch to thin .html shells on 2026-10-14 made every committed page stale without a commit here. The index that mounts this instance registers `smart-trust:pages` at its root (a mounted instance cannot own a checkout script there), and derive:publish builds the directory; `directory` names the declared entry it fills, so check:declared-dirs and check:declaration-resolution do not expect it on disk before publish, and check:docs-populated does not grade pages a writer produced as authored documentation. The one committed file, docs/README.md, a three-line copy of the README's opening, went with it: nothing declared built at publish is tracked.
