templates/ folio-templates

The PAPER profile of the files `folio_init` writes into a new folio: `paper/` holds the Lean build, lake-cache restore and blueprint workflows and the `.github/scripts` they call, written into a paper folio after the `document/` profile the tools layer keeps. Moved here from cat-harness-tools `templates/paper/` (move M11, folio-assistant#2598; owner 2026-10-23): only a paper folio is given them, and the paper profile is this layer's. The id is the tools layer's `folio-templates`, so this directory is a member of that subgraph and `init-folio` finds it by id across the checkout, never by a path naming this layer. `{{assistant}}`, `{{folio}}`, `{{platform_git}}` and `{{platform_repo}}` are substituted at write time. Declared `code`: executable sources whose target is another repository. `dependents: skip` -- a folio inherits them through `folio_init`, not by owning a copy. Declared WITH its files, per bean dh4f.

adapters/ sci-adapters

The PAPER content adapter — `PaperContentAdapter` and its Lean tool registrar. It arrived here 2026-09-30 (bean y5si, step 1 of 2 on the owner's Option A ruling on issue #1558), and the destination was not a judgement made at the time: `cat-harness/src/builtin-adapters.ts` already declared this adapter `layer: "sci"`, and `cat-harness/scripts/partition/instance-rules.ts` already listed the prefix `adapters/paper/` in its `repo: "sci"` block. Two existing machine-readable classifications that the DIRECTORY had simply never matched; the directory caught up with them. This is the first EXECUTABLE TypeScript this instance holds beyond `contributions.ts`, which is why `tsconfig.json`'s `include` gained `folio-assistant-sci/adapters/**/*.ts` in the same commit as the move — bean `lvoa` measured what happens when it does not: a file crossing an instance boundary leaves the typecheck program and no gate reports a shrinking one. `dependents: skip` because a dependent gets its adapter by DECLARING a `contentType`, resolved through `BUILTIN_ADAPTERS` by variable path, rather than by inheriting this directory to scan. `adapters/document/` is NOT here and is not coming in this change: it is step 2, and moving it alongside is what takes the instance-boundary import axis through 16 instead of leaving it at 2.
